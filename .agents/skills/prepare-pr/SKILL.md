# PR 준비

[AGENTS.md](../../../AGENTS.md)의 공통 원칙을 따른다. 준비 요청이면 로컬에서 제목·본문·검증 근거를 준비한다. 원격 PR 생성·수정은 사용자 요청 범위에 포함된 경우 수행하며, 이미 주어진 승인을 반복해서 묻지 않는다. 구현자 외 리뷰와 사용자의 최종 병합 결정을 유지한다.

1. 최종 diff와 [TASKS](../../../docs/TASKS.md), 관련 [PRD](../../../docs/PRD.md)의 REQ/AC를 확인한다. PR은 한 목적에 집중하고 TASKS ID·관련 REQ/AC를 적는다. 해당 항목이 없으면 없다고 명시한다.
2. [공통 검증 지침](../implement-feature/references/verification.md)에 따라 마지막 코드 변경 이후의 검증을 확인한다. 미실행이면 해당 워크트리에서 실행한다. 실패 시 같은 지침의 최대 3회 수정·재검증과 차단 보고 절차를 따른다. 필수 검사가 실패하거나 미실행이면 Draft를 유지한다. 문서 전용 변경은 명시된 예외와 이유를 기록한다.
3. [.github/pull_request_template.md](../../../.github/pull_request_template.md)의 **목적·변경 내용·검증** 구조를 사용한다. 별도 `리뷰 참고` 섹션을 추가하지 않는다. 제목·본문은 한국어, conventional prefix(`feat:`, `fix:`, `docs:`, `test:`, `chore:`), 코드 식별자·명령은 영어로 쓴다. 커밋 메시지 규칙은 바꾸지 않는다.
4. 해결하는 문제와 변경 후 동작을 먼저 설명한다. 최종 diff 기준으로 제목·본문을 작성하고 검증한 커밋·실행 명령·결과·실패/미실행 이유를 넣는다. 범위가 바뀌면 제목·본문도 최종 구현에 맞춘다.
5. 코드·테스트·의존성·실행 설정이 바뀐 충돌 해결·통합은 전체 검증을 수행한다. 문서만 변경된 경우와 동일 코드의 검증 결과 재사용은 공통 검증 지침을 따르며 PR 근거를 갱신한다. 구현자 외 리뷰를 받아야 하며 사용자가 최종 병합을 결정한다.
