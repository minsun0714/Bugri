# 기능 구현

공통 규칙은 저장소 루트의 `AGENTS.md`를 따른다. 사용자가 명시적으로 구현을 요청하지 않았다면 문서·분석 범위에 머물고 코드 수정에 착수하지 않는다.

1. `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/TASKS.md`와 관련 코드를 읽고 확정 사항·제안·미결정을 구분한다.
2. 대상 REQ/AC 번호와 TASKS 작업 ID, 선행 조건을 확인한다. 후속 제품 요구사항을 MVP 구현으로 확대하지 않는다.
3. 수정 범위와 검증 계획을 짧게 제시한다. 구현에 꼭 필요한 결정이 없으면 해당 부분을 보류하고 확인한다. 이미 승인된 범위를 다시 승인받지는 않는다.
4. 해당 작업을 IN_PROGRESS로 표시하고 요청된 기능을 구현한다. 범위가 달라지면 관련 문서도 일치시킨다.
5. 수용 기준에 맞는 관련 테스트와 AGENTS.md의 적용 가능한 검사를 실행한다. 테스트 도구가 없으면 그 사실과 검증 한계를 기록한다.
6. 실패 원인을 분석하고 요청 범위 안에서 수정한 뒤 관련 검사를 다시 실행한다. 환경 문제로 검증할 수 없으면 사유와 해제 조건을 기록한다.
7. 변경 파일·동작, 실행 명령과 결과, 미실행 검사·남은 제약을 보고한다. 실행하지 않은 테스트를 성공으로 보고하지 않는다.
8. 최종 보고와 일치하도록 TASKS.md 상태와 검증 근거를 반영한다. 구현과 필수 검증을 모두 마친 작업만 DONE으로 표시한다.
