# 리뷰 요청과 기록

## 메인이 보내는 요청

다음 항목을 실제 값으로 채워 새 컨텍스트 리뷰어에게 제공한다. 구현자의 정답·평가를 추가하지 않는다.

> 이 화면에서 사용자 목적 달성을 방해하는 UX 문제를 목록화하라.
> ux-review-loop와 ux-designer 스킬을 읽고 적용하라. 코드 수정·다른 sub-agent 생성은 금지한다.
>
> - 사용자/상태와 목적, 진입 경로, 성공 행동:
> - 확정 요구사항과 수정 가능한 설계 선택:
> - 미결정 정책·자리 표시자·작업 범위/제외 파일:
> - 워크트리·코드 버전·변경 파일:
> - 서버 URL·포트·재현 경로·데모 사용자:
> - 직접 조작 도구 또는 캡처 경로/viewport/상태/촬영 대상 버전:
> - 같은 작업 재검증이면 이전 문제 ID와 이번 수정 내역:
>
> 먼저 화면에서 이해한 목적과 다음 행동을 적고, 주요 흐름을 추적하라. 그 뒤 코드/테스트를 확인하라. 각 평가 관점에 관찰 근거를 적고, 문제별 사용자 영향·개선안·해결 조건을 제시하라. 관찰하지 않은 동작은 미확인으로 표시하라. 문제를 억지로 만들지 않되, 문제 없음도 근거가 있어야 한다.

## 지속 기록: docs/ux-reviews/<TASK_ID>.md

짧은 변경은 표의 각 셀을 한 문장으로 작성한다. 리뷰 분량을 위해 증거를 반복하지 않는다.

### 대상과 증거

- 사용자 목표·확정 제약·변경 가능한 범위
- 코드 버전, 경로, viewport, 확인한 로그인/소유자 상태
- 직접 조작 / 제공된 캡처 / 구현자 E2E 결과 / 코드만 확인을 구분
- 코드가 바뀌면 어떤 증거가 이전 버전인지 명시

### 최초 관찰과 흐름

- 화면에서 이해한 목적·다음 행동
- 진입 → 핵심 행동 → 완료/다음 이동, 발견한 마찰
