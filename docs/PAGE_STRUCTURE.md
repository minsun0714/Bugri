# Bugri 페이지 구조와 워크스페이스 통합 기준

2026-11-07 합의한 1단계 프로토타입의 페이지 구성이다. 다른 워크스페이스는 화면과 이동 경로를 이 문서에 맞춘다. 구현 완료 기록이 아니며, 제품 규칙은 [PRD](PRD.md), 데이터 경계는 [아키텍처](ARCHITECTURE.md), 호출 계약은 [API](API.md)를 따른다.

## 1. 메뉴 구조

로그인 사용자 기준 주 메뉴는 **탐색 · 상점 · 마이페이지**다. 홈은 로고 클릭으로 이동하므로 주 메뉴에 중복 표시하지 않는다. 브레드크럼의 홈 링크는 유지한다. 데스크톱 헤더와 모바일 메뉴의 항목과 순서를 동일하게 유지한다. 내 퀴즈와 보관함은 마이페이지에 둔다.

```text
홈
 ├ 스트릭 요약·월/년 학습량·오늘 학습 완료 여부
 └ 구독 기반 태그 선택 → 풀이 → 결과 → 다음 문제 / 다시 풀기
탐색
 ├ 개발자 / 해시태그 / 내 구독
 └ 다른 사용자 프로필 → 공개 퀴즈·학습 활동·데스크
상점
 └ 상품·카테고리 → 구매 확인 → 구매 완료 → 보관함 바로가기
마이페이지
 ├ 데스크 꾸미기 바로가기 → /my/desk
 ├ 프로필 편집
 ├ 내 퀴즈 → 생성·저장·검토·수정·승인·공개 범위·삭제
 ├ 학습 기록 → 스트릭 상세·월별 학습 달력·풀이 기록
 ├ 보관함 → 장착·해제·데스크 미리보기
 ├ BugCoin → 잔액·지급 및 사용 내역
 └ 설정 → 학습 시간대
```

## 방문자와 로그인 사용자

아래 로그인은 제품의 사용자 상태다. 1단계에서는 방문자와 선택된 더미 사용자로 UX를 검증하고, 진입 안내는 ‘데모 사용자 선택’으로 표시한다. 실제 로그인으로 오인시키지 않으며 Google OAuth2·JWT는 2단계에 구현한다.

| 화면·동작                         | 비로그인 방문자                          | 로그인 사용자(1단계: 더미 사용자)        |
| --------------------------------- | ---------------------------------------- | ---------------------------------------- |
| 헤더                              | 탐색·상점과 로그인 진입 안내          | 탐색·상점·마이페이지                  |
| 홈                                | 전체 활성 PUBLIC 퀴즈에서 무작위 한 문제 | 직접 구독 조건에 맞는 PUBLIC 퀴즈        |
| 학습 태그·스트릭                  | 표시하지 않음                            | 태그 선택·월/년 학습량·스트릭·오늘 완료 여부 |
| 답 제출                           | 정오·정답·해설 확인 후 다음 랜덤 문제    | 기존 풀이 기록·학습일 정책 적용          |
| 탐색·공개 프로필                  | 둘러보기 가능, 구독 클릭 시 로그인 안내  | 3종 구독 등록·해제·내 구독               |
| 상점                              | 상품 둘러보기, 구매 클릭 시 로그인 안내  | 잔액 확인·구매                           |
| 마이페이지·퀴즈 작성·개인 Attempt | 로그인 안내                              | 기존 소유권·접근 규칙 적용               |

- 비로그인 체험은 홈 안에서 진행한다. PRIVATE·PENDING·삭제 퀴즈는 제외하고, 후보가 없으면 빈 상태를 표시한다. 태그 필터·구독 조건·미풀이 소진 개념은 적용하지 않는다.
- 체험 답 제출 후에만 정답·해설을 공개한다. 원본 학습 내용은 공개하지 않는다. 제출 시에도 공개 범위와 삭제 상태를 검사한다.
- 방문자 체험의 풀이 기록·스트릭·BugCoin은 저장·집계·지급하지 않는다. 사용자별 Attempt 기록이나 익명 OwnerSession을 만들지 않는다. 새로고침 후 체험 복원은 보장하지 않는다.
- 로그인 후에는 기존 구독 기반 홈으로 전환한다. 체험 결과는 사용자 기록이나 보상으로 이관하지 않는다. 구독이 없으면 탐색을 안내하고 방문자 랜덤을 로그인 사용자에게 대신 제공하지 않는다.
- 구독·구매 및 보호 페이지 진입은 로그인 안내를 거친다. 성공 후 원래 페이지로 돌아가되 구독·구매를 자동 실행하지 않는다. 취소·실패 시 상태 변경 없이 재시도를 안내한다.
- 아래 트리와 스트릭·개인 기록 설명은 로그인 사용자 기준이다. 방문자 홈과 헤더에는 이 절의 차이를 적용한다.

## 2. 통합 목표 경로

아래는 페이지 URL이며 API 엔드포인트가 아니다. 기존 작업 경로가 다르면 통합 시 링크와 테스트를 함께 맞춘다.

| 경로                      | 역할                           |
| ------------------------- | ------------------------------ |
| `/`                       | 스트릭 요약과 태그별 연속 학습 |
| `/discover/developers` | 개발자 탐색 |
| `/discover/tags` | 태그 탐색 |
| `/tags/[hashtagId]/quizzes` | 태그별 공개 퀴즈 목록·구독·개별 풀이 연결 |
| `/users/[publicId]`       | 사용자 정보·데스크·최신 퀴즈·학습 활동 |
| `/shop`                   | 상품 목록·구매                 |
| `/coin-history`           | 코인 잔액·지급 및 사용 내역·데스크 편집 링크 |
| `/my`                     | 사용자 쿼리를 보존해 `/coin-history`로 이동 |
| `/my/quizzes`             | 내 퀴즈 목록                   |
| `/my/quizzes/new`         | 내용 입력·생성 후보·저장       |
| `/my/quizzes/[quizId]`    | 작성자 검토·수정·승인·관리     |
| `/my/desk` | 데스크 편집·보유 상품·잔액 |
| `/my/learning`            | 학습 기록·달력·스트릭 상세     |
| `/my/inventory`           | 보관함·장착·해제               |
| `/my/coins`               | 잔액·지급 및 사용 내역         |
| `/my/settings`            | 학습 시간대 설정               |
| `/quizzes/[quizId]/solve` | 목록·프로필에서 개별 풀이 진입 |
| `/attempts/[attemptId]`   | 개별 풀이 진행·결과 복원       |

마이페이지 하위 화면은 공통 개인 메뉴를 사용한다. 데스크톱에서는 사이드 메뉴, 모바일에서는 접을 수 있는 메뉴로 제공한다. 개별 풀이 진입에서 Attempt를 시작한 뒤 해당 Attempt 경로로 연결하며, 결과 조회만으로 새 Attempt를 만들지 않는다.

## 3. 화면별 연결과 표시 규칙

### 홈과 학습 기록

- 홈의 퀴즈 영역 위에 현재 스트릭·월/년 학습량·오늘 완료 여부와 `/my/learning`으로 가는 ‘학습 기록 보기’를 표시한다.
- 오늘 미완료라도 어제까지 이어진 스트릭을 즉시 끊긴 것으로 표시하지 않는다. 학습일은 사용자 학습 시간대를 따르며 정답 여부와 무관하게 신규 풀이·다시 풀기 모두 인정한다. 같은 날 여러 번 완료해도 하루로 집계한다.
- 체크와 텍스트를 함께 사용해 색상만으로 완료 여부를 구분하지 않는다.
- 홈 학습량은 이번 달 달력이 기본이며 탭 대신 날짜 제목 → 월 목록 → 제목 아래 연도 드롭다운으로 기간을 선택한다. 연도 메뉴를 열어도 월별 학습량은 유지한다. 보기 전환 시 같은 카드 높이를 유지한다. 월 달력은 작은 라벤더색 날짜 띠와 큰 학습량 영역을 옅은 연보라 선으로 나누고, 완료 개수에 따라 연두색 농도를 달리한다. 년은 2열 × 6행의 월별 가로 막대와 해당 월 진입을 제공한다(AC-12l). 현재 스트릭 요약은 과거 기간 탐색과 독립적이다.
- 홈에서 풀이·결과·다음 문제를 이어가고 개별 풀이 컴포넌트를 재사용한다. 태그는 다음 문제에서도 유지한다. 후보 없음과 미풀이 소진을 구분하며 PRD의 탐색 안내·다시 풀기 규칙을 따른다.
- 상세 학습 기록은 마이페이지에 두며 홈에서도 위 범위의 월별 학습량 달력을 제공한다. 비공개 전환·삭제 후에도 완료 기록과 성과를 보존하되 이용 불가 문제 본문을 재노출하지 않는다.

### 내 퀴즈와 탐색

- 내 퀴즈 목록에 ‘퀴즈 만들기’를 주요 버튼으로 제공한다. 저장 전 생성 후보와 저장된 퀴즈 목록을 구분한다.
- PENDING 목록 항목은 검토 화면으로, 승인된 퀴즈는 풀이로 연결한다. 작성자 관리 버튼은 별도로 제공한다. 생성·저장만으로 승인하거나 공개하지 않는다.
- 탐색은 개발자 탐색과 태그 탐색의 독립 페이지·메뉴로 구성한다. 개발자 이름은 공개 프로필로, 별도 공개 퀴즈 수는 전체 공개 퀴즈 목록으로 연결한다. 개발자 탐색은 검색 아래 접힌 내 구독(3종)을 최대 3개 미리 보여주고 전체 보기 모달로 연결한다. 모달은 이름·아이디·태그 검색, 전체/개발자/태그/개발자별 태그 필터, 20개 단위 페이지 이동과 구독 해제를 제공한다. 모바일은 전체 화면, PC는 넓은 모달로 표시한다. 개발자·해시태그·개발자와 해시태그 조합의 3종 구독을 지원한다.
- 풀이 화면·상태·응답에 제출 전 정답·해설·원본 학습 내용을 포함하지 않는다. 작성자 검토와 풀이 데이터 경계를 유지한다.

### 상점과 마이페이지

- 구매는 상점에서, 장착·해제는 `/my/desk`의 보유 상품에서 수행한다. 구매 완료 시 ‘보관함으로 이동’을 제공한다.
- 공개 프로필(`/users/[publicId]`)은 사용자 정보를 상단 고정하고 기본적으로 데스크·최신 공개 퀴즈 최대 4개·학습 활동을 배치한다. 본인 전용 ‘순서 편집’은 프로필 편집과 헤더 관리 그룹에 함께 표시한다. 좁은 화면에서는 ID 아래에 두 버튼을 묶어 배치하며 독립 툴바를 만들지 않는다. ‘순서 편집’ 모달의 간결한 세 행에서 세 섹션을 손잡이 드래그·위/아래 버튼으로 이동하고 저장·취소한다. 저장한 순서는 방문자에게도 적용한다. 장착 아이템이 없으면 기본 데스크를 표시한다.
- 타인에게는 공개 퀴즈만 제공하고 개인 학습 기록·잔액·구매 내역·보관함·설정을 노출하지 않는다.
- 프로필 편집·대표 퀴즈 고정 등은 이 문서로 구현 범위를 자동 확대하지 않는다.

## 4. 병렬 작업과 통합

| 담당 기능      | 소유 범위                                               |
| -------------- | ------------------------------------------------------- |
| 퀴즈 생성·CRUD | 내 퀴즈 목록·생성·작성자 관리                           |
| 퀴즈 풀이      | 공통 풀이 컴포넌트·개별 풀이·Attempt 결과               |
| 탐색·구독      | 탐색 탭·구독 조작                                       |
| 홈 학습        | 홈 태그·연속 풀이·스트릭 요약 배치                      |
| 학습 기록      | 기록·스트릭 상세·달력·시간대 설정 및 홈 요약용 컴포넌트 |
| 쇼핑몰         | 상품·구매·보관함·장착·데스크·BugCoin 내역               |
| 통합           | 공통 헤더·마이페이지 메뉴·공개 프로필 조립·기능 간 링크 |

공통 화면 조립은 담당자 사이에서 조율하고, 다른 워크스페이스의 담당 파일을 임의로 수정하지 않는다.

- UI는 기존 typed API client를 사용한다. 필요한 조회 계약이 없으면 별도 변경으로 명시하며 Mock 파일·localStorage 직접 접근으로 우회하지 않는다.
- 현재 브랜치의 구현 유무와 다른 워크스페이스의 완료 상태를 동일하게 취급하지 않는다. 통합 대상 커밋을 확인한다.
- 시간대 감지 실패 시 기본값과 BugCoin 지급 정책은 미결정 상태를 유지한다. 화면 구조를 근거로 임의 확정하지 않는다.
- 실제 DB·OAuth/JWT·AI 호출·결제는 이번 1단계 작업에 추가하지 않는다.

## 5. 검증 기준

- 방문자 랜덤 풀이 → 제출 후 해설 → 다음 문제, 태그·스트릭 숨김, 기록·보상 미생성, 로그인 후 체험 미이관을 검증한다.
- 탐색의 구독 클릭·상점 구매·보호 URL 접근에서 로그인 안내, 취소·실패, 복귀 후 명시적 재조작을 검증한다.

- 주 메뉴·개인 메뉴의 직접 진입·새로고침·뒤로가기와 모바일·키보드 접근성을 확인한다.
- 생성 → 저장 → 검토·승인 → 개별 풀이 → 결과 복원을 검증한다.
- 탐색 → 구독 → 홈 학습 → 학습 기록과 사용자별 상태 격리를 검증한다.
- 구매 → 보관함 → 장착 → 내 프로필·타인 공개 프로필을 검증한다.
- 빈 상태·요청 실패·재시도·이용 불가 콘텐츠와 학습 시간대의 자정 경계를 확인한다.

이 문서 추가는 문서 전용 작업이다. 링크·요구사항·단계·범위 정합성과 `git diff --check`로 검증하며 기능 pipeline 실행이나 기능 구현 완료를 의미하지 않는다. 구현 작업에는 기존 검증 절차와 구현자 외 리뷰를 적용한다.


## 헤더 선행 통합 — NAV-01

- 현재 구현 경로는 `/discover`, `/quizzes/authoring/manage` 등 기존 경로를 유지한다. 탐색·내 퀴즈만 메뉴로 연결하고 상점·마이페이지는 실제 페이지 통합 시 추가한다. 내 퀴즈 메뉴는 마이페이지 통합 전 임시 직접 진입점이다. 로고는 홈으로 연결한다.
- 데모 사용자 전환은 헤더 우측의 `데모 사용자 선택`으로 통일하며 선택 후에도 버튼을 유지한다. 헤더 하단 배너·프로필 메뉴의 전환 항목·탐색 오류의 별도 사용자 선택은 제공하지 않는다. 구독·풀이 진입에 필요한 사용자 선택 안내는 유지한다. 헤더의 `데모 사용자 선택`에서 사용자를 명시적으로 선택하며 URL의 user 값으로 헤더와 본문 상태를 함께 구분한다. 새로고침에도 URL 사용자를 유지하고 `데모 나가기`로 방문자 화면에 돌아간다. 실제 인증은 아니며 방문자 홈 체험은 개인 학습 기록·보상을 저장하지 않는다.
- 개발자 탐색의 구독 조작에는 데모 사용자 선택 안내를 연결하며 선택 후 다시 명시적으로 실행한다. 실제 인증·권한 보장을 구현한 것으로 간주하지 않는다.
- 브레드크럼은 등록한 경로와 고정 레이블을 사용하고 동적 ID는 표시하지 않는다. 존재하는 상위 페이지에만 링크하며 미구현 상위 페이지는 일반 텍스트로 남긴다. 전시 페이지의 섹션 내비게이션은 제품 헤더와 구분해 유지한다.

### 공개 프로필과 개인 관리의 분리

- `/users/[publicId]`는 본인·타인 모두 같은 공개 화면을 본다. 사용자 이름·공개 ID·구독 버튼, 데스크, 최신 공개 퀴즈 최대 4개를 제공한다. 학습 활동은 홈과 같은 스트릭·월별 학습 달력을 표시한다. 기존 `/developers/[publicId]/quizzes` 경로도 유지한다.
- `/my`는 개인 관리 화면이다. 풀이 기록, 학습 시간대 설정은 제목·컨테이너로 구분하고 데스크 편집 링크를 제공한다. BugCoin 영역에는 본인 잔액과 최신순 지급·사용 내역, 로딩·빈 상태·오류 재시도를 표시한다. 데스크 캔버스·보유 상품·잔액은 `/my/desk`로 분리한다. 편집 화면의 ‘내 공개 프로필 보기’로 공개 화면을 확인하며, 데스크 편집은 마이페이지와 공개 프로필 상단의 본인용 링크에서 접근한다.
- 공개 페이지 본문에는 문제별 풀이 기록·선택한 답·오답·잔액·보관함·개인 학습 설정 컨트롤을 넣지 않는다. 데스크 편집은 개인 마이페이지 또는 공개 프로필 상단의 본인용 링크에서 진입한다. 이는 화면 구성 분리이며 데모 인증을 실제 접근 통제로 바꾸는 작업은 아니다.


### 학습 활동과 풀이 기록

- 사용자 요청으로 공개 프로필의 ‘학습 활동’에 홈 StreakSummary를 재사용한다. 프로필 주인의 스트릭·오늘 완료·날짜별 완료 수와 월/년 탐색을 제공한다. 주요 학습 태그 등 추가 통계는 범위 밖이다.
- 개인 마이페이지의 ‘학습 기록’ 영역은 ‘풀이 기록’으로 표시한다. 문제별 기록·선택한 답·오답·다시 풀기 등 복습 정보는 개인 영역에 남긴다.
- 이번 명시적 요청으로 프로토타입의 스트릭·일별 완료 집계는 공개 프로필에서 조회한다. 문제별 기록과 답안은 공개하지 않는다. 실제 사용자 대상 공개 여부 설정·동의의 세부 범위는 후속 정책으로 남기며 이번에 설정 UI를 추가하지 않는다.

### 공개 프로필 바로가기

- 로그인 데모 헤더의 ‘내 프로필’ 드롭다운은 ‘공개 프로필 보기 → 내 퀴즈 → 코인 내역 → 로그아웃’ 순서로 제공한다. 데스크톱·모바일에서 같은 드롭다운을 사용한다.
- ‘공개 프로필 보기’는 현재 사용자의 publicId를 API로 조회해 `/users/[publicId]?user=현재사용자`로 이동한다. 조회 중에는 상태 문구, 실패 시에는 다시 불러오기 버튼을 표시하며 임의의 프로필 주소를 만들지 않는다.


### 공개 프로필 정보 우선순위

- 모바일·데스크톱 공통 순서: 사용자 이름/공개 ID와 구독 진입 → 데스크 → 최신 공개 퀴즈 최대 4개 → 학습 활동. 빈 프로필 컨테이너는 제거하며 입력한 자기소개와 링크만 표시한다.
- 프로필에는 검색·태그 필터·페이지 이동을 두지 않는다. 최신 4개는 데스크톱 2열·모바일 1열이고 제목 클릭 시 바로 풀이한다. 전체 보기는 `/developers/[publicId]/quizzes`로 연결하며 그곳의 기존 검색·태그 필터·페이지 이동 동작을 유지한다.
- 비로그인 ‘구독하기’는 데모 로그인만 수행한다. 로그인 후 구독 버튼을 다시 눌러 명시적으로 구독하고, 구독 중이면 해제를 제공한다. 본인은 구독 대신 상단 ‘데스크 편집’ 링크로 `/my/desk`에 진입한다.

- 후속 사용자 요청에 따라 데스크는 축소하지 않고 기본 큰 캔버스로 표시한다. ‘데스크’ 제목·크게 보기/접기·데스크 편집 링크·기본 데스크 안내 문구는 제거한다. 45도 시점·정면·위에서 버튼도 제거하고 드래그 시점 조작과 접근성 레이블은 유지한다.

- 공개 프로필 상단의 본인용 링크는 ‘데스크 편집’이며 현재 사용자 쿼리를 보존해 `/my/desk`로 연결한다. 데스크 캔버스 안에는 편집 링크를 중복 표시하지 않는다.

### 공개 프로필 자기소개·링크 — PROFILE-ABOUT

- 본인 공개 프로필에서 ‘프로필 편집’으로 사용자 정보 바로 아래의 Markdown 자기소개·링크 폼을 연다. 데스크 편집 링크는 유지한다. 마이페이지의 빈 프로필 편집 컨테이너는 제거한다.
- 공개 표시는 사용자 정보 → 입력한 자기소개·링크 → 데스크 → 최신 공개 퀴즈 → 학습 활동 순서다. 방문자·타인은 입력한 공개 내용만 볼 수 있다.
- 새 링크는 버튼으로 한 행씩 추가하며 기타만 표시 이름을 받는다. 전체 저장·취소, 행 수정·삭제, 입력 오류·저장 실패와 미저장 취소 확인을 제공한다.

### 공개 프로필 정보 묶음 — PROFILE-LAYOUT

- 후속 사용자 요청에 따라 상단 이름 제목을 제거하고 공개 ID → 자기소개 → 링크를 가까이 배치한다. 프로필 편집은 PC·모바일 공통 상단 오른쪽 콘텐츠 끝에 맞춘다. 이전 896px 정보 묶음 제한과 편집 동작 한 줄 묶음은 이 요청으로 대체한다.
- 후속 PROFILE-BIO-CONTAINER 요청에 따라 소개 컨테이너는 헤더 콘텐츠 전체 폭을 사용한다. 데스크 편집은 데스크 바로 위 우측에 둔다. 두 편집 동작은 그림자·테두리 없는 동일한 낮은 강조 스타일을 사용한다.
- 소개는 16px/28px 본문이며 링크는 서비스별 아이콘·밑줄·외부 이동 화살표로 구분한다. 기타 링크는 지정 이름 옆 실제 도메인을 한 덩어리로 줄바꿈하고 보조기술에도 전달한다.
- 저장·취소 후 공개 정보로 돌아오며 프로필 편집 버튼으로 포커스가 복귀한다. 저장 완료는 화면 하단 공통 토스트(4초 자동 닫힘/직접 닫기)로 표시하며 소개 본문에 남기지 않는다. 데스크 캔버스 크기·퀴즈·활동 영역은 유지한다.

### 공개 프로필 행동 발견성 — PROFILE-POLISH

- 편집 동작은 연필 아이콘·강조색을 공유하고 오른쪽 텍스트 끝을 맞춘다. 소개 아래 공개 퀴즈 개수 바로가기는 후속 요청으로 제거했다. 아래 퀴즈 목록과 전체 보기는 유지한다.
- 소개와 데스크 사이 여백을 줄인다. 사용자 후속 지시에 따라 데스크 캔버스·크기·조작·구도는 기존 상태를 유지한다.

- PROFILE-BIO-CONTAINER: 입력된 Markdown 자기소개만 얇은 테두리·16px 안쪽 여백으로 묶는다. 제목·그림자 없이 링크는 컨테이너 아래에 유지하며 소개가 비어 있으면 컨테이너도 숨긴다.

- 자기소개 컨테이너는 최대768px 제한을 제거하고 헤더 콘텐츠 영역의 좌우 끝에 맞춘다.

- PROFILE-FORM-POLISH: 자기소개 편집기만 compact 모드를 사용하고 링크 행은 간결한 입력 목록으로 표시한다. 링크 추가는 목록 전체 폭의 중앙 + 아이콘이며 보조기술 이름은 ‘링크 추가’다. 추가 후 종류 선택, 저장 검증 실패 후 첫 오류, 취소 확인 후 계속 편집, 복귀 후 이전 입력으로 포커스를 연결한다.

### 마이페이지 BugCoin 시각 정리

`/my` 본문은 최대768px로 제한한다. 데스크 편집 링크 아래에 BugCoin 잔액·필터·5개씩 내역을 먼저 배치한다. 풀이 기록·시간대 설정의 미구현 영역은 하단 제목 중심의 compact 영역으로 남기고 빈 내부 박스를 표시하지 않는다. 실제 설정/학습 기능을 추가한 것은 아니다. 큰 잔액, 거래 사유와 부호 있는 금액, 보조 날짜 순서로 위계를 둔다.

풀이 기록·학습 시간대 설정의 하단 영역은 PC와 모바일 모두 세로 순서로 배치한다. 가로 열로 나누지 않는다.

후속 사용자 수정: 마이페이지의 별도768px 제한을 제거하고 헤더와 같은 공통 max-width1220px 및 좌우 패딩을 사용한다. 하단 관리 영역의 세로 배치와 BugCoin 페이지당5개는 유지한다.

마이페이지의 ‘데스크 꾸미기 바로가기’는 BugCoin 아래 개인 관리 영역에서 풀이 기록·학습 시간대 설정과 함께 세로 항목으로 표시한다. 제목 옆이나 BugCoin 위에는 배치하지 않는다. /my/desk로 이동하며 현재 더미 사용자 쿼리를 유지한다.

### 개발자·태그 탐색 분리

- 개발자 탐색 `/discover/developers`, 태그 탐색 `/discover/tags`를 헤더·모바일 메뉴에서 각각 제공한다. 기존 통합 탭 구성을 대체한다.
- 검색어·페이지·데모 사용자는 URL로 복원한다. 기존 `/discover`는 kind에 맞는 새 페이지로 연결한다. 학습 소진의 태그 탐색은 태그 페이지, 프로필의 상위 탐색은 개발자 페이지로 연결한다.

### TAG-DISCOVERY-POLISH — 태그 탐색

- 태그 탐색은 제목 → 검색 → 전체 태그/내 구독 필터 → 결과 순서로 배치한다. 태그 페이지의 빈 내 구독 자리표시자를 제거하고 HASHTAG 직접 구독을 API에서 필터링한 실제 목록으로 대체한다. 개발자 탐색 자리표시자는 이번 범위 밖이다.
- 태그명·구독 중 상태·공개 퀴즈 수를 표시한다. 공개 퀴즈가 없는 태그도 구독 가능하며 학습 버튼만 비활성화한다.
- 태그 페이지의 구독·해제·학습은 데모 세션 안내를 연결한다. 로그인 후 같은 검색 조건에 머물고 원래 행동을 자동 실행하지 않는다. 앞의 NAV-01 로그인 게이트 미구현 설명은 이 페이지에서만 대체하며 실제 인증·다른 화면 통합은 포함하지 않는다.
- 검색/필터와 내 구독 URL 복원, 빈 상태·조회 실패·입력 검증·페이지 범위 복귀, 메뉴/검색/해제 키보드 초점과 모바일 44px 행동 영역을 제공한다.


### 개발자별 퀴즈 상단 — DEVELOPER-CATALOG-HEADER

- 개발자 아바타·이름·공개 ID 링크와 개발자 구독 상태를 하나의 헤더에 둔다. 태그 검색은 폭을 제한한 보조 도구로 제공한다.
- 최신 사용자 요청으로 태그명 클릭의 자동 구독을 제거한다. 태그명은 퀴즈 필터, 옆의 구독 버튼은 해당 개발자의 태그 구독이다. 선택 배경과 구독 체크를 구분하며 메뉴/구독 버튼은 최소44px 조작 영역을 갖는다.
- 태그 검색으로 선택 항목이 숨겨져도 공개 퀴즈 제목 옆에 선택한 태그와 ‘전체 퀴즈’ 해제를 유지한다. 방문자 필터/탐색은 user 값을 추가하지 않으며 구독 요청은 명시적 데모 선택 뒤 다시 실행한다. 공개 프로필과 퀴즈 카드는 유지한다.

### COIN-ROUTE — 코인 내역 전용 화면 (앞선 마이페이지 구성 대체)

- 기존 개인 관리 `/my` 화면은 `/coin-history`로 이동하고 제목·프로필 메뉴·현재 위치를 ‘코인 내역’으로 통일한다. `/my` 접근 시 사용자 쿼리를 보존해 새 경로로 연결한다.
- 풀이 기록·학습 시간대 설정 자리표시자를 제거한다. BugCoin 잔액·필터·페이지당 5개 내역·상점 이동과 하단 데스크 꾸미기 바로가기는 유지한다.
- 공통 콘텐츠 폭과 기존 PC·모바일 스타일을 유지한다. `/my/desk`는 독립된 데스크 편집 경로이며 현재 위치는 ‘홈 → 데스크 편집’이다.
- 학습 기록·시간대의 도메인 정책이나 장기 제품 요구를 삭제하는 변경은 아니다. 앞선 마이페이지의 미구현 영역 배치 설명은 이 구성으로 대체한다.

### DEVELOPER-TAG-PANEL

개발자별 공개 퀴즈의 헤더 구독 설정은 공통 ResponsivePopover를 사용한다. PC는 앵커 패널, 모바일은 하단 모달이며 제목/닫기·검색·페이지 조작과 스크롤 목록을 제공한다. 전체/태그 구독은 기존 PERSON/PERSON_HASHTAG 계약을 유지한다. 바깥 태그 검색/필터는 펼친 공통 FilterChips로 다중 선택(OR), 개별 해제 및 전체 초기화를 제공한다. URL 반복 tag로 복원하며 필터 변경 시 퀴즈 페이지를 1로 되돌린다. 구독 패널 검색·페이지는 바깥 조건을 바꾸지 않는다. 이전 DEVELOPER-CATALOG-HEADER의 태그 옆 구독 버튼 배치는 이 구조로 대체한다.

- 공개 프로필의 최신 공개 퀴즈는 데스크·학습 활동과 같은 흰 배경의 둥근 테두리 섹션으로 표시한다. 최신4개 카드와 중립색 전체보기는 유지하고, 빈 상태는 작은 내부 여백과 한 줄 안내로 표시한다.
