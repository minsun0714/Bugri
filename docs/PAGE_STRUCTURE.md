# Bugri 페이지 구조

2026-11-08 제품 방향 재정의에 따른 1단계 화면 구성과 흐름이다. 제품 규칙은 [PRD](PRD.md), 데이터 경계는 [아키텍처](ARCHITECTURE.md), 호출 계약은 [API](API.md)를 따른다. 구현 완료 기록이 아니다. 이전 구조는 [보관 문서](archive/PAGE_STRUCTURE-v1.md)에 있다.

## 1. 전체 흐름

```text
[홈] 빠른 메모 저장 ──(나중에)──▶ [메모 상세] 퀴즈로 만들기 → 후보 확인·수정 → 저장
  ▲                                                                     │
  └──── [홈] 오늘 복습 ◀──── 다음 복습일 도래 ◀──────────────────────────┘
          맞힘: 간격 늘림(1→3→7→14→30일) / 틀림: 다음 날 다시
```

## 2. 메뉴와 경로

헤더: **로고(홈) · 내 노트 · 언어 선택 · 다크모드 토글 · 데모 사용자 전환**. 홈은 로고로 이동하므로 별도 메뉴를 두지 않는다. 데스크톱 헤더와 모바일 메뉴의 항목·순서를 같게 유지한다.

| 경로 | 역할 |
| --- | --- |
| `/` | 빠른 메모, 오늘 복습, 연속 학습일 요약 |
| `/notes` | 내 노트 목록·검색·태그 필터 |
| `/notes/[noteId]` | 메모 본문·수정·삭제, 퀴즈로 만들기, 이 메모의 퀴즈 목록 |

- 경로 이름은 위를 기준으로 하되 구현 시 기존 라우트와 충돌하면 API·테스트와 함께 조정한다.
- 1단계에는 방문자와 데모 사용자 선택으로 UX를 검증한다. 데모 사용자 선택을 실제 로그인으로 표현하지 않는다.

## 3. 화면별 구성과 상태

### 홈 `/` (데모 사용자)

위에서 아래 순서로 배치한다. 업무 중에는 적으러 들어오고, 여유가 있을 때 복습한다.

1. **빠른 메모**
   - 첫 화면 맨 위의 입력창. 기본은 낮은 높이이며 입력하면 늘어난다. 코드 블록·글자 수(`현재 / 10,000자`)를 지원한다.
   - 저장 성공: 입력창을 비우고 "저장했어요 · 퀴즈로 만들기" 토스트. 토스트의 행동은 해당 메모 상세로 이동한다.
   - 저장 실패·공백·초과: 입력을 유지하고 입력창 가까이에 이유를 표시한다.
2. **오늘 복습**
   - 제목에 남은 개수(`오늘 복습 N개`)를 표시하고 한 문제씩 홈 안에서 푼다. 틀렸던 문제와 오래된 순서를 먼저 낸다.
   - 결과: 선택한 답·정오·정답·해설, 다음 복습일, "원래 메모 보기", "다음 문제".
   - 모두 완료: "오늘 복습 끝"과 내일 복습할 개수.
   - 퀴즈 없음: 복습 영역에 "메모를 퀴즈로 만들면 여기서 복습해요" 정도의 짧은 안내만 두고 빠른 메모를 강조한다.
   - 퀴즈는 있지만 오늘 복습할 것이 없음: 다음 복습일과 개수.
3. **연속 학습일 요약**
   - 작은 버그리, 현재 연속 학습일, 오늘 완료 여부를 한 줄로 표시하고 학습 달력은 기본으로 접는다. 복습 제출 후 기록만 갱신하고 펼침 상태는 유지한다.

모바일에서는 첫 화면에 빠른 메모 입력과 오늘 복습의 시작이 보이도록 상단 높이를 줄인다.

### 내 노트 `/notes`

- 상단: 검색창과 태그 칩(여러 개 선택, 하나라도 포함) + "태그 없음" 칩.
- 목록: 최신순. 항목마다 본문 앞부분, 작성일, 태그, 퀴즈 개수 또는 "퀴즈 없음". 항목 전체가 메모 상세로 이동한다.
- 검색어·태그·페이지는 URL로 복원한다. 조건이 바뀌면 첫 페이지부터 조회한다.
- 상태: 메모 없음(홈에서 첫 메모를 쓰도록 안내) / 조건에 맞는 결과 없음(조건 초기화) / 로딩 / 오류와 재시도.

### 메모 상세 `/notes/[noteId]`

- 본문: Markdown과 코드 블록을 그대로 표시한다. "수정" 버튼을 누르면 같은 화면에서 편집 모드로 바뀌고, 저장 전 이탈 시 경고한다.
- 삭제: 연결된 퀴즈 개수를 알려 주는 확인 모달을 거친다. 삭제 후 내 노트로 이동한다.
- **퀴즈로 만들기**
  - 누르면 작업 모달을 연다. 생성 중 상태를 표시하고 중복 요청을 막는다. 모바일은 전체 화면.
  - 후보 1~5개를 탭으로 보여 준다. 후보마다 형식·문제·선택지·정답·해설·태그, "직접 수정", "LLM으로 수정", "저장"(개별).
  - 하단에 "남은 퀴즈 모두 저장"(아직 저장하지 않은 후보 전부)을 둔다. 저장한 후보는 탭에 "저장됨"을 표시한다. 미반영 수정이 있는 후보는 저장을 막고 이유를 표시한다.
  - 저장 후 모달을 닫고 아래 퀴즈 목록에 새 퀴즈를 표시한다. 닫기 전 미저장 후보가 있으면 확인한다.
- **이 메모의 퀴즈**: 퀴즈마다 형식, 제목, 태그, 다음 복습일, 수정·삭제.
- 없는 메모·삭제된 메모·다른 사용자의 메모: 접근할 수 없다는 안내와 내 노트로 돌아가기.

### 방문자 홈 `/` (마지막 단계에서 구현)

- 예시 메모 → 생성된 퀴즈 → 한 문제 풀어 보기 순서로 보여 준다. 결과는 저장하지 않는다.
- 메모 작성·내 노트 진입 시 데모 사용자 선택을 안내한다. 선택 후 원래 화면으로 돌아오되 저장 동작을 자동 실행하지 않는다.
- 구현 전까지 방문자 홈은 서비스 한 줄 소개와 데모 사용자 선택 안내만 있는 임시 화면으로 둔다.

## 4. 공통 규칙

- 제출 전 정답·해설과 다른 사용자의 메모·퀴즈를 응답·화면에 포함하지 않는다.
- 로딩·빈 상태·오류(입력 보존과 재시도)·접근 불가 상태를 각 화면에 둔다. 영구 오류에는 재시도 대신 돌아갈 곳을 제공한다.
- 키보드 포커스, 줄인 모션 설정, 모바일 배치, 라이트·다크와 한국어·영어를 모든 화면에서 유지한다.
- UI는 typed API 클라이언트만 사용하며 Mock 파일·localStorage에 직접 접근하지 않는다.
