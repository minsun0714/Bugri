# Bugri MVP 작업 계획

## 1. 사용 방법과 현재 상태

요구사항은 [PRD.md](PRD.md), 구조와 계약은 [ARCHITECTURE.md](ARCHITECTURE.md)를 기준으로 한다. 전체 제품의 공유·구독 방향은 유지하되 이번 구현은 PRD의 여섯 기능만 대상으로 한다.

현재 홈 화면과 Next.js 프로젝트 기반만 존재한다. 이 문서를 작성한 시점에는 MVP API·DB·AI·검토·풀이·버그리 기능을 구현하거나 검증하지 않았다. 기존 `AGENTS.md`와 `package-lock.json`의 작업 중 변경은 이 계획의 구현 완료 근거가 아니다.

상태는 `TODO`(미착수), `IN_PROGRESS`(진행 중), `BLOCKED`(사유와 해제 조건 필요), `DONE`(검증 근거 있음)을 사용한다. 한 작업을 시작하면 상태를 바꾸고, 완료 시 관련 파일·실행 명령·결과를 기록한다. 실패하거나 실행하지 못한 검증은 그대로 적고 완료로 표시하지 않는다.

## 3. 작업별 범위와 완료 조건

### 01~03: 최소 기반

- 01에서 테스트 도구를 결정하고 02에서 도메인 테스트 실행 환경을 먼저 구성한다. 03에서 MySQL 8.4 통합 검증 환경을 마련한다. 세션 만료와 실제 데이터 정리 정책의 검증은 구분한다.
- 기술 선택은 Next.js 풀스택·MySQL과 Spring Boot 전환 원칙 안에서 한다. Spring Boot 프로젝트는 아직 생성하지 않는다.
- 계약에는 작성자용 ReviewQuiz와 풀이용 AttemptView를 분리한다. 데이터 모델·FK·유일성·버전 필드를 먼저 정의한다.
- 세션 없는 요청, 만료된 세션, 다른 세션의 ID 접근, 변경 요청의 Origin 검사를 검증한다.
- DB 연결 정보와 AI 키는 서버 환경변수로 관리한다. 환경 예시와 실행 방법에는 비밀값을 넣지 않는다.
- DB 마이그레이션과 테스트 방법을 기록하고 로컬 MySQL에서 재현 가능하게 만든다.

### 04~05: 입력에서 생성까지

- 입력과 생성 상태 UI를 연결하고 실패해도 입력을 보존한다.
- AI 어댑터는 정상 응답, 구조 오류, 문항 수 불일치, 정답의 보기 참조 오류, 거절·입력 부족, 제공자 실패, 시간 초과를 구분한다.
- 유효하지 않은 AI 결과를 저장하지 않고 정상 결과만 DRAFT로 저장한다.
- 본문·해설 코드 블록이 있는 응답과 없는 응답, 잘못된 언어/코드 형식을 검증한다. 구조 검증 통과를 기술적 정확성 검증으로 보고하지 않는다.
- 요청 중복·실패 재시도·만료 lease·저장 실패를 검증한다. 요청 제한은 여러 서버 프로세스에서도 유지되어야 한다.
- 실제 제공자에 예제 지식과 실행하지 않는 코드 조각을 보내 생성 경로를 한 번 이상 검증한다. 자동 테스트에 외부 AI 호출을 필수로 넣지 않는다.

### 06~07: 검토에서 승인 저장까지

- 제목·문항·보기·정답·해설 편집, 문항별 검토 표시, 초안 저장, 승인 저장을 구현한다.
- 내용 PUT → 저장된 내용 재확인 → 검토 PATCH → 승인 순서를 확인한다. PUT에 reviewed를 넣으면 거부하고, 수정 후 false·재검토 후 true·오래된 version 충돌을 검증한다. 미저장 변경 상태에서는 승인하지 않는다.
- 본문·해설 코드 블록의 추가·편집·제거, 언어 변경, 개행·들여쓰기 보존과 검토 해제를 검증한다.
- 미검토·필수값 누락·오래된 버전·READY 수정 요청을 차단한다.
- 저장 실패와 충돌 시 작성 내용이 사라지지 않는지 확인한다. 저장 성공 후 새로고침과 서버 재시작으로 영속성을 확인한다.
- 목록은 정답·원본 코드 없이 요약만 반환하며 빈 상태와 다음 페이지를 지원한다.

### 08~09: 풀이와 채점

- READY에서만 새 풀이를 시작하고 생성 요청 재시도로 중복 Attempt가 생기지 않게 한다.
- 미제출 문항의 correctOptionId, explanation, isCorrect 등 정답 관련 필드가 응답·HTML·RSC에 없는지 확인한다.
- 본문 코드 블록은 제출 전에 표시하고 explanationCodeBlock은 제출 후에만 전달하는지 확인한다. 코드가 실행되지 않고 언어·개행·들여쓰기가 보존되는지 검증한다.
- 다른 퀴즈의 문항, 다른 문항의 보기, 순서가 아닌 문항, 다른 소유자의 풀이에 대한 제출을 거부한다.
- 같은 답의 재전송은 기존 결과, 다른 답의 재전송은 충돌로 처리한다. 동시 요청에도 점수와 완료 상태가 일치해야 한다.
- 제출 후 새로고침 시 결과·진행을 복원한다. 다시 풀기는 새 기록으로 시작한다.

### 10: 버그리

- PRD의 이벤트별 문구와 기본 표정을 연결한다. 상태 전환을 위해 별도 AI 호출을 추가하지 않는다.
- 정오 반응은 채점 응답 이후에만 표시하고 마지막 문항의 결과와 완료 반응을 분리한다.
- 화면 읽기 도구와 키보드 사용 시 반응이 핵심 조작을 방해하지 않게 한다. 캐릭터 성장이나 아이템 기능은 추가하지 않는다.

## 4. 검증 명령과 실행 정책

코드 구현 시 기본 검사:

```bash
npm run lint
npx tsc --noEmit
npm run build
```

테스트 실행 환경을 구성한 이후:

```bash
npm test
npx playwright test
```

현재 `npm test` 스크립트와 Playwright 환경은 구성되지 않았다. 01~03 단계에서 구성한 뒤 사용하며, 설치하지 않은 명령을 통과했다고 기록하지 않는다. Next.js 빌드와 린트는 별도로 실행한다. 각 기능 변경에는 관련 테스트를 먼저 실행하고 최종 통합 단계에서 전체 검증을 수행한다. 문서만 바꾸는 이번 작업에는 빌드나 기능 테스트를 완료 조건으로 삼지 않는다.

## 6. 후속 백로그 — 이번 MVP에서 착수하지 않음

| 항목                                  | 상태    | 재검토 시점                         |
| ------------------------------------- | ------- | ----------------------------------- |
| 퀴즈 공개 공유·탐색, 친구와 함께 학습 | BACKLOG | 개인 생성·검토·풀이 흐름 검증 후    |

| 회원가입·로그인, 기기 간 동기화       | BACKLOG | 익명 MVP 검증 후 계정 모델 설계 시  |
| 오답 노트·학습 통계·추천·복습 알림    | BACKLOG | 학습 기록 활용 범위 결정 후         |

| Spring Boot 백엔드 전환               | BACKLOG | 운영 요구로 분리 필요성이 확인될 때 |

PRD의 전체 제품 요구사항 A~F는 확정된 방향이며 구현 시기·상세 정책이 미결정이다. 구독 3유형과 피드 중복 제거, XP/DP·미션·Streak·업적, 데스크테리어 구매·보관·장착과 중복/잔액 제어, 마이페이지, 블로그·퀴즈 임베드를 후속 범위로 보존한다. 기존 표의 추천·알림·대화 등 A~F에 없는 확장 아이디어는 별도 검토 대상이다. 어느 항목도 편의를 이유로 MVP에 선행 구현하지 않는다.
