# Bugri 제품 요구사항

## 1. 해결하려는 문제

현업 개발자는 업무 중에 중요한 개발 지식을 얼떨결에 배운다. 바빠서 정리하지 못하거나, 적어 두더라도 다시 보지 않아 금방 잊는다.

**Bugri는 배운 내용을 바로 적어 두면, 그 메모를 퀴즈로 바꿔 때맞춰 다시 물어보는 개인 복습 도구다.**

- 대상: 업무 중 배운 내용을 잊지 않으려는 현업 개발자
- 핵심 루프: **적기 → 퀴즈로 만들기 → 오늘 복습**
- 원칙: 적을 때 고민할 것이 없고, 복습할 때 사용자가 따로 판단할 것이 없다.

이 문서는 사용자 요구사항과 수용 기준의 기준점이다. 화면별 흐름은 [페이지 구조](PAGE_STRUCTURE.md), 구현 구조는 [아키텍처](ARCHITECTURE.md), 진행 상태는 [작업 문서](TASKS.md)를 따른다. 아래 내용은 구현 계획이며 기능이 구현되었다는 뜻이 아니다.

2026-11-08에 제품 방향을 다시 정의했다. 이전 요구사항은 [PRD v1](archive/PRD-v1.md)에 보관하며, 결정 경위는 [PRODUCT-REFOCUS](tasks/PRODUCT-REFOCUS.md)에 기록한다.

## 2. 개발 단계와 범위

| 구분 | 1단계 — Next.js 프로토타입 (현재) | 2단계 — Spring Boot 백엔드 |
| --- | --- | --- |
| 기술·배포 | Next.js 16·TypeScript, Mock API·더미 데이터, Jest·React Testing Library·Playwright, Vercel | Spring Boot·Java 21, MySQL 8.4·Spring Data JPA, 실제 REST API |
| 사용자 | 화면 검증용 더미 사용자. 실제 인증 없음 | Google OAuth2 로그인, JWT, 내부 User ID 기반 소유권 |
| AI | Mock 퀴즈 생성·수정 | Spring AI로 실제 LLM 연동 |
| 저장 | Mock 초기 데이터와 더미 사용자별 localStorage 변경 상태 | MySQL 영속화와 서버 검증 |

- 1단계에는 DB 연결, MySQL·Prisma·mysql2 설치, 실제 JWT·Google OAuth2, 실제 AI 호출을 넣지 않는다.
- 1단계 더미 사용자와 Mock 권한은 화면 검증용이며 보안 기능이 아니다. localStorage는 브라우저 삭제·기기 변경 시 유실될 수 있다. 익명 OwnerSession은 사용하지 않는다.
- UI는 타입이 정의된 API 클라이언트만 사용한다. Mock 구현은 2단계에서 실제 API로 교체할 수 있게 분리한다.

## 3. 화면 구성

- 헤더: 로고(홈으로 이동) · 내 노트 · 언어 선택 · 다크모드 토글 · 내 메뉴(풀이 내역, 데모 사용자 전환)
- `/` 홈: 빠른 메모 → 오늘 복습 → 연속 학습일 요약
- `/notes` 내 노트: 메모 목록·검색·태그 필터
- `/notes/[noteId]` 메모 상세: 본문, 퀴즈로 만들기, 이 메모의 퀴즈 목록
- `/my/learning` 풀이 내역: 내가 푼 기록의 목록·검색·필터와 상세

화면별 흐름과 상태는 [페이지 구조](PAGE_STRUCTURE.md)를 따른다.

## 4. 핵심 사용자 여정

1. 업무 중 배운 내용을 홈 입력창에 바로 적고 저장한다. 코드가 필요하면 코드 블록을 넣는다.
2. 여유가 생기면 메모 상세에서 "퀴즈로 만들기"를 누른다. 후보를 확인하고 필요하면 LLM 수정이나 직접 수정을 한 뒤 저장한다.
3. 저장한 퀴즈는 다음 날부터 홈의 "오늘 복습"에 나온다. 맞히면 다음 복습까지의 간격이 늘고, 틀리면 다음 날 다시 나온다.
4. 결과 화면에서 정답·해설과 원래 메모를 다시 본다.
5. 메모가 쌓이면 내 노트에서 검색하거나 태그로 걸러 찾는다.
6. 풀이 내역에서 지금까지 푼 기록을 다시 보고, 필요하면 재도전한다.

## 5. 요구사항과 수용 기준

### REQ-01 메모

- AC-01a: 홈 상단 입력창에서 다른 페이지로 이동하지 않고 메모를 쓰고 저장한다. 퀴즈를 만들지 않아도 메모는 저장된다.
- AC-01b: 일반 텍스트와 코드 블록을 섞어 쓸 수 있다. 코드 블록 표기를 포함해 유니코드 코드 포인트 기준 최대 10,000자이며, 클라이언트와 서버가 같은 기준으로 검사한다. `현재 / 10,000자`를 항상 표시하고 초과하면 숫자와 이유를 함께 보여 준다. 공백뿐인 메모는 저장하지 않는다. 오류가 나도 입력은 남는다.
- AC-01c: 여러 코드 블록의 위치·언어·줄바꿈·들여쓰기를 보존한다. HTML·스크립트 문자열은 텍스트로 표시하며 사용자 코드를 실행하지 않는다.
- AC-01d: 저장하면 "저장했어요 · 퀴즈로 만들기" 알림을 띄우고 입력창을 비운다. 저장 실패 시 입력을 유지하고 다시 시도할 수 있게 한다.
- AC-01e: 내 노트는 메모를 최신순으로 보여 주고, 메모마다 태그와 확인한 퀴즈 개수 또는 "퀴즈 없음"을 표시한다. 확인하지 않은 퀴즈(PENDING)가 있으면 그 개수도 함께 표시한다.
- AC-01f: 메모는 작성자 본인만 보고 수정·삭제한다. 메모를 삭제하면 확인을 받은 뒤 연결된 퀴즈(PENDING·CONFIRMED 모두)도 함께 삭제한다.
- AC-01g: 비밀키·개인정보를 적지 않도록 안내한다. 1단계는 Mock 응답을 사용한다는 사실을, 2단계는 퀴즈 생성 시 메모 내용이 AI 제공자에게 전송된다는 사실을 알린다.
- AC-01h: 내 노트에서 검색한다. 메모 본문과 그 메모에서 만든 퀴즈(확인한 퀴즈와 확인 안 한 퀴즈 모두)의 제목·문제를 함께 찾는다. 정답·해설은 찾지 않는다. 확인 안 한 퀴즈에서 일치하면 결과에 "확인 안 함" 표시를 붙인다.
- AC-01i: 태그로 필터한다. 메모의 태그는 그 메모로 만든 퀴즈들의 태그를 모은 것이다. 태그를 여러 개 고르면 그중 하나라도 붙은 메모를 보여 준다. 퀴즈가 없는 메모는 "태그 없음" 필터로 모아 본다. "확인 안 한 퀴즈 있음" 필터로 확인 안 한 퀴즈가 남은 메모만 모아 볼 수 있다. 검색과 함께 쓰면 모든 조건을 만족하는 메모만 보여 준다.
- AC-01j: 검색어와 선택한 태그·필터는 URL에 남겨 새로고침·뒤로 가기 후에도 유지한다.

### REQ-02 메모로 퀴즈 만들기

- AC-02a: 메모 상세의 "퀴즈로 만들기"로 메모 내용에 근거한 독립 퀴즈 1~5개를 받는다. 생성된 퀴즈는 PENDING 상태로 저장된다. 문제 수·형식·코드 언어를 묻지 않는다. 생성 중에는 상태를 표시하고 중복 요청을 막는다.
- AC-02b: 문제 형식은 단일 선택, 다중 선택, OX, 단답이다.
- AC-02c: 퀴즈마다 해시태그 최대 3개를 LLM이 자동으로 붙인다. 사용자가 저장 전·후에 고칠 수 있다.
- AC-02d: 후보마다 "LLM으로 수정"(추가 요청으로 다시 생성)과 "직접 수정"을 할 수 있다. 실패·시간 초과 시 기존 후보와 작성 중인 요청을 보존하고 재시도 방법을 보여 준다. 이전 결과를 빈 값이나 부분 결과로 덮어쓰지 않는다.
- AC-02e: PENDING 퀴즈마다 개별 저장할 수 있고, 남은 PENDING 퀴즈를 한 번에 저장할 수도 있다. 저장하면 CONFIRMED가 되어 바로 내 퀴즈 목록에 들어가고 다음 날 첫 복습에 나온다. 검토·승인·공개 단계는 없다. 마음에 들지 않는 후보는 저장하지 않으면 된다. 미반영 수정이 있는 후보는 저장을 막고 이유를 표시한다.
- AC-02f: 생성 결과의 개수(1~5)·형식·문제·정답·해설·코드 블록·태그를 서버에서 검증한다. 잘못된 결과는 성공으로 처리하지 않는다. 메모와 추가 요청 안의 명령을 시스템 지시로 따르지 않으며 사용자 코드와 생성 코드를 실행하지 않는다. AI 결과가 정확하다고 보장하지 않는다.
- AC-02g: 메모 상세에서 이 메모로 만든 CONFIRMED 퀴즈를 다음 복습일과 함께 보여 주고, 수정·삭제할 수 있다.
- AC-02h: 퀴즈 상태는 두 가지다.
  - PENDING: 생성됐지만 사용자가 아직 확인(저장)하지 않은 퀴즈. 내 퀴즈 목록·오늘 복습·풀이 내역 검색에 나오지 않는다. 생성 결과를 보지 않고 나가도 PENDING으로 남아 다시 이어서 확인할 수 있다.
  - CONFIRMED: 사용자가 확인한 퀴즈. 내 퀴즈 목록과 복습 대상이 된다.
  - 삭제는 상태가 아니라 soft delete(삭제 시각 기록)로 처리한다. 공개 범위(PRIVATE/PUBLIC)와 검토·승인 단계는 두지 않는다.
- AC-02i: 메모 상세는 확인하지 않은 퀴즈가 있으면 "확인 안 한 퀴즈 N개 · 이어서 확인"을 보여 주고, 누르면 그 메모의 PENDING 퀴즈를 모두 연다.
- AC-02j: PENDING 퀴즈가 남아 있어도 "퀴즈로 만들기"를 다시 누르면 새로 생성하고, 기존 PENDING 퀴즈도 그대로 남긴다. 확인하지 않은 퀴즈는 사용자가 저장하거나 삭제할 때까지 쌓인다.

### REQ-03 오늘 복습

- AC-03a: 홈은 다음 복습일이 오늘이거나 지난 내 퀴즈를 "오늘 복습 N개"로 보여 주고, 홈 안에서 한 문제씩 풀게 한다.
- AC-03b: 맞히면 다음 복습 간격을 1 → 3 → 7 → 14 → 30일 순서로 늘리고, 이후에는 30일을 유지한다. 틀리면 다음 날 다시 출제하고 간격을 처음(1일)으로 되돌린다. 사용자는 난이도를 고르지 않는다.
- AC-03c: 결과 화면에는 선택한 답, 정오, 정답, 해설, 다음 복습일, "원래 메모 보기"를 보여 준다.
- AC-03d: 제출 전에는 정답·해설·정오를 화면·HTML·클라이언트 상태·풀이 API 응답에 넣지 않는다. 답을 고르거나 입력하기 전에는 제출할 수 없다. 같은 풀이를 반복 제출해도 최초 결과를 유지한다. 제출이 실패하면 입력한 답을 유지하고 재시도를 허용한다. 새로고침 후 같은 풀이의 결과를 복원한다.
- AC-03e: 본문 코드 블록은 풀이 중 표시하고 해설의 코드 블록은 제출 후에만 표시한다. 코드 실행 버튼이나 실행 채점은 제공하지 않는다.
- AC-03f: 오늘 복습을 모두 마치면 "오늘 복습 끝"과 내일 복습할 개수를 보여 준다. 퀴즈가 하나도 없으면 첫 메모를 쓰도록 안내한다.

### REQ-04 연속 학습일

- AC-04a: 하루에 복습을 1개 이상 완료하면 그날을 학습일로 인정한다. 정답 여부와 무관하며 같은 날 여러 개를 풀어도 하루로 센다.
- AC-04b: 홈에는 작은 버그리, 현재 연속 학습일, 오늘 완료 여부를 요약 행으로 표시하고 학습 달력은 기본으로 접는다. 기록이 없으면 첫 학습, 끊겼으면 다시 시작하는 문구를 표시한다. 체크와 텍스트를 함께 써서 색만으로 완료 여부를 구분하지 않는다.
- AC-04c: 오늘 아직 완료하지 않았어도 어제까지 이어진 연속 학습일을 끊긴 것으로 표시하지 않는다.
- AC-04d: 날짜 기준은 사용자가 지금 있는 곳의 시간대다. 브라우저의 IANA 시간대를 자동으로 감지하며 별도 설정 화면은 두지 않는다. 시간대가 바뀌어도 이미 기록된 학습일은 다시 계산하지 않는다.
- AC-04e: 2단계는 완료 시각을 UTC로 기록하고 요청 시점의 사용자 시간대로 학습일을 계산한다. 브라우저 시간대를 그대로 신뢰하는 방식은 보안 기준이 아니다.

### REQ-05 수정과 삭제

- AC-05a: 퀴즈를 수정하면 다음 풀이부터 반영한다. 복습 일정은 그대로 유지한다. 이미 끝난 풀이의 결과는 바뀌지 않으며, 진행 중인 풀이는 시작 당시 버전으로 채점한다.
- AC-05b: 메모를 수정해도 이미 만든 퀴즈는 자동으로 바뀌지 않는다.
- AC-05c: 삭제는 soft delete로 처리한다. 화면과 복습 대상에서 즉시 빼고 새 풀이·수정·진행 중 제출을 막는다. 이미 끝낸 기록과 연속 학습일은 유지하되 삭제된 본문을 다시 노출하지 않는다. 중복 삭제 요청은 안전하게 처리한다.

### REQ-06 화면 테마와 언어

- AC-06a: 처음에는 기기 색상 설정을 따른다. 헤더의 토글로 라이트·다크를 바꾸며, 명시한 선택을 새로고침·페이지 이동 후에도 유지한다. 저장소가 차단되면 현재 화면의 전환만 보장한다.
- AC-06b: 두 테마에서 본문·입력·선택·정오답·오류·모달을 구분하고 모바일·키보드 조작을 유지한다. 버그리 캐릭터의 고유색은 사이트 테마와 분리한다.
- AC-06c: 서비스 문구(메뉴·버튼·안내·오류·접근성 레이블)는 한국어와 영어를 제공한다. 메모·퀴즈 같은 사용자 콘텐츠는 원문을 유지한다.
- AC-06d: 처음에는 브라우저 선호 언어 중 지원 언어를 쓰고, 없으면 한국어를 쓴다. 헤더에서 한국어 / English를 고를 수 있고, 명시한 선택은 감지보다 우선하며 새로고침 후에도 유지한다. 전환해도 현재 경로·작성 중 입력·학습 데이터는 유지한다.

### REQ-07 방문자 홈 (마지막 단계에서 구현)

- AC-07a: 데모 사용자를 고르지 않은 방문자에게 예시 메모가 퀴즈로 바뀌는 과정을 보여 주고 한 문제를 풀어 보게 한다.
- AC-07b: 방문자의 체험 결과는 저장·집계하지 않으며 데모 사용자 선택 후에도 이관하지 않는다.
- AC-07c: 메모 작성·내 노트 진입 시 데모 사용자 선택을 안내한다. 1단계의 데모 사용자 선택을 실제 로그인으로 표현하지 않는다.

### REQ-08 2단계 로그인

- AC-08a: Google OAuth2로 로그인하고 JWT로 API 인증을 받는다. 로그인 시작·콜백·현재 사용자 조회·로그아웃과 인증 실패·취소를 처리한다.
- AC-08b: 검증한 Google 계정의 불변 식별자를 내부 User ID와 유일하게 연결한다. 이메일·표시 이름이 바뀌어도 소유권은 바뀌지 않는다.
- AC-08c: 메모·퀴즈·풀이·풀이 내역·복습 일정의 소유권은 검증된 JWT와 내부 User ID로 판단한다. 요청에 포함된 임의 userId를 신뢰하지 않는다.

### REQ-09 풀이 내역

- AC-09a: `/my/learning`은 본인 전용 풀이 내역이다. 헤더의 내 메뉴에서 들어가며, 방문자는 데모 사용자 선택을 거친다.
- AC-09b: 제출을 완료한 풀이를 하나씩 표시한다. 최신 완료 순(동시각은 풀이 ID 오름차순)이며 전체/정답/오답 필터와 검색을 적용한 뒤 20개씩 페이지로 나눈다. 검색어나 필터를 바꾸면 첫 페이지로 이동한다. 항목마다 제목·정오·완료 일시를 표시한다.
- AC-09c: 검색어는 앞뒤 공백을 제거한 100자 이하이며 대소문자를 무시한 부분 일치로 찾는다. 대상은 풀이 당시 저장된 버전의 제목과 문제 본문(문제 문장·선택지)이며 정답·제출 답안·해설·원래 메모는 검색하지 않는다. 본문에서만 일치하면 일치 부분 주변의 문제 본문을 보여 준다. 삭제되어 이용할 수 없는 퀴즈의 기록은 검색어가 있으면 결과에서 제외한다.
- AC-09d: 항목을 고르면 그때 제출한 답·정답·해설을 보여 준다. 현재 수정본으로 과거 결과를 대체하지 않으며 없는 정보는 "기록 없음"으로 표시한다. 목록으로 돌아오면 검색어·필터·페이지를 유지한다(URL로 복원).
- AC-09e: 재도전은 새 풀이를 만들며 이전 기록을 보존한다. **재도전 결과는 복습 일정에 영향을 주지 않는다.** 복습 일정은 오늘 복습에서 푼 결과로만 바뀐다. 재도전 완료도 학습일로는 인정한다(AC-04a).
- AC-09f: 삭제되어 이용할 수 없는 퀴즈는 "이용할 수 없는 퀴즈"로 표시하고 본문과 재도전을 숨긴다.
- AC-09g: 기록이 없으면 "아직 풀이 내역이 없어요"와 홈 링크, 필터 결과가 없으면 전체 보기, 검색 결과가 없으면 검색어와 검색 초기화, 조회 실패에는 재시도를 제공한다. 조회는 연속 학습일·복습 일정을 바꾸지 않는다.

## 6. 품질 기준

- UI는 Tailwind CSS v4와 공통 디자인 토큰을 사용한다. 모바일·데스크톱과 키보드로 핵심 동작을 수행할 수 있어야 한다.
- 1단계는 Jest·React Testing Library·Playwright로 메모·퀴즈 생성·복습 주기·연속 학습일과 더미 사용자 여정을 검증하고 Vercel에 배포한다.
- 2단계는 인증·소유권, MySQL 저장 복원, 복습 일정과 학습일의 중복 집계 방지를 Spring Boot·MySQL 테스트로 검증한다.

## 7. 확정 정책과 미결정 사항

확정(2026-11-08): 위 REQ-01~09, 1단계 기술 범위, 2단계 Spring Boot·MySQL·Google OAuth2·JWT·Spring AI. 모든 퀴즈는 작성자 전용이며 공개·구독·검토·승인 단계를 두지 않는다. 퀴즈 상태는 PENDING(생성·미확인)과 CONFIRMED(확인) 두 가지다.

미결정:

- 2단계 LLM 제공자와 모델
- 시간대를 감지하지 못했을 때 사용할 기본 시간대
- JWT 만료·갱신·폐기 정책, 2단계 배포 환경과 MySQL 호스팅
