# TAG-CARD-UNIFY

## 대상과 확정 범위

- 사용자는 태그를 찾아 공개 퀴즈 목록에 들어가거나 명시적으로 구독/학습한다. 방문자와 데모 learner 상태를 구분한다.
- 사용자 최신 지시: 개발자 탐색과 태그 탐색의 대상 카드끼리 통일한다. 앞서 완료한 퀴즈 목록 4곳은 유지한다. 최초 퀴즈 카드 기준 시안은 사용자 방향 변경으로 폐기했으며 그 시안의 검사/리뷰를 최종 근거로 재사용하지 않는다.
- 개발자 탐색의 `discoveryStyles.card/personLink/subscriptionButton/unsubscribed`를 수정 없이 재사용한다. 48px # 아이콘·이름/구독 상태·구분선 footer·공개 퀴즈 수·독립 구독/학습 버튼을 제공한다. PC3열/태블릿2열/모바일1열로 맞춘다. API와 이벤트 처리, 데모 안내, URL 조건, 권한 및 학습 정책은 변경하지 않는다.
- 기준 d821fdd + 현재 `src/components/discovery/search-results.tsx`, `styles.ts` diff. 별도 UI 설계 에이전트가 개발자 카드 기준의 최소 변경안을 검토했다.

## 화면 증거

- 격리 복제 `/tmp/bugri-tag-card-review`, `http://127.0.0.1:3220`. 원본과 같은 수정 소스, webpack dev. 기존 개발 서버는 재사용/중단하지 않았다.
- `/discover/tags?user=learner`, `/discover/tags`, 비교 `/discover/developers?user=learner`.
- 최종 캡처 `/tmp/bugri-tag-cards/final/{member,guest,developers}-{1280,390,320}.png`, viewport 각 너비×900, fullPage 캡처. 첫 화면 아래 목록은 스크롤 영역이다. 상위 폴더의 캡처는 폐기된 이전 시안이다.
- 구현자 직접 Playwright: 회원/방문자 각 폭의 overflow 검사 및 방문자 제목 focus→Enter로 `/tags/web/quizzes?discoveryPage=1` 이동. 구독/해제·학습·검색 조건 및 포커스는 관련 E2E로 검증한다.

## 관점별 평가 및 문제 처리

최초 독립 리뷰는 새 컨텍스트의 UX/UI 에이전트가 각각 수행했다. 이전 시안 R0 필수 문제는 없었지만 사용자 지시를 반영한 C1을 같은 리뷰어들이 R1에서 다시 확인했다. 수정 1회이며 리뷰어 발견 결함이 아닌 사용자 피드백에 따른 수정이다.

| 관점 | R1 관찰 근거와 판정 |
| --- | --- |
| UX 목적/대상 | 태그 탐색 제목·검색·#태그명으로 구독 대상 탐색임을 식별. 문제 없음. |
| UX 위계·첫 화면 | 이름이 가장 강조되고 메타는 구분선 아래 표시. 320px 첫 화면에 첫 두 카드가 보임. |
| UX 주요 행동 | 리뷰어가 320px에서 #JavaScript focus→Enter→공개목록 제목을 직접 확인. 중간 단계 없음. |
| UX 밀도 | 없는 개발자 ID/관심 태그를 위한 빈 공간을 추가하지 않음. 이름·퀴즈 수·행동 구분. |
| UX 상태 | 공개 퀴즈 없음·구독 중·학습 버튼을 문자로 구분. 변경 직후 피드백·로딩·오류는 리뷰어 직접 미확인. |
| UX 모바일·키보드 | 320px footer는 필요할 때 줄바꿈하고 학습/더보기 유지. 제목 Enter 이동 및 최소44px 행동 영역 확인. |
| UX 방문자·회원 | 방문자 구독하기와 회원 Web의 구독 중/학습하기 구분. 데모 안내 직접 조작은 관련 E2E와 구분. 태그 소유자 구분은 해당 없음. |
| UI 일관성 | UI 리뷰어가 최신 비교 캡처 9장을 직접 확인. 개발자·태그 카드의 모서리·선·그림자·48px 아이콘·제목·구분선·pill 버튼 일치. |
| UI 위계·색상 | 굵은 태그명, 보조 구독 상태, footer 수량 강조. 연보라 아이콘은 개발자 아바타와 크기/모서리가 대응됨. |
| UI 여백·모바일 | PC1280 두 화면 3열 폭 일치. 390/320 한 열 및 잘림 없음. 태그 카드의 낮은 높이는 표시 정보 차이임. |

필수 문제 0개, C2 없음. UI 리뷰는 대비 수치·긴 사용자 생성 태그·hover/메뉴 열린 상태·태블릿2열 캡처를 직접 확인하지 않았다. 최종 코드의 태블릿768 배치/키보드/구독 흐름은 관련 E2E 범위와 구분한다. 공통 스타일 참조·이벤트/URL 보존에 대한 구현자 외 정적 검토도 완료했다.

## 검증

- Node v22.23.3. 기존 공통 스타일은 수정하지 않고 탐색 화면에서 재사용하는 UI 변경이므로 변경 정적 검사·타입·관련 테스트와 화면 검증을 선택했다. 최종 전체 verify는 이번 로컬 완료 범위에서 실행하지 않는다.
- 최종 코드: 변경 파일 ESLint/Prettier, `npm run typecheck`, `npx jest --runInBand tests/unit/discovery.test.tsx` 1 suite/9개 통과. `git diff --check` 통과.
- `npm run test:e2e -- tests/e2e/tag-discovery.spec.ts tests/e2e/tag-catalog.spec.ts`: 첫 실행 7개 통과/1개 실패. 잘못된 페이지 복구 후 5초 내 목록 개수 조회가 0이었지만 실패 시점 스냅샷에는 4개 목록이 복구되어 있었다. 변경하지 않은 복구 코드 및 기록을 확인해 일시 지연 가능성으로 판단했다. 코드/기대값/타임아웃을 수정하지 않고 같은 8개를 `--workers=1`로 재실행하여 모두 통과(52.5초, production build 포함). 재실행 1회. 첫 로그 `/tmp/bugri-tag-cards/e2e-final.log`, 성공 로그 `/tmp/bugri-tag-cards/e2e-retry.log`.
- 검증 후 변경은 이 문서와 TASKS 기록뿐이다. 검증용3220 서버만 종료했다. 최초시안의 검사 결과는 최종 통과 수에 포함하지 않는다.
- 최초 시안 화면 확인의 dev 초기 컴파일이 30초를 초과해 캡처를 재시도했다. 제품 코드/테스트 실패는 아니며 테스트를 약화하지 않았다.
