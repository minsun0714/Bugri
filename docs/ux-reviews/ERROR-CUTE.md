# ERROR-CUTE 전체 오류 화면 리뷰

## 대상과 증거

- 사용자 요청: 전체404/렌더/global오류만 깜찍한 버그리장면으로 변경한다. 부분Query오류·기존복구동작은 유지한다. 404지도/전체오류컴퓨터·공구, 기존Bugri/Button/토큰 재사용.
- 코드: ErrorPage·ErrorIllustration, Bugri 새mood2개. 기본표정은 유지한다. `/tmp/bugri-error-cute-captures/{404,error}-{1280,375,320}.png`, viewport높이800. 실제 URL404·클라이언트 렌더오류 캡처이며 global실제장애는 아님.
- 독립 UX가 6장 최신캡처를 직접 열고 E2E·코드를 검토했다. 구현자 productionE2E7개에서 사용자유지 홈복귀·Enter재시도·320px넘침없음·기존부분오류복구 확인(`/tmp/bugri-error-cute-expression-e2e.log`). 직접브라우저조작/스크린리더/global장애복구는 미확인.

## 구현자 사전검사·사용자 피드백

- 초기320px에서 grid item의 min-content 너비로 카드가 넘쳤다. `min-w-0`로 수정하고 같은E2E 통과. 독립리뷰 발견건수에 포함하지 않는다.
- 사용자 ‘404인데 웃고 있네’ 피드백으로 confused(o입)·concerned(일자입)를 추가했다. 오류화면에만 적용, 기존neutral등 유지. 사용자발견이며 sub-agent발견으로 기록하지 않는다.
