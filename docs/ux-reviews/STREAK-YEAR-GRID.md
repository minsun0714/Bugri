# STREAK-YEAR-GRID — 연간 2열 학습량

## 범위와 증거

- 사용자 가설: 홈에서 학습량을 살핀 후 퀴즈를 이어가는 로그인 학습자.
- 사용자 확정: 월·년 두 보기, 기본 이번 달, 두 보기 동일 높이. 기간 기능 C3/R3 이후 추가로 연간 2열 표시를 요청했다.
- 변경: 연간을 2열 × 6행, 월·가로 막대·개수로 표시한다. 1월/2월, 3월/4월 순서이며 월 선택과 미래 비활성 동작은 유지한다. 연간 전체 최댓값을 공유하며 일별 개수 합계 정책은 변경하지 않는다.
- 별도 UI 설계: 높이 44px와 행 간격 4px로 총 284px, 고정 차트 292/340px 안에 배치한다. 월과 개수는 줄이지 않고 막대가 남은 공간을 사용한다.
- 새 컨텍스트의 UX·UI 리뷰어에게 production `127.0.0.1:3327`, 로그인·실제 제출 경로와 390/768/1280 화면을 제공했다. 파일 `activity-periods.tsx`, HEAD `db866f3` 이후 미커밋 변경 대상이다. 이전 기간 리뷰와 구분한 새 사용자 요청 범위다.
- 관련 E2E 4개 통과. 실제 버튼 좌표로 2열 배치와 월·년 동일 높이를 검증한다. 독립 R0와 최종 전체 verify를 완료했다. Node v22.23.3에서 lint·TypeScript·Jest 199개·도구 3개·production build·E2E 121개 통과, 로그 `.bugri-hooks/verify-2.log`.

## R0 결과

두 리뷰어가 새 컨텍스트에서 독립 실제 화면을 확인했고, 범위 내 필수 수정 문제를 발견하지 못했다. 수정 0회로 종료한다.

| 역할·관점           | 관찰 근거                                                                                                         |
| ------------------- | ----------------------------------------------------------------------------------------------------------------- |
| UX 목적·우선순위    | 연속 학습, 기간, 완료 합계, 월별 기록 순서로 읽히며 아래 퀴즈가 다음 행동으로 식별된다.                           |
| UX 핵심 행동        | 로그인 → 년 → 1월 → 달력 → 답 제출 → 년 합계 1개, 재풀이 후 1개 유지 직접 확인. 과거·현재 복귀도 확인했다.        |
| UX 밀도·피드백      | 세 화면에서 2열 6행, 0개·1개·미래 — 구분, 추가 설명 없이 반복 정렬된다.                                           |
| UX 접근성·사용자    | Tab 1월→2월, Enter 월 진입과 월 탭 포커스를 확인했다. 본인 상태 직접 확인, 방문자·타인은 이번 변경 대상이 아니다. |
| UI 위계·타이포·정렬 | 10~12월 포함 월·막대·개수 기준선 유지, 숫자가 막대와 분리된다.                                                    |
| UI 밀도·색·모바일   | 390px에서도 충돌·줄바꿈·가로 넘침 없음. 미래는 흐린 표시와 —로 과거 0개와 구분된다.                               |
| UI 비례·일관성      | 월/년 카드 높이는 390px에서 583px, 768px에서 651px, 1280px에서 551px로 동일하다.                                  |

별도 정적 코드 리뷰에서 연간 최댓값에 비례한 가로 막대, 수치 텍스트, 미래 비활성, 월 진입 상태·포커스·고정 높이를 확인했고 범위 내 결함은 발견하지 못했다.

한계: 다수 월의 큰 수치, 화면낭독기, 확대, 로딩·실패 상태 직접 미확인. 대비는 화면 관찰이며 수치 측정은 아니다. 고정 높이에 따른 모바일 퀴즈 스크롤은 확인했으며 확정 제약 안에서 추가 변경하지 않는다.
