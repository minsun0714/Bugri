# PROFILE-SUBSCRIPTION-STATE — 구독 상태 리뷰

## 대상과 증거

- 사용자 목표: 타인 공개 프로필에서 구독 상태 확인 및 명시적인 해제. 사용자 요청은 ‘개발자 구독 해제’ 대신 ‘구독 중’ 표시.
- 기준 a72d943 + 이번 diff. `/users/bugri-author?user=friend`, 격리 E2E 포트 3110, Chromium 1280×900 / 390×900.
- 최신 캡처: `test-results/profile-subscription-state-196e3--explicit-removal-at-1280px-chromium/` 및 `test-results/profile-subscription-state-2a023-d-explicit-removal-at-390px-chromium/`의 subscribed/menu/unsubscribed PNG.
- 구현자 E2E 직접 실행, 독립 UX/UI 리뷰어는 캡처·코드·조작 검사 결과를 간접 확인. 실제 휴대폰·스크린리더·오류 주입은 미실행.

## 사전 논의와 처리

- UX: 문구만 바꾸고 즉시 해제하면 기존 탐색의 관리 메뉴와 달라 혼동할 위험(가설, UX-01). 기존 SubscriptionControl 재사용 제안.
- UI: 상태 문구 통일에 동의. 즉시 해제 버튼에 메뉴 화살표만 추가하는 것은 부적절하나, 실제 메뉴가 연결되면 해당 문제 없음.
- 처리: 로그인 프로필에 공통 컨트롤 적용. 미구독은 `+ 구독하기`, 구독 후 `✓ 구독 중 ▾`, 누르면 명시적 `구독 해제`. 방문자 선택 안내와 본인 편집 분기 유지. 새 설명·공유 스타일 변경 없음.
- 사용자 지적을 리뷰어가 새로 발견한 문제로 기록하지 않는다.

## 검증과 회차

- 단위 4개: 방문자 명시 선택, 구독 상태 전환, 메뉴 열 때 구독 유지, 명시 해제 및 API 상태 확인.
- E2E 2개: PC/모바일에서 구독 → Enter 메뉴 열기 → Escape 닫기 → 클릭 메뉴 열기 → 해제 → 취소 토스트 → 새로고침 후 미구독 유지, 가로 넘침 없음.
- 첫 두 E2E 실행은 Toast의 체크/닫기 문자를 포함한 DOM에 exact 텍스트 locator를 사용해 실패. 스냅샷에는 취소 안내가 존재했다. 상태 역할+문구 locator로 수정하여 통과. 제품 토스트 누락으로 판단한 초기 가설은 철회.
- 구현 중 구독 상태에서만 컨트롤을 사용하는 안을 로그인 전체 상태 사용으로 수정 1회. 독립 구현 후 R0에 따른 추가 UI 수정은 0회.
