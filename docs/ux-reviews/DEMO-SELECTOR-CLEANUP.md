# DEMO-SELECTOR-CLEANUP

## 대상과 증거

- 사용자 요청: 헤더 우측 데모 사용자 선택을 유지하고 중복 사용자 전환 UI를 제거한다. 학습·탐색 방문자와 선택된 더미 사용자가 검토 대상이다.
- 변경: 헤더 하단 배너, 상점 프로필의 전환 항목, 탐색 오류의 별도 전환 버튼·모달 삭제. 헤더 선택은 선택 후에도 유지한다. 구독·풀이 진입 안내, 데모 나가기, 사용자별 저장은 유지한다.
- 워크트리: `데모-삭제`, 이 문서와 함께 커밋하는 diff. 격리 서버 `http://127.0.0.1:3419`.
- 캡처: `.bugri-hooks/previews/demo-cleanup/`. 홈 1280/390/320×900의 `home-*-r1.png`가 최종 C1이다. `home-*.png`는 R0 이전 증거다. `shop-profile.png`는 R0, `corrupt.png`는 C1이다.
- 새 컨텍스트의 독립 UX/UI 리뷰어가 각각 스킬에 따라 확인했다. UI는 캡처, UX는 캡처와 실제 Playwright 조작 및 코드 리뷰를 수행했다.

## 최초 관찰과 흐름

- UX: 홈은 학습 현황·오늘의 퀴즈, 탐색은 검색·구독이 주 목적이며 사용자 선택은 헤더에서 발견된다.
- UI: 배너 제거 후 잔여 영역 없이 콘텐츠가 이어지고 계정 행동의 표면·테두리는 기존 토큰과 일치한다.
- UX 직접 확인: 390px 방문자 개발자 탐색 → 헤더 선택 → 친구 → 동일 경로의 user=friend. 재선택 Enter → Escape → 원버튼 포커스 복귀. 320px 친구 → 프로필 → 데모 나가기 → 방문자 홈.
- 구현자 직접 확인: 320px 학습자 → 친구, 세 화면 너비의 가로 넘침 없음.

오류 복구·구독/풀이·사용자 격리의 독립 UX 직접 재실행은 미확인이다. 구현자 E2E 결과는 TASKS에 별도 기록한다. 최초 오류 캡처 스크립트는 숨겨진 중복 오류 문구를 기다려 시간 초과됐고, 보이는 alert를 선택해 캡처했다. 이는 앱 테스트 실패나 UX 통과 근거로 대체하지 않는다.

## 검증 과정

- Node v22.23.3. 헤더 테스트의 로그인 후 선택 버튼 부재로 TDD 3개 실패를 먼저 확인한 뒤 구현했고 관련 10개가 통과했다.
- 최초 전체 검증은 생성된 `LayoutProps` 부재로 타입 검사에서 중단했다. `npx next typegen` 후 재실행했다.
- 중간 전체 E2E: 160개 통과/7개 실패. 구독 모달, 3D 마우스 이동, 상점·풀이 시간 초과와 상품 선택 버튼 검사 범위 오류가 있었다. 동시 실행된 최종 스타일 단위 검사에서도 상점 1개가 시간 초과했다. 실패를 제외하거나 제한 시간을 늘리지 않았다.
- 상품 선택 부재 검사는 전역 `/선택$/`가 헤더의 새 상시 선택 버튼을 포함한 것이 원인이었다. 공개 프로필 `main`으로 범위를 한정해 본문의 상품 선택 비노출을 유지했다. 독립 UX 리뷰어가 해당 테스트와 ProductLayout을 확인해 검증 목적 유지로 판단했다.
- 최종 코드에서 동시 검사를 마치고 `npm run verify -- -- --workers=2`로 재검증한다. 서버 포트가 빌드 중 점유되면 기존 래퍼가 새 포트를 자동 선택하며 다른 서버를 종료하지 않는다. 최종 결과는 TASKS에 기록한다.

최종 재검증 exit 0: lint·타입·Jest 54 suites/273개·도구 3개·빌드·E2E 167개 전부 통과했다. 로그 `/tmp/demo-final-verify.log`. 마지막 코드 이후 변경은 이 기록과 TASKS뿐이다. 전체 미통과 검사는 없으며 독립 UX 직접 확인 한계는 위에 유지한다.
