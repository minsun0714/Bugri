# DEVELOPER-TAG-PANEL — 다중 필터와 구독 설정

## 대상과 증거

- 목적: 개발자의 공개 퀴즈를 여러 태그로 찾고, 별도의 구독 설정에서 전체 또는 특정 태그를 구독한다. 사용자 요청으로 바깥 필터는 펼쳐 두며 PC Popover/모바일 하단 다이얼로그를 직접 공통 컴포넌트로 구현했다. OR 다중 선택, 기존 PERSON/PERSON_HASHTAG 계약 유지.
- 구현: `src/components/ui/responsive-popover.tsx`, `filter-chips.tsx`, `src/components/developer/`, 다중 태그 API/서비스 및 관련 테스트. `a0ba753` 이후 이 작업 diff를 검토했다.
- 별도의 새 컨텍스트 UX/UI 리뷰어가 서버 `http://127.0.0.1:3220/developers/bugri-author/quizzes?user=friend`에서 직접 조작했다. PC1280/mobile390·320, 높이900 및 500. 초기 캡처 `/tmp/bugri-tag-panel/{filters,panel}-{width}.png`, 최신 짧은 화면 `/tmp/bugri-tag-panel/r2-short-{width}.png`. 임시 캡처는 커밋하지 않는다.

## 최초 관찰과 흐름

- UX: 개발자 정보 → 태그 필터 → 공개 퀴즈의 목적이 읽힌다. 두 태그 선택으로 OR 결과 확인, 구독 설정 → 개별 구독 → 검색 → 닫기 → 다시 열기 → 해제를 직접 수행했다. 검색과 외부 필터 URL은 독립적이었다.
- UI: 기존 보라/연두 토큰과 카드가 이어지고, 반복 구독 버튼이 외부 필터에서 없어져 위계가 분명하다. 단, 높이500에서 패널 하단 페이지 이동이 잘렸다.

| 관점 | 판단·관찰 |
| --- | --- |
| 목적/대상 | 개발자 이름·공개 ID와 퀴즈 제목, 패널 전체/태그별 구독으로 대상 식별 가능 |

| 방문자·본인·타인 | 타인 로그인 및 게스트 구독 시 데모 사용자 선택 직접 확인. 본인 상태·데모 선택 완료 복귀는 리뷰 미확인 |

## 회차와 종료

- R0: UX 직접 핵심 흐름 문제 없음, UI 짧은 화면 UI-01 발견.
- C1/R1: 내용 축소 보완 및 PC 외부 초점/모바일 스크롤 보완. 핵심 흐름 회귀 없음. UI-01은 아직 미해결. 선택/구독 완료/빈 검색 상태 추가 확인.
- C2/R2: dialog의 실제 display가 block인 원인을 수정. 두 리뷰어 새 컨텍스트에서 짧은 높이 UI-01 해결 및 검색/구독/Escape 회귀 없음 확인. 총 수정 2회, 필수 미해결 문제 없음.
- 한계: 실제 대량 태그 페이지 이동·오류/재시도·본인 화면·스크린리더 음성은 독립 화면 리뷰에서 확인하지 않았다. 페이지 이동/검색시 첫페이지 복원은 6태그 응답 fixture 단위 테스트로 별도 확인하며 화면 리뷰를 대신한다고 주장하지 않는다.

## 코드 리뷰와 검증 한계

독립 코드 리뷰에서 단일 hashtagId 호환, 다중 OR의 페이지 이전 적용, 공개 응답 제한, HTTP 반복 쿼리, 구독 캐시, 이벤트/overflow/초점 cleanup을 확인하고 확정 회귀를 발견하지 못했다. breakpoint 전환은 코드로만 검토했다. 최종 전체 검증은 신규 HTTP 테스트의 lint 2건에서 중단되었으므로 UX/UI 리뷰 완료와 기능 검증 완료를 구분한다. 상세 실패와 재실행 한도는 TASKS의 DEVELOPER-TAG-PANEL에 기록했다.

사용자의 재개 지시 후 중첩 구조 분해/빈 줄 수정 및 전체 검증 재실행 성공: Node22.23.3, lint·타입·Jest281·도구3·build·E2E175. 기존 중단 기록은 보존하며 최종 기능 검증은 완료했다.
