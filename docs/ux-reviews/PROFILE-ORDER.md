# PROFILE-ORDER 공개 프로필 순서 편집 리뷰

## 대상과 증거

- 목표: 본인 공개 프로필의 데스크·최신 공개 퀴즈·학습 활동 순서를 바꾸고 저장하여 방문자에게 표시한다. 정보·소개는 상단 고정이며 섹션 숨김/개별 카드 정렬은 제외한다.
- 현재 워크트리 미커밋 구현. `/users/bugri-author?user=author`, 방문자는 user 생략, 타인은 friend. 격리된 production 서버 `http://127.0.0.1:3125`.
- R0: Playwright `profile-order.spec.ts`의 1280×900/390×900 전체 페이지 편집·실패·방문자 캡처. UX 리뷰어는 별도로 브라우저를 조작했고 UI 리뷰어는 6개 실제 캡처를 확인한 후 코드를 검토했다.
- 구현자 관련 E2E 4개(신규2+기존 profile-split2) 통과. 테스트 성공은 독립 UX 판단을 대체하지 않는다.

## 최초 관찰과 흐름

- UX: 공개 ID로 대상이 드러나고 본인에게 ‘순서 편집’ 진입이 보인다. 편집 → 이동 버튼 → 방향키 → 저장 → 방문자/타인 조회를 직접 수행했다. 저장한 퀴즈 우선 순서를 방문자에서도 확인했다.
- UI: 저장은 보라색 채움, 취소는 테두리로 구별된다. 콘텐츠보다 작은 조작 제목·핸들·화살표가 편집 대상에 대응한다. 방문자 화면에서는 조작과 편집 테두리가 사라진다.

### UI R1

최신 캡처와 390×900 실제 브라우저에서 편집 진입 → Tab 포커스 → 데스크 드래그/연속 스크롤 → 저장을 직접 확인했다. 포커스 링은 겹치지 않고 드래그 대상의 보라색 테두리/옅은 배경이 구별된다. 저장/취소 바는 스크롤 중 상단에 남으며 저장 후 도구 제거·순서 반영·성공 토스트를 확인했다. 신규 시각 회귀 및 필수 미해결 문제 없음. 증거 `/tmp/ui-r1-focus.png`, `/tmp/ui-r1-drag.png`, `/tmp/ui-r1-saved.png`. 빠른 저장 중 상태·소개 내용 채운 화면·타인 시각 상태는 UI 리뷰어 미확인.

### UX R1 및 종료

UX 리뷰어가 최신 390×900 브라우저에서 아래 가장자리 1.1초 유지 시 816px 연속 스크롤과 첫→마지막 이동, 위 가장자리에서 마지막→첫 이동을 직접 확인했다. Escape 후 스크롤 887→887, 드롭 후 79→79로 중단됐고 Escape는 이동을 적용하지 않았다. 취소 원복, 저장 실패 초안 보존 후 저장 기능 복원·재시도·새로고침 유지, 실제 자기소개 입력 후 상단 고정까지 확인했다. UX-01 해결, 새로운 필수 문제 없음. 코드상 훅 분리와 RAF cleanup 확인. R0의 나머지 판단 유지.

수정 C1/R1 한 회 후 종료한다. UI-01은 선택 개선으로 보류한다. 실기기 터치와 스크린리더, 빠른 저장 중 시각 상태는 미확인이다. 전체 회귀 검증 결과는 TASKS에 별도로 기록한다.

### 후속 테스트 갱신 리뷰

사용자 후속 승인으로 `developer.test.tsx`의 전체 보기 링크 조회를 비동기 대기로 바꾸고 `public-profile.test.tsx`의 DeveloperScreen Mock에 activity 렌더링을 반영했다. 기존 UX 리뷰어가 두 diff를 독립 정적 검토하여 정확한 링크 href·구독·기본 배치·개인 관리 정보 비노출 assertion이 보존됨을 확인했다. 새 문제 없음. Mock 기반 배치 검증은 실제 정렬 구현을 대신하지 않으며 별도 profile-order 테스트와 R1 조작 근거를 유지한다. 앱 코드는 R1 이후 변경하지 않았다.
