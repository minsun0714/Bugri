# P08-COIN-FILTER UX 리뷰

## 대상과 증거

- 검토용 사용자 가설: 지급 또는 사용 내역을 따로 찾으려는 본인 사용자. 전체/지급/사용, 필터 변경 첫 페이지와 잔액 유지가 확정 요구다. 다른 마이페이지 placeholder·API·보상 정책은 제외한다.
- HEAD9dcfbc7 + coin-history.tsx diff. 새 컨텍스트 독립 리뷰어가 먼저 화면을 보고 코드를 확인했다. 전용3150 서버 `/my?user=learner`, 격리 Chromium PC1280×900·모바일390×844 직접 조작.
- 캡처 `/tmp/bugri-coin-filter.png`(모바일 사용), `/tmp/bugri-coin-initial.png`(PC 전체).

## 최초 관찰과 흐름

개인 마이페이지 잔액·거래 내역으로 이해했고 내역 바로 위 세 탭을 탐색 행동으로 식별했다. 초기 사용 빈 상태/잔액100→상점 구매→전체2페이지→지급1/3→사용-30 한 건/잔액70→전체1/3을 직접 수행했다. 방향키의 선택·포커스 이동과 모바일 가로 넘침 없음도 확인했다.

## 관점별 평가

| 관점                  | 판단                | 근거                                                              |
| --------------------- | ------------------- | ----------------------------------------------------------------- |
| 목적/대상 식별        | 문제 없음           | 내 잔액·지급/사용 명칭과 부호로 목적 구분                         |
| 정보 우선순위·첫 화면 | 영역 내부 문제 없음 | 잔액→필터→결과. 앞선 placeholder 스크롤은 기존 배치이며 제외 범위 |
| 핵심 행동·이동 단계   | 문제 없음           | 한 번 선택으로 필터, 전체로 복귀, 첫 페이지 초기화                |

## 문제 목록과 처리

필수 수정 문제0개. 기존 마이페이지 placeholder 배치는 제외 범위로 유지한다. 사용자 피드백의 필터 누락은 요청된 구현 배경이며 리뷰어 발견으로 계산하지 않는다.
