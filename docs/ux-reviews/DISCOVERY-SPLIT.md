# DISCOVERY-SPLIT 독립 UX·UI 리뷰

## 대상과 증거

- feat/split-discovery-pages의 탐색 페이지·메뉴 분리 미커밋 변경. 사용자 목표는 출제자 또는 기술 태그 검색 후 구독/프로필 이동이다.
- 확정: 별도 페이지·메뉴, 내부 탭 제거, 기존 검색·구독 계약 유지. 기존 내 구독 placeholder는 제외 범위다.
- 구현 전 별도 UI 설계 에이전트가 기존 토큰·카드 재사용, 대상별 제목·검색 레이블, 640px 헤더 확인을 제안했다.
- 독립 UX/UI 리뷰어 각각 새 컨텍스트에서 실제 Chromium과 http://127.0.0.1:3198을 확인했다. 1280/640/390×900 화면.
- UX: `/tmp/ux-developers-{1280,640,390}.png`(데모 로그인), `/tmp/ux-tags-{1280,640,390}.png`(방문자).
- UI: `/tmp/ui-review-{developers,tags}-{1280,640,390}.png` 방문자 화면 직접 캡처, 로그인 개발자 화면과 모바일 열린 메뉴 직접 확인. 로그인 태그는 구현자 E2E 캡처 `/tmp/bugri-discovery-results/`로 간접 확인.

## 관점별 근거

| 역할·관점         | 관찰                                                                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| UX 목적·정보 위계 | 제목·브레드크럼·검색 레이블 일치. 방문자는 제목→검색→결과 순으로 첫 화면에서 행동 발견 가능.                                              |
| UX 이동           | 개발자 ‘타입’ 검색, 결과 이름 링크 이동, 뒤로가기의 검색어·URL 보존 직접 확인. 최종 공개 프로필 리다이렉트는 직접 미확인.                 |
| UX 중복·밀도      | 내부 탭 제거로 대상 중복 선택 없음. 기존 내 구독 빈 패널은 제외 범위.                                                                     |
| UX 상태           | 결과 수·페이지 표시 직접 확인. 구독 완료·실패·빈 결과의 독립 직접 조작은 미완료.                                                          |
| UX 키보드·모바일  | Enter 메뉴 열기, Tab 개발자 항목 초점, Escape 닫기·트리거 초점 복귀 확인. 추가 태그 링크 조작은 locator 대기와 빌드 재생성이 겹쳐 미확인. |
| UX 사용자 상태    | 방문자·데모 로그인 확인. 본인 구독 정책과 타인 상세 동작은 변경 범위 밖.                                                                  |
| UI 위계·타이포    | 제목·카드명·보조 ID/결과 수 차이 명확. 390px 이름·버튼 잘림 없음.                                                                         |
| UI 간격·비례·정렬 | 검색 입력/버튼 정렬, 일정한 카드 여백, 1280px 2열과 640/390px 1열 확인.                                                                   |
| UI 색상·일관성    | 활성 메뉴와 주요 버튼/구독 버튼 역할 구분. 두 페이지 동일한 틀. 정량 대비 측정 미실행.                                                    |
| UI 헤더·모바일    | 640px 메뉴·로고·프로필 충돌 없음. 390px 열린 메뉴가 화면 안에 표시됨.                                                                     |

## 문제와 회차

- R0: 두 역할 모두 신규 필수 문제 없음, 수정 0회. 선택적 취향을 결함으로 등록하지 않았다.
- 기존 내 구독 빈 패널이 첫 화면 공간을 차지하는 점은 기존 범위 제외 사항으로 유지했다.
- UI 키보드 포커스·구독 후 피드백·긴 이름·빈 결과·오류는 독립 직접 미확인. UX 및 구현자 테스트 근거와 혼동하지 않는다.
- 분리 E2E 2개에서 레거시 URL 검색어/페이지/사용자 보존, 세 너비 메뉴 이동·뒤로가기 확인. 구독/검색 복원은 기존 단위·E2E로 보완한다.
- 실제 화면에서 확인한 이번 변경의 필수 결함이 없어 R0 종료. 독립 리뷰는 전체 기능 테스트를 대체하지 않는다.
