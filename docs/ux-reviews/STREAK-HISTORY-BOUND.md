# STREAK-HISTORY-BOUND — 기간 선택과 첫 기록 경계

> 사용자 스크린샷으로 R0에서 놓친 단일 연도 화면의 과도한 빈 공간을 확인했다. R0의 필수 문제 없음 및 종료 판단은 철회하고 아래 C1/R1을 최종 근거로 사용한다.

## 범위와 증거

- 대상 사용자 가설: 홈에서 본인 학습 기록을 탐색하고 퀴즈를 이어가는 로그인 더미 사용자.
- 승인된 요구: 첫 기록의 연도·월까지만 탐색하며 기록이 없으면 올해·이번 달만 허용한다. 첫 기록 이후의 빈 기간은 볼 수 있다. 연간 월 진입에도 같은 경계를 적용한다.
- 작업 중 추가 승인: 월·년 탭 대신 날짜 제목 → 2열 월 목록 → 연도 제목 → 연도 목록으로 이동한다. 연도 선택은 해당 연도 월 목록, 월 선택은 달력으로 돌아간다. 모든 상태에서 카드 높이를 유지하고 선택 후 제목 초점을 복구한다. 긴 연도 목록은 내부 스크롤을 사용한다.
- 구현 전 UI 설계 위임: 기존 이전 화살표는 숨기지 않고 비활성화한다. 날짜 제목은 ▾가 있는 공통 버튼으로, 연도 선택은 선택 표시와 제목 초점 복귀를 제공한다. 탭의 공간은 제거한다.
- 코드: `f220dd7` 이후 `activity-periods.tsx`, `periods.ts` 및 테스트 변경. API·저장·일별 집계 규칙 변경 없음. 완료일과 양수 일별 개수를 합쳐 첫 기록을 찾고 미래/0개 기록은 제외한다.
- 실제 화면 리뷰: 새 컨텍스트 UX·UI 리뷰어, production `127.0.0.1:3327`, 390/768/1280 화면. 로그인·답 제출과 과거 기록 fixture 경로를 제공했다. 코드보다 화면을 먼저 평가하도록 요청했다.

## 구현 검증

- Node v22.23.3. 하한 및 제목 선택 테스트의 의도한 미구현 실패 후 구현했다.
- 관련 단위 14개와 E2E 5개 통과. 날짜/월/연도 전환, 처음 기록/빈 사용자 경계, 사용자 변경, 키보드 초점·Escape, 4·5·6주 및 세 보기의 동일 높이를 검증한다.
- 첫 통합 E2E 높이 테스트는 과거 월에서 연간 보기로 열어도 현재 연도로 초기화된다는 이전 탭 동작을 가정해 실패했다. 승인된 제목 흐름은 조회 연도를 보존하므로 테스트가 이번 달 복귀를 명시한 뒤 연간 보기를 열도록 수정했다. 숫자·높이 기대값은 유지했다.
- 마지막 전체 verify와 독립 리뷰 결과는 아래 및 TASKS에 기록한다.

- 실제 Google 데모 로그인 후 390/768/1280에서 달력 → 월 목록 → 연도 목록을 확인했다. 보라색 날짜 제목과 ▾가 선택 진입점으로 식별된다.
- 요약 제목·날짜 선택·완료 수·달력의 위계가 구분되며, 월 이름·막대·개수 정렬은 모바일에서도 겹치지 않는다.
- 빈 기록은 현재 월만 활성, 과거·미래 월 및 화살표는 비활성 스타일로 구분된다. 세 상태의 카드 하단과 다음 퀴즈 위치가 유지된다.
- 단일 연도 항목 주변 여백은 고정 높이 요구에 따른 것으로 추가 변경하지 않는다. 필수 문제 없음, 수정 0회.
- UI 리뷰어의 과거 fixture·답 제출·복귀 완주·키보드 초점은 직접 미확인이다. 해당 흐름의 UX 직접 리뷰 및 E2E와 구분한다.

## 사용자 지적과 C1

- 사용자 스크린샷: 단일 2026년 버튼을 고정 영역 중앙에 두어 기존 월별 기록을 지우고 대부분을 빈 공간으로 만들었다. 제목과 버튼의 연도가 반복됐다. 이는 사용자가 발견한 문제이며 sub-agent 발견으로 바꾸지 않는다.
- 메인과 UI 리뷰어는 고정 높이 요구를 이유로 여백을 정당화한 R0 판단을 철회했다. 고정 높이는 내용을 비워야 한다는 뜻이 아니다.
- C1: 연도 선택을 제목 아래 폭 176px의 공통 Dropdown compact variant로 바꾼다. 월별 2열 막대와 합계를 그대로 유지하고 메뉴만 겹쳐 연다. 연도 한 개면 한 항목 높이만 차지한다. 기본 Dropdown 스타일은 변경하지 않는다.
- 공통 Dropdown의 외부 클릭·Escape·Tab 닫기와 선택 후 초점 동작을 재사용한다. 부모 Escape가 드롭다운의 닫기를 다시 달력 복귀로 처리하지 않도록 defaultPrevented를 존중한다.
- 단일 연도 상태에서 메뉴 높이 100px 미만·월 목록과 합계 유지·카드 높이 동일함을 세 viewport로 검증하는 E2E를 추가했다. C1 이전 전체 verify 통과는 C1 이후 결과로 대체하지 않는다.

## C1/R1 재검증

- 관련 단위 15개와 E2E 6개 통과. 첫 C1 높이 검증은 제목 버튼과 Dropdown의 1.328px 차이로 실패했다. 월 제목에도 44px 높이와 세로 패딩 0을 명시해 동일 높이를 맞췄으며 기대값을 완화하지 않고 재실행했다.
- UI R1: 390/768/1280에서 단일 연도 메뉴가 제목 아래 작게 열리고 월 목록이 유지됨을 직접 확인했다. 기본 제목 44px, 카드 하단·퀴즈 위치 유지, 메뉴가 카드나 화면 밖으로 잘리지 않는다. 모바일에서는 메뉴가 합계 일부를 일시적으로 덮는 일반적인 팝오버 중첩이 남지만 본문을 빈 화면으로 대체하지 않는다.
- UX R1: 세 viewport에서 메뉴 열기 전후 월 12개 유지 및 카드 높이 526/594/494px 동일. Escape 후 월 목록 유지, Enter 재열기, ArrowDown+Enter 선택, 2024년 → 3월 달력, 바깥 클릭 닫기를 직접 확인했다.
- 사용자 발견 문제를 C1에서 수정하고 동일 리뷰어 R1로 재검증했다. R0 종료 판단은 폐기한다. 최종 직접 확인 범위에서 해당 공백 문제는 해결됐고 추가 필수 문제는 발견하지 않았다.
- 최신 캡처 `/tmp/ui-period-r1-{390,768,1280}-{calendar,months,years}.png`, `.bugri-hooks/previews/streak-history/`. 실제 스크린리더 음성 및 수십 년 메뉴는 미확인이다.

최종 C1 코드 이후 Node v22.23.3 전체 verify 통과: lint·TypeScript·Jest 204개·도구 3개·production build·E2E 123개. `.bugri-hooks/verify-1.log`, diff check 통과. 이전 R0 코드의 검증 결과를 최종 근거로 재사용하지 않았다.
