# HOME-QUIZ-03 연속 학습과 퀴즈 스타일 통일

## 범위와 설계

사용자 지시: “pull 받은 거 봤지? 같은 스타일로 UI 분위기 좀 바꿔봐”. `93cb262`로 origin/dev 병합을 완료한 뒤 오늘의 퀴즈에 연속 학습의 표현을 적용한다. 헤더 콘텐츠 너비·B 단일 열·방문자/회원 풀이 동작은 유지한다. 연속 학습 내부와 공통 UI 전체는 변경하지 않는다.

UI 디자이너가 실제 dev 화면을 기준으로 24px 모서리, 흰 표면, 얇은 border-line, 모바일16px/PC24px 패딩, 작은 보조 라벨, 평평한 버튼을 제안했다. UX 디자이너는 문제→답안→제출, 결과→답 비교→해설 순서를 유지하고 강조를 선택 답안/주 행동에 집중하도록 제안했다. 새 문구나 장식은 추가하지 않는다.

- `solving/styles.ts`: 카드 모서리·패딩·간격, 흰 선택지와 연보라 선택 상태, 답안 구분선, 퀴즈 카드 내부 버튼의 그림자/이동 효과 제거. 공통 버튼과 연속 학습에 영향을 주지 않는다.
- `solve-screen.tsx`: 제목24px과 간결한 자간.
- `quiz-panel.tsx`: 주제는 작은 무채움 라벨, 모바일 질문20px, 결과 상태16px와 연한 답 비교 패널. 정오답 의미 색·문구·아이콘 보존.

스타일 전용 변경이라 스타일 문자열을 복제하는 새 테스트는 만들지 않는다. 관련 단위/홈·풀이·연속학습 E2E 및 실제 화면 독립 UX/UI 리뷰로 검증한다.

## C2 사용자 후속 요청: 채점 결과 버그리

사용자가 채점 결과에도 버그리가 함께하도록 요청했다. 기존 Bugri 컴포넌트를 결과 문구 왼쪽60px로 배치하고, 정답은 complete·오답은 encouraging·판정 불명은 neutral로 표시한다. 날짜는 결과 문구 아래, 정오답 문구·색·아이콘은 유지한다. 새 설명 문구나 애니메이션은 추가하지 않았다. 이미지의 감정 label은 접근 가능한 의미로 유지했다. 연속 학습 내부는 수정하지 않았다.

정오답별 반응 컴포넌트 테스트2개를 먼저 추가해 미구현 실패를 확인한 뒤 구현했다. C1 전체 verify는 후속 코드 변경 때문에 해당 프로세스만 중단했으며 완료 검증으로 쓰지 않는다. C2에서 전체 검증을 다시 실행한다.

## 사용자 피드백에 따른 전신·응원 자세

- C2 동일60px 얼굴은 사용자가 달력 옆 얼굴과 중복되어 불편하다고 지적했다. C3에서 결과 전용 `ResultBugri`로 전신 작업복·손·발을 추가했다. PC88×104/모바일72×88이며 달력의 작은 얼굴과 크기·실루엣을 구분한다. 정답은 별 없이 양팔을 든 축하 자세다. UI 리뷰에서 손이 귀처럼 보인다는 지적을 받아 팔을 얼굴 바깥/위로 옮겼고1440/375에서 재확인했다.
- 사용자가 오답의 들어 올린 팔을 공격적인 모습으로 지적했다. 사용자 직접 지시에 따른 추가 수정으로 올라간 팔과 둥근 주먹을 제거하고 두 손을 가슴 앞에 모아 응원하는 자세로 바꿨다. 이전 리뷰어의 적절하다는 평가보다 사용자 피드백을 우선했다. 자율 반복 회차를 늘린 것이 아니라 후속 승인 범위다.
- 최종 UI: 실제375 오답에서 두 손을 모은 차분한 실루엣, 상태/날짜와 겹침 없음 확인. 손 세부 모양보다 응원하는 자세로 전달된다는 한계 기록. UX: 실제390 오답에서 결과 포커스→Tab 다시 풀기→Tab 다음 문제→Enter 이동 및 넘침 없음 확인. 메인도 최종 카드 캡처를 직접 보았다. 최종 변경은 오답 팔 모양뿐이며 정답은 직전 PC/mobile 검토를 유지한다.
- C2 E2E에서 이전 ‘버그리 없음’ 기대가 사용자 새 요구와 충돌해7실패/7통과 후 중단(9미실행)했다. 정답 helper를 축하 이미지 표시로 바꿨고 오답 케이스까지 같은 기대를 적용한 실수를 다음 실행22통과/1실패에서 확인했다. 오답은 응원 이미지 표시로 수정한 후 관련23개 통과. 결과/해설/기록/이동 assertions는 유지했다. 정오답 반응 단위2개 포함 관련8개 통과.

## 최종 오답 자세 검증

최종 오답 팔 수정 후 관련 단위8개 통과. 개발 서버 관련 E2E는22통과/1실패였으며 초기 모바일 학습 태그 클릭 직후 listbox가 없다는 실패였다. 해당 테스트 단독 재실행에서도 동일 실패를 확인했다. 오답 결과 렌더 전 발생하며 태그/Query/Dropdown 구현은 이번 스타일 변경에서 수정하지 않았다. 환경 원인으로 단정하지 않고 기존 초기 진입 타이밍의 회귀 가능성을 남긴다. 기대/timeout을 약화하거나 관련 없는 앱 코드를 바꾸지 않았다. 최종 production 전체 verify를 별도로 실행한다.

첫 최종 production verify는 TypeScript에서 ResultBugri의 correct prop이 완료 기록의 null 판정을 받지 못해 중단됐다. 기존 verdict 계약대로 null을 허용하도록 타입만 보완했으며 표현/동작은 그대로다. `npx tsc --noEmit` 통과 후 최종 전체 검증을 다시 실행했다.
