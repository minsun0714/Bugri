# TAG-QUIZ-CATALOG 태그별 공개 퀴즈 목록

## 대상과 범위

- 사용자 요청: 태그 탐색의 태그명을 클릭해 해당 태그의 공개 퀴즈 목록을 열고 기존 풀이로 연결한다. 후속 요청으로 헤더 오른쪽의 구독 배지·학습·메뉴 배치를 정돈한다.
- 시작 커밋 131adda 위의 변경. `/tags/[hashtagId]/quizzes`, 태그 목록 API/서비스/Query 훅, 탐색 링크와 검색 상태 보존, 공통 메뉴의 선택적 outlined 표시, 내비게이션 경로만 수정한다. 홈·개발자 목록 내부와 개인 풀이 규칙은 유지한다.
- 목적: 관심 태그의 공개 퀴즈를 둘러보고 제목으로 하나를 풀거나 명시 구독 후 연속 학습한다. 방문자도 목록 조회 가능하며 구독·개별 풀이 선택은 데모 사용자 선택으로 연결한다. 선택 직후 구독/풀이를 자동 실행하지 않는다.
- 기존 보라·라임·둥근 카드와 TagExplorer를 재사용한다. API 목록에는 제목·작성자만 제공하며 비공개·검토 중·삭제·비활성 퀴즈와 정답·해설·원문은 제외한다.

## 설계 및 직접 화면 확인

- 별도 UI 설계 agent가 기존 탐색/개발자 목록을 읽고 제목·퀴즈수·행동 헤더와 단일 열 제목/작성자 목록을 제안했다. 최초 설계는 코드 기반 판단이며 실제 시각 통과 근거와 구분한다.
- 새 컨텍스트 UX/UI 리뷰어가 각각 localhost3002를 Playwright로 직접 조작했다. Node v22.23.3. PC1440, 모바일375/320.
- UX: `/tmp/tag-ux-desktop.png`, `/tmp/tag-ux-mobile.png`, `/tmp/tag-ux-subscribed375.png`, `/tmp/tag-ux-empty.png`, `/tmp/tag-ux-missing.png`, `/tmp/tag-ux-range.png`.

## 최초 관찰과 주요 흐름

- UX는 #태그·공개수·목록으로 현재 범위와 다음 행동이 구분된다고 관찰했다. 검색된 #Web → 목록 → 제목 → 개별 풀이, 구독 → 학습 → 홈의 선택 태그 도달, 해제 → 구독 버튼 초점 복구를 직접 추적했다.
- 방문자 제목 클릭은 데모 선택을 열며 선택 후 같은 목록에 남는다. 다시 제목을 눌러 개별 풀이로 이동한다. 친구 본인 작성 퀴즈와 다른 작성자의 퀴즈가 함께 표시된다.
- 목록 돌아가기는 query/discoveryPage를 원래 탐색 query/page로 복원한다. 브라우저 뒤로가기도 풀이에서 목록으로 돌아온다.
- UI 최초 관찰은 라임 태그명 → 공개 제목 → 작성자 위계가 명확하나, 우측 배지와 행동 크기가 혼재하는 UI-01을 발견했다.

## 검증 및 실패 기록

- 변경 분류: 신규 API/서비스·페이지 이동·구독 캐시와 공통 메뉴 옵션. 관련 검사를 먼저 수행하고 최종 전체 verify를 실행한다.
- API 테스트 우선 작성 시 미구현 tagQuizzes 요청으로3개 실패를 확인했다(`/tmp/tag-catalog-red.log`).

- 재검증: tagQuizzes Jest4개 통과(`/tmp/tag-catalog-unit-recheck.log`), 페이지네이션 E2E1개 통과(`/tmp/tag-catalog-page-recheck.log`). C1 이후 관련 E2E의 나머지9개도 통과했다(`/tmp/tag-catalog-e2e-final.log`).

### 사용자 후속 C2 — 퀴즈 카드 시각 개선

- 사용자 요청으로 카드만 귀엽게 개선했다. 별도 UI 설계자가375px 실제 캡처를 확인하고 작은 퀴즈 노트 형태를 제안했다.
- 둥근3xl 카드와 얕은 하단 그림자, 라임 노트 SVG, 제목행 화살표, 옅은 작성자 영역을 적용했다. 헤더 C1·링크 목적지·게스트 선택·페이지 동작은 유지한다. 장식 SVG/화살표는 aria-hidden이다. 긴 제목/작성자에는 overflow-wrap:anywhere를 사용한다.
- 전체3차 검사는 C2 전에 빌드한 기능 코드 기준이며 중단하지 않았다. C2는 스타일·장식만 변경하므로 변경 파일 ESLint/Prettier, 새 컨텍스트 최초 리뷰와 같은 독립 리뷰어의 R2 실제 PC/mobile, 관련 태그 목록 E2E로 추가 확인한다. 전체 결과를 C2 스타일 빌드 결과라고 주장하지 않는다.
