# PROFILE-ABOUT UX 리뷰

## 대상과 증거

- 사용자 가설: 개발자가 본인 공개 프로필에 소개·작업물 링크를 게시하고, 방문자가 이를 읽고 외부 작업물로 이동한다.
- 확정: 공개 프로필의 본인 편집, 선택 Markdown 하나, 동적 링크 다섯 종류와 기타 이름, 수정·삭제·빈 값 저장. 닉네임·이미지·실제 인증 및 학습 활동 자리 표시자 구현은 제외한다.
- 워크트리: `자기소개`, 미커밋 PROFILE-ABOUT 코드. 독립 새 컨텍스트 리뷰어 `/root/profile_ux`. 구현자와 별개이며 코드 수정 없음.
- R0: `test-results/profile-about-public-intro-a993e-editing-and-links-at-1280px-chromium/`와 `profile-about-public-introduction-editing-and-links-at-390px-chromium/` 편집·저장 fullPage 캡처(1280×900/390×900)를 먼저 관찰한 후 코드·E2E 시나리오 확인. 제공된 캡처는 본인 로그인 상태다. 실제 조작은 3158 dev 접속 거부로 미확인. 기존 사용자 dev 3003와 충돌해 새 dev가 종료되었으며 기존 서버는 건드리지 않았다.
- R1용 최신 production build 후 별도 3158 서버를 실행했다. 공개 최소 높이 수정 후 코드이며 편집 미리보기는 그대로다.

## 최초 관찰과 흐름

‘타입 개발자의 공개 소개·작업물·데스크’ 화면으로 이해된다. 이름·공개 ID로 대상이 식별되고 본인은 프로필 편집, 방문자는 링크 이동을 할 수 있다. 본인 편집 → Markdown 작성 → 링크/기타 이름 입력 → 저장 → 공개 소개·링크를 캡처로 추적했다. 짧은 소개와 링크 사이의 약 200px 공백이 정보의 연결을 약하게 했다.

## R1 직접 확인과 종료

- 독립 리뷰어가 Node v22.23.3, 최신 production `127.0.0.1:3158`에서 직접 Playwright 조작. 1280×900/390×900 공개 소개 높이 111px, min-height 0px, 링크 간격 16px로 UX-01 해결. 캡처 `/tmp/profile-r1-1280.png`, `/tmp/profile-r1-390.png`.
- 긴 글·200자 코드에서 페이지 가로 넘침 없음, 코드 내부 스크롤 유지. 편집 미리보기 최소 높이 270px 유지.
- 본인 소개·GitHub·기타 링크 작성→저장→완료 안내→공개 표시 확인. 비로그인 방문자와 로그인 타인은 소개/링크를 읽으며 편집이 없음.
- GitHub 사용자 정보 형식 오류 문구 확인. 브라우저 저장 예외 주입으로 실패·입력 보존 확인 후 예외 제거·동일 입력 재시도 성공.
- 취소 확인에서 Tab으로 계속 편집 도달, 변경 취소 후 프로필 편집 버튼 포커스 복귀 확인.
- 목적/대상·행동 발견·밀도는 R0 판단 유지. 정보 우선순위 문제 해결, 상태 피드백·모바일·기본 키보드·사용자별 핵심 상태를 직접 확인으로 보완했다.
- 수정 1회로 종료. 필수 미해결 문제 없음. 스크린리더 음성 출력·타 브라우저·로딩/조회 실패의 실제 화면은 미확인. UX 리뷰는 전체 기능 검증이나 병합 결정을 대신하지 않는다.

## 사용자 스크린샷 후속 평가

사용자가 현재 화면의 UX 문제를 평가해 달라고 요청했다. 이는 추가 구현 요청으로 해석하지 않는다. 메인 평가: 별도 행의 프로필 편집 버튼이 이름→자기소개 흐름을 끊고, 데스크 편집과 프로필 편집의 높이·형태가 분산되어 있으며, 작은 소개 글자의 정보 위계가 약하다. 제안은 이름/ID/소개/링크를 가깝게 묶고 본인 편집 동작을 함께 배치하는 것이다. 이미지의 `guthub`은 입력된 기타 표시 이름인지 확인되지 않았으므로 실제 종류 매핑 오류로 단정하지 않는다. 이 평가를 독립 리뷰어의 발견이나 적용 완료로 기록하지 않으며, 후속 배치 수정은 이번 검증 코드에 반영하지 않았다.
