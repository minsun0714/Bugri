# NOTE-TO-QUIZ UX·UI 리뷰 기록

## 대상과 증거

- 대상: 메모 상세의 퀴즈 영역, "버그리와 퀴즈 다듬기" 작업 모달, 퀴즈 수정 모달, 메모 삭제 경고, 내 노트 목록 행, 홈 저장 토스트.
- 사용자 목표(검토용 가설): 업무 중 배운 내용을 메모하고 퀴즈로 만들어 저장한 뒤 풀어 복습하려는 개발자.
- 리뷰어: 새 컨텍스트의 독립 UX sub-agent 1명, UI sub-agent 1명(최초 리뷰 R0). 두 리뷰어는 Playwright MCP로 같은 브라우저를 공유해 직접 조작했다(데스크톱 1280, 모바일 390/320, 일부 다크·영어).
- 한계: 리뷰 서버를 영어 번역 키 추가 전에 빌드해서 영어 화면에 한국어가 남아 보였다(UX-13, UI-9). 이후 재빌드했고 영어 재확인은 하지 않았다. 공유 브라우저 탓에 한 리뷰어의 탭에 잘못된 조작이 한 번 들어갔다. 퀴즈 수정 모달 단독, 320 모달, 키보드 전체 순회는 미확인.
- 수정(C1) 이후 sub-agent 재검증(R1)은 **실행하지 않았다.** 사용자가 MCP 사용을 확인하는 중이라 중단했고, 대신 단위·E2E 테스트로 수정 동작을 확인했다.

## 수정 횟수

C1 한 번, 이후 UI R1 후 C2 한 번(UI-10·UI-11).

## R1 (UI 리뷰어, 직접 조작: 320/390 영어 라이트·다크, MCP 수동 확인)

- 해결: UI-1, UI-2(목록·모달), UI-5, UI-8, UI-9(재빌드로 영어 정상). 편집 중 하단 푸터 위계 양호.
- 새 회귀 UI-10: 삭제를 고스트로 낮춘 뒤 모바일 모달 카드 헤더 액션이 2줄로 우측 정렬되어 Save가 첫 화면 밖으로 밀림 → C2에서 모바일은 좌측 정렬로 변경.
- 잔여 UI-11: 긴 영어 배지 행이 3줄, 수정·삭제 38px → C2에서 배지 말줄임·한 줄 고정, 버튼 min-h-11.
- UI-12(메모 삭제는 채운 danger, 퀴즈 삭제는 고스트): 퀴즈 전체를 지우는 더 큰 파괴 동작이라 의도로 유지.
- 미확인: 한국어 재확인, 데스크톱, 저장됨 탭·완료 버튼, 삭제 모달, 키보드.
- UX 리뷰어 R1 결과는 아래에 이어서 기록한다.

## R1 (UX 리뷰어, 직접 조작: 데스크톱 1280, 모바일 390, 한국어·영어, MCP 수동 확인)

- 해결: UX-01, 03, 04, 13, "문제 1 / 2". 부분: UX-02(제목 링크 20px·수정/삭제 38px는 선택으로 남김).
- 미해결: UX-07 목록(PENDING 메모에 "퀴즈 없음"), UX-10(괄호 그대로), UX-11(포커스 BODY). 구현자가 확인한 원인: 앞선 수정 두 곳이 포맷 변경 때문에 적용되지 않았고(UX-07 목록, UX-10), 포커스는 저장 중 탭이 disabled라 이동하지 못했다.
- 새 회귀 N-1: PENDING만 있는 메모에서 "이 메모의 퀴즈" 제목만 남음.

## C3

UX-07 목록, UX-10, UX-11(저장 완료 후 포커스), N-1(빈 섹션 숨김)을 수정하고 단위 테스트 3개를 추가했다. UI-12는 의도로 유지. 
## R2 (UX 리뷰어, 직접 조작: 1280·390, 한국어, 영어는 모바일 상세만, MCP 수동 확인)

- 해결: UX-07 목록, N-1, UX-10(PENDING 있을 때 괄호 유지 확인), UX-11(저장·모두 저장·삭제 후 탭에 포커스), 모바일 모달 카드 헤더 액션 좌측 정렬. 새 회귀 없음, 차단 이슈 없음.
- 남은 것(수정 3회 소진, 보류): 퀴즈 행 수정·삭제 터치 높이 38px(목표 44px, 공통 Button `sm` 크기가 `min-h-11`보다 우선), 제목 링크 20px, 모달 탭 31x42px(UX-12), UX-05·06·08·09·14, 삭제 문구 어미 "삭제했습니다"(저장 문구 "저장했어요"와 톤 차이, 선택).
- 미확인: 다크 모드 재확인(UI R1은 다크 확인), 영어 모달 전체, 모바일 키보드 전체 흐름. UI 리뷰어의 R2는 요청하지 않았다(UI-10·UI-11의 C2 수정은 UX R1·R2가 모바일에서 간접 확인).
