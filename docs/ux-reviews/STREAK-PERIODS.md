# STREAK-PERIODS — 기간 탐색과 안정적인 높이

## 대상과 증거

- 사용자 가설: 홈에서 단기·장기 학습량을 확인하고 오늘 퀴즈로 돌아오는 로그인 더미 사용자.
- 승인 범위: 기본 7일 막대, 월 달력, 년 월별 합계, 연간 월 선택 → 월 달력, 이전·다음·현재 기간 복귀. 현재 스트릭은 조회 기간과 독립적이다. 일별 고유 개수의 합을 사용하며 사용자 전환 시 기본 보기로 초기화한다.
- 후속 사용자 피드백: 데이터 양에 따라 컨테이너 높이가 바뀌는 문제를 수정하고 sub-agent를 사용하도록 요청했다.
- 코드: `24ae9af` 이후 ActivityPeriods·periods·summary 변경. API와 저장 정책은 변경하지 않았다.
- 구현 전 별도 UI 설계: lg부터 좌우 분할, 공통 Tabs/Button, 모바일·태블릿 세로 배치, 연간 모바일 6열 2행을 제안했다. 설계 제안은 실화면 검증과 구분했다.
- 독립 UX·UI R0는 각각 새 컨텍스트로 위임했다. 전용 production 서버 `127.0.0.1:3327`, 로그인 fixture, 390×844·768×900·1280×900 화면을 제공했다. C1 후 서버를 다시 시작하고 같은 리뷰어가 R1을 수행했다.

## 역할별 관찰

| 역할·관점 | 관찰과 확인 범위 |
| --- | --- |
| UX 목적·우선순위 | 현재 스트릭과 과거 학습량을 구분할 수 있다. 기본 7일을 작게 유지하면 퀴즈 접근을 불필요하게 늦추지 않는다. |
| UX 핵심 행동 | 기간 이동·현재 복귀·연간 월 진입·월 탭 포커스, 홈 → 과거 탐색 → 7일 → 답 선택·제출 → 결과·다음 문제를 직접 확인했다. |
| UX 밀도·상태 | R0의 빈 안내와 가변 달력 행이 높이를 바꿨다. R1에서는 총 0개와 날짜별 0개로 빈 상태가 전달되고, 미래 날짜의 — 및 다음 기간 비활성이 유지됐다. |
| UX 접근성·사용자 | 세 viewport와 월 진입 포커스 확인. 전체 키보드 순회·스크린리더·확대·방문자·사용자 변경은 직접 미확인. 타인 화면은 범위 밖이다. |
| UI 위계·색·타이포 | 버그리·스트릭·선택 탭·기간 이동의 구분이 유지된다. 줄인 셀에서도 날짜와 개수가 겹치지 않는다. |
| UI 여백·정렬·비례 | R1의 4주 달력 아래 여백은 안정된 높이를 위한 절충으로 수용했다. 데스크톱 월 보기 퀴즈 시작은 기존 y748에서 y692로 당겨졌다. |
| UI 모바일·초점 | 390px 연간 2행 막대와 라벨이 잘리지 않고 세 viewport에서 가로 넘침이 없다. 키보드 화살표로 월 탭 전환 후 Tab으로 패널 진입 및 초점 표시를 확인했다. |

## 문제와 처리

사용자 높이 피드백을 sub-agent가 새로 발견한 요구로 기록하지 않는다. 두 리뷰어는 다음 원인과 영향을 직접 재현했다.

| ID | R0 근거·영향 | 처리와 R1 결과 |
| --- | --- | --- |
| UX-HEIGHT-01 / UI-03 | 빈 안내가 같은 보기 높이에 28px를 추가해 아래 퀴즈 위치가 움직였다. | C1에서 중복 안내 제거. 총 0개·개별 0개로 상태를 유지했다. 두 리뷰어가 빈/채움 높이 동일함을 확인했다. |
| UX-HEIGHT-02 / UI-02 | 4·5·6주 달에 따라 최대 136px 높이 변화가 있었다. | C1에서 항상 6행 확보. 빈 칸에는 날짜나 데이터를 만들지 않는다. 두 리뷰어가 달별 동일 높이를 확인했다. |
| UI-04 | 월 셀 56/64px가 카드 밀도를 낮추고 큰 여백을 만들었다. | C1에서 비인터랙티브 셀을 40/48px로 줄였다. 날짜·개수가 읽히고 겹치지 않음을 확인했다. |
| UI-01 | 모든 탭을 같은 높이로 맞추자는 제안. | 기각. 승인된 기본 7일의 간결함과 퀴즈 접근을 우선해 보기 간 의도적 높이 차이를 유지한다. UX는 모든 탭을 월 높이로 맞추면 기본 화면에 큰 공백이 생긴다고 지적했다. UI 리뷰어도 R1에서 처리 이유를 수용했다. |

## 회차와 종료

- R0: 위 문제 재현. 전탭 동일 높이 의견 충돌은 승인된 기본 보기와 사용자 목표를 근거로 결정했다.
- C1: 빈 안내 제거, 6행 확보, 셀 밀도 축소. 높이 E2E가 모바일에서 남은 4px 차이를 발견해 날짜 셀의 안쪽 여백도 조정했다. 기대값을 완화하지 않고 재실행해 통과했다.
- R1: 두 리뷰어가 독립 실제 화면에서 해결을 확인했다. 새 필수 문제 없음. 공통 수정 1회 후 종료한다.

별도 정적 코드 리뷰에서는 날짜 이동·일별 범위 합계·미래 제외·월 전달·사용자별 마운트 경계를 검토했고 수정 필요 결함을 발견하지 못했다. 정적 검토를 테스트 실행으로 표현하지 않는다.

## 구현 검증

- Node v22.23.3. 관련 단위 10개와 E2E 4개 통과. E2E는 기간 탐색·사용자 변경·제출 및 세 viewport의 4·5·6주/빈·채움 높이를 검증했다.
- 초기 타입 검사는 RTL에 지원되지 않는 exact 옵션으로 실패했다. 옵션을 제거하고 문자열 이름의 기본 정확 일치를 유지해 타입 검사와 관련 테스트를 통과했다.
- 마지막 코드 변경 후 전체 verify 결과는 TASKS에 기록한다. 사용자 최종 디자인·병합 판단은 별도다.
