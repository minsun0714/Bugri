# COIN-ROUTE UX·UI 리뷰

- 범위: `/my` → `/coin-history`, 제목·메뉴·현재 위치 ‘코인 내역’, 풀이 기록·학습 시간대 설정 자리표시자 제거. 기존 잔액·필터·내역·데스크 링크 유지.
- 구현 전 별도 UI 설계: 공통 H1·카드·여백과 의미 토큰 유지, 인접 영역만 변경.
- R0: 새 컨텍스트의 독립 UX 및 UI 리뷰어가 화면을 먼저 확인하고 diff·테스트를 검토했다. 필수 문제 0개, 수정 회차 0회. UX 리뷰어가 라우팅 코드도 독립 검토했으며 발견한 회귀 없음.
- 증거: `test-results/coin-history-*/coins-*.png`, `test-results/navigation-header-*/profile-menu.png`. 코인 화면은 1280×900·390×900 viewport 전체 페이지 캡처. 동작은 coin-history/navigation/profile-split E2E 실행 결과와 코드로 간접 확인했다.

## UX R0

본인 잔액과 거래를 조회하는 화면으로 읽힌다. 제목·현재 위치가 일치하고 ‘내 잔액’이 대상을 명시한다. 첫 화면에 잔액·필터·거래가 있으며 하단 데스크 링크가 주목적을 방해하지 않는다. 지급/사용 부호와 선택 탭·현재 페이지·비활성 이전 버튼이 상태를 전달한다. 제거한 두 영역의 빈 컨테이너도 남지 않는다. 모바일에서 잔액·탭·금액 잘림 없음.

제공된 실행 근거에서 기존 주소 → 새 주소(사용자 보존) → 프로필 메뉴 진입/닫힘, 코인 화면 → 데스크 편집 → 공개 프로필 이동을 추적했다. 구매 후 잔액·거래 반영, 사용자 분리, 필터·키보드 페이지 이동도 E2E로 간접 확인했다. 제목과 카드 제목의 반복은 사용을 방해하는 문제로 보지 않았다.

## UI R0

페이지 제목 → 카드 제목 → 큰 잔액 → 필터 → 목록의 위계가 분명하다. 거래명·날짜·금액의 굵기와 크기가 구분되며 구분선·여백이 규칙적이다. 거래명/날짜 왼쪽, 금액 오른쪽 정렬이 유지된다. 지급·사용은 색상과 부호로 구분한다. 모바일 390px에서 메뉴·탭·본문이 화면 안에 들어오며 겹침이나 불필요한 줄바꿈 없음. 메뉴 트리거의 포커스 테두리를 캡처로 확인했다.

## 한계와 종료

리뷰어는 직접 브라우저를 조작하지 않고 실제 캡처와 실행 증거를 사용했다. 로딩·오류의 시각 표현 및 게스트 직접 진입 상태는 미확인이다. 기존 컴포넌트의 상태 동작은 관련 Jest로 검증했으며 이번 변경은 해당 로직을 바꾸지 않는다. 요청한 핵심 화면·메뉴·이동 증거가 확보되어 R0에서 종료한다. 미해결 필수 문제 없음.

## 검증

Node v22.23.3. 변경 파일 ESLint·Prettier, 전체 TypeScript, 관련 Jest 4 suites/19개, production build 및 관련 E2E 16개 통과. 최초 타입 검사에서 redirect 반환 타입과 Jest 옵션 오류가 발견되어 1회 수정 후 재검증했다. 최초 새 메뉴 Jest 실패는 구현 전 의도한 TDD 실패다. 전체 `npm run verify`는 페이지 이동 변경의 로컬 검증 범위이므로 실행하지 않았다. 최종 검사 이후 변경은 기록 문서뿐이다.
