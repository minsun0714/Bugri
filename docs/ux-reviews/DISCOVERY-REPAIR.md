# DISCOVERY-REPAIR — 개발자 탐색 전체 개선

## 대상과 증거

- 사용자 목표: 헤더에서 개발자 탐색에 진입해 이름/@ID로 찾고 공개 퀴즈·태그를 비교한 뒤 프로필/퀴즈를 보거나 명시적으로 구독한다. 로그인 사용자는 3종 내 구독을 확인·해제한다.
- 사용자 승인: 선행 리뷰 16개 항목 전체 개선. 1단계 Mock, 실제 인증 없음. 개발자 탐색에서 데모 로그인 안내를 연결한다. 태그 탐색 본문·공개 프로필 본문·다른 화면 로그인 게이트는 범위 밖이다.
- 구현: 검색 최우선, 접힌 실제 내 구독, 공개 프로필 이름 링크/별도 공개 퀴즈 수 링크, 대표 공개 태그, 공통 홈 학습 이동, 명시적 구독 상태/펼침형 해제. 검색 @ 정규화·경계/저장 오류 복구·초점·44px 액션 반영.
- 현재 워크트리 미커밋 코드와 `localhost:3001`에서 독립 새 컨텍스트 UX/UI 에이전트가 Playwright Chromium으로 직접 조작했다. UX PC1440×900/mobile390×844, UI PC1440/mobile375·320.
- 증거: `/tmp/repair-ui-desktop.png`, `/tmp/repair-ui-{375,320}.png`, `/tmp/repair-ui-{modal,subs,manage,error,profile}.png`, `/tmp/repair-ux-r1-{error,mobile}.png`, `/tmp/repair-ui-r1-{320,375,1440}.png`, `/tmp/repair-ui-r1-error-{320,375,1440}.png`, `/tmp/repair-ui-r2-{pending,complete}.png`(로컬 세션 파일).

## 최초 관찰과 흐름

UX: 개발자를 검색하고 공개 퀴즈 수/태그를 비교해 프로필·퀴즈 또는 구독으로 진행하는 화면으로 이해했다. 모바일 @ID 검색→로그인 모달→데모 로그인만으로는 미구독 유지→재클릭 구독→내 구독 관리/해제→summary 초점 복귀를 직접 확인했다.

UI: 제목→검색→카드가 명확하며 기존 색·타입 위계가 유지된다. 접힌 내 구독이 결과를 과도하게 밀지 않는다. 모바일 카드별 액션 위치와 오류 시 검색 버튼 정렬은 수정이 필요했다.
