# QA-SPACE-20261108 — 작성·관리 공간 활용 리뷰

## 대상과 증거

- 검토용 사용자 가설: 학습 내용을 퀴즈로 만들고 자기 목록에서 관리하려는 개발자. 더미 사용자 `author` 상태.
- 범위: QA-01 모바일 작성/미리보기 탭, QA-03 HTTP 예시 placeholder, QA-04 관리 카드 밀도. 공개 카드 기본값·톱니 동작·API/Mock·Header/토큰은 보존한다.
- 버전: `1c73960` 기반 이 TASK의 미커밋 코드. 리뷰 뒤 변경은 E2E의 합성 긴 태그 스트레스 검사와 기록뿐이다.
- 경로: `/quizzes/authoring?user=author`, `/quizzes/authoring/manage?user=author`. 작업 전용 서버 `http://127.0.0.1:3120`.
- 캡처: `/tmp/bugri-quiz-space/`의 `ko/en-mobile-write`, `mobile-empty`, `mobile-code`(390×844), `desktop-code`(1280×900), `mobile-generated`(320×800), `ko/en-{320,390,1280}-manage`(높이 900), `manage-open`. PNG 전체 페이지 캡처이므로 첫 viewport 아래 영역도 포함한다.
- UX/UI는 각각 새 컨텍스트의 독립 sub-agent. 사전 시각 설계 에이전트와도 분리했다. 코드 수정과 추가 위임은 하지 않았다.

## 최초 관찰과 흐름

UX: 작성 화면은 학습 내용을 적고 퀴즈를 생성하는 목적, 관리 화면은 내 퀴즈를 찾고 검토하는 목적으로 식별된다. 390×844 한국어에서 입력 → 방향키 미리보기 → 생성 → 후보 모달, 목록 → 톱니 Enter → 관리 상세를 직접 완료했다. 첫 직접 시도는 브라우저 언어를 지정하지 않아 한국어 locator가 실패했고, 한국어를 명시한 재시도에서 완료했다(제품 실패 아님).

UI: 제목과 생성 CTA가 우선 보이고 관리 카드에서는 제목 → 상태 → 날짜·태그를 읽는다. 제공된 ko/en × PC/모바일 캡처를 직접 시각 검사한 간접 리뷰다. 브라우저 조작은 수행하지 않았다.

## 문제 목록과 처리

필수/일반 문제 0건. 문제 없음은 위 관찰에 한정한다. UX는 공통 `tabs`/`split` 기본값과 `QuizCard` 기본 밀도 보존, 전체 제목의 접근성 이름·독립 톱니·포커스 스타일을 diff로 추가 확인했다.

긴 태그는 실제 API가 등록 태그만 허용하므로 최초 관리 캡처의 태그는 `javascript/web/typescript`다. 실제 저장 흐름과 별개로 DOM의 태그 텍스트만 합성 긴 문자열로 바꾸는 E2E 레이아웃 스트레스 검사를 추가했다. API/Mock 구조를 바꾼 증거로 취급하지 않는다.
