# I18N-01 — 한국어·영어 화면 언어

## 대상과 증거

- 검토용 사용자 가설: 한국어/영어로 퀴즈를 풀거나 작성하는 방문자·학습자·작성자. 서비스 UI만 번역하며 사용자 콘텐츠·입력·현재 경로를 유지한다(REQ-16).
- 현재 작업 트리의 미커밋 구현. 격리 dev 서버 `http://127.0.0.1:3417`. PC 1280×900, 모바일 320×800·390×844.
- 구현 전 별도 UI 설계자가 PC 테마 옆/모바일 메뉴 안의 언어 선택을 제안했다. 새 컨텍스트 UX/UI 리뷰어가 Playwright로 실제 화면과 조작을 독립 확인했다. 구현자는 별도 언어 E2E와 회귀 검증을 수행했다.
- 화면 증거: `.bugri-hooks/i18n/`의 주요 화면 캡처; 리뷰어 `/tmp/ui-*-r1.png`, `/tmp/ux-r1-author.png`, `/tmp/ux-r1-tags.png`. 로컬 검증 산출물이며 저장소에 포함하지 않는다.

## 문제와 처리

| ID | 관찰·영향 | 처리·해결 근거 |
| --- | --- | --- |
| UI-01 | P2: `Search results4results · 1Page`, `Total0items`가 붙어서 표시됨. | C1: 완성 문구 보간. R1 실제 320px에서 `4 results · Page 1`, `Total: 0` 확인. |
| UX-01 | P3: `1 items`, `10,000characters`, `1 / 5 Page`가 부자연스러움. | C1: 중복 단위 생략, 공백, `Page 1 of 5`. 두 리뷰어 R1 확인. |

## 회차·한계

- R0 독립 UX/UI 화면 리뷰 → C1 공통 수정 → R1 같은 리뷰어 재검증. 수정 1회, 필수 미해결 문제 없음.
- 실제 모바일 OS 키보드, 스크린리더 음성, 정량 색 대비, 모든 오류/상품/타인 프로필 상태 조합은 직접 미확인이다. 저장소 차단과 작성 입력 보존은 구현자 Playwright 테스트에서 확인했다.
- 코드 리뷰는 화면 리뷰와 별도로 수행했으며 테스트 통과를 화면 검토 근거로 대신하지 않았다.

## 검증 과정

- Node v22.23.3. 신규 locale 단위 테스트는 미구현 모듈 오류로 최초 실패를 확인한 뒤 구현했다.
- 개발 중 기본 매개변수의 번역 훅 접근을 본문으로 옮기고 Next 타입 생성을 실행했다. 기존 단위 테스트에서 발견된 공백·연간 제목 회귀를 수정한 뒤 해당 17개 테스트가 통과했다.
- 새 편집기 단위 테스트의 ESM 로딩 오류는 기존 저장소 테스트와 같은 Markdown mock 방식으로 해결했다. 실제 Markdown/중국어·코드 입력 보존은 브라우저 E2E로 별도 확인했다. 신규 언어 단위 5개와 관련 E2E 4개 통과.
- 최초 전체 lint는 작업용 임시 CJS 도구가 검색되어 실패했다. 임시 도구를 저장소 밖 `/tmp/bugri-i18n-tools`로 옮겼으며 검사 규칙이나 제품 테스트를 제외·약화하지 않았다.
- 번역 사전 677개 항목의 보간 자리표시자 일치와 호출된 한국어 정적 메시지의 사전 누락 없음 확인. 변경 코드 Prettier와 `git diff --check` 통과.

## 최종 검증 결과 — 미완료

- `PLAYWRIGHT_PORT=3447 npm run verify` exit 1. lint·타입·Jest 64 suites/316개·도구3개·production build 통과. E2E 201개 중198개 통과/3개 실패. 언어 전환 신규 E2E4개는 production에서도 통과했다.
- `profile-split.spec.ts:19`: 기존 ‘개인 관리’ region을 desk-shortcut 링크 이름으로 바꾼 접근성 이름 회귀. 기존 한국어 이름을 유지하면서 영어 이름을 제공하는 컴포넌트/레이블 연결로 수정해야 한다. 테스트 기대를 약화하지 않는다.
- `developer-discovery-repair.spec.ts:317`: 모바일 구독 모달 검색·필터·해제/초점 흐름30초 시간 초과. 실패 스냅샷에 모달이 열린 상태이며 원인 추가 확인 필요.
- `scene-centering.spec.ts:4` mobile390: orbit의 mouse.move 중30초 시간 초과. 이번 변경과의 인과관계를 확정하지 않았다.
- 단위 회귀 수정→관련 재실행, 신규 단위 ESM 설정 수정→재실행, 전체 lint 임시 도구 정리→전체 재실행까지3회 이후 최종 실패를 확인했다. 추가 재시도 없이 실패를 보존한다. UI 리뷰의 확인 범위는 유지하지만 작업 전체는 DONE이 아니다. 최종 검증 이후 코드 변경 없음, 문서 결과만 갱신했다.
