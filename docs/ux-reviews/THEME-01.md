# THEME-01 — 화면 테마 리뷰

## 대상과 증거

- 대상: 밤에 학습·작성·탐색하는 방문자와 데모 사용자(검토용 가설). 헤더에서 테마를 고르고 이동·재접속해도 선택을 유지하는 것이 목표다.
- 확정: 기본 시스템, 명시 선택 우선, 브라우저 단위 표시 설정, 버그리 고유색·사용자 방 보존. 후속 사용자 확인으로 문제 환경은 **갤럭시 Chrome**이다. 삼성 인터넷으로 단정하지 않는다.
- 버전: 기준 `96749c9` 위 THEME-01 미커밋 변경. Node 22.23.3, 격리 dev 서버 3167. 구현 전 독립 UI 설계, 별도 새 컨텍스트 UX·UI 리뷰어의 Chromium 실제 조작/캡처, 별도 구현자 외 정적 코드 리뷰를 수행했다.
- 1280×900: 홈·개발자 탐색·작성·상점·공개 프로필·마이페이지·UI 전시. 320×850 및 390×844: 홈 테마 메뉴·선택/정오답·작성 폼·공통 모달. UX R1은 320×800.
- 캡처: 구현자 `.bugri-hooks/theme/`, UI 리뷰어 `/tmp/ui-*.png`(로컬 비커밋 증거). 최초 구현자 profile 캡처는 잘못된 publicId의 오류 상태이며 정상 프로필 근거로 사용하지 않는다. UI 리뷰어는 `/users/bugri-learner?user=learner`의 실제 방을 따로 확인했다.

## 최초 관찰과 흐름

UX: 홈은 퀴즈, 탐색은 검색·구독, 작성은 입력이 주 행동이다. 개발자 탐색 → 키보드 다크 선택 → OS 라이트 → 명시 다크 유지 → 시스템 선택 → OS 변경 반영 → 라이트 선택 → 상점 이동·새로고침을 직접 확인했다.

UI: 차콜 바탕·카드·라임 캐릭터·보라색 CTA가 구분된다. 정오답은 색상뿐 아니라 문구·기호로 구분되며 모바일 모달의 제목·취소·확인이 온전히 표시된다. 밝은 사용자 방은 승인된 보존 제약이다.

## 회차와 한계

- R0: UI 필수/일반 결함 0건. UX 필수/일반 결함 0건, 선택적 UX-01 한 건.
- C1/R1: 선택기 아이콘·폭 수정 1회. UX-01 해결을 독립 UX가 직접 확인. UI 재검증 결과는 아래 후속 기록에 남긴다.
- UI 직접 확인 한계: `/my` 라이트는 로딩 상태, 320/390px 탐색·상점·프로필·코인 전체 상태, 실제 구매/프로필 편집 모달·라이트 정답은 미확인. UX 상점 직접 캡처도 로딩 상태이며 정상 상점의 시각 판단은 별도 UI 리뷰 근거를 사용한다.
- 실제 Galaxy Chrome 버전/OS 설정 조합과 삼성 인터넷은 미확인이다. Chromium CDP Auto Dark 에뮬레이션과 실기기를 구분한다. 강제 색상 변환을 모든 브라우저에서 차단한다고 주장하지 않는다.
- 구현자 토큰 대비 계산: 본문/보조문구/링크/주 버튼/성공·경고·오류의 지정 글자·배경 쌍은 양 테마 4.5:1 이상. 전체 화면 모든 합성 색상에 대한 접근성 인증은 아니다.

## 실기기 후속 확인

Galaxy Chrome의 버전·One UI/Android 버전·다크 관련 설정을 기록하고 OS 라이트/다크에서 사이트 시스템/라이트/다크를 확인한다. 강제 웹 다크 옵션이 있는 환경은 꺼짐/켜짐 각각 홈·탐색 버그리·정오답·작성 모달·상점 방을 비교한다. 사이트 라이트는 원색을 유지하고 다크는 자체 팔레트/검은 눈·입을 유지하는지, 새로고침 시 반전/번쩍임이 없는지 확인한다. 이 기록이 없으므로 실기기 호환성은 완료 처리하지 않는다.

Chrome의 Auto Dark opt-out은 [공식 설명](https://developer.chrome.com/blog/auto-dark-theme)에 따라 라이트의 `color-scheme: only light`에 적용했다. 이 문서의 오래된 실험 설정명이 현재 모든 Android Chrome에 있다는 뜻은 아니다.

### R1 최종 기록

UI도 320×850·390×850 양 테마의 닫힘/열림 캡처와 390px 라이트 작성 폼을 재확인했다. 아이콘·시스템·화살표 겹침 없이 로고/메뉴와 같은 줄을 유지하며 세 옵션과 체크가 잘리지 않는다. UX·UI 공통 수정 1회 후 필수/일반 미해결 문제 없이 종료한다. 갤럭시 Chrome 실기기 및 위에 열거한 미확인 화면 범위는 그대로 남는다.

정적 재리뷰에서 CODE-01 해결을 확인했다. 루트/글로벌 오류의 layout-effect 구독·저장값 초기화·cleanup, bootstrap/store의 only-light 일치, 추가 테스트의 의도를 확인했으며 추가 차단 결함은 발견하지 않았다. 리뷰어가 직접 테스트를 실행한 결과는 아니다.


### 최종 자동 검증 한계

관련 테마/내비게이션 E2E 13개는 통과했다. 최종 전체 E2E는 190/191 통과이며 `discovery-split.spec.ts:25`의 640px 펼친 메뉴 기대값이 현재 1024px 헤더 기준과 달라 실패했다. 이는 앞선 UX/UI 관찰 결과를 전체 테스트 통과로 대체할 수 없음을 뜻한다. 검증 지침의 수정·재실행 3회 한도에 도달해 추가 수정/재검증은 남겨두었다. TASKS는 IN_PROGRESS로 유지한다.

### 사용자 승인 후 테스트 정합화

사용자가 추가 수정·재검증을 명시 승인했다. `discovery-split.spec.ts`의 두 메뉴 분기를 현행 1024px 기준에 맞추고 기존 1280/640/390px에 1023/1024px 경계를 추가했다. 독립 리뷰에서 헤더·모바일 메뉴·훅의 기준과 일치하고 활성 표시·이동·사용자 보존·뒤로 가기 assertion을 유지했음을 확인했다. 앱 변경이 없어 기존 UX/UI R1 증거를 재사용한다. 관련 E2E 2개 통과; 최종 전체 결과는 TASKS에 기록한다.

후속 최종 전체 검증은 Node22.23.3에서 exit0: Jest302개·E2E191개 및 lint·타입·도구3개·production build가 모두 통과했다. 앞선640px메뉴 기대값 실패는 해결되었으며 로컬 미통과 검사는 없다. 앱 코드는3f3abc7과 같고 테스트만 정합화했으므로 기존 UX/UI R1근거를 재사용한다. 갤럭시Chrome 실기기 미확인 한계는 유지한다.
