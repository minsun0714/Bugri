# GUEST-LANDING UX/UI 리뷰

## 대상과 증거

- 가설 사용자: 처음 방문해 Bugri를 이해하고 공개 퀴즈를 풀려는 개발자.
- 확정 제약: 방문자 전용 랜딩, 아래 실제 퀴즈, 바로 풀기 앵커, 로그인 학습 유지. API·보상 정책 제외.
- 구현: GUEST-LANDING 미커밋 코드. `/` 및 `/?user=learner`, 전용 서버 `http://127.0.0.1:3189`.
- `/tmp/bugri-landing/desktop.png` (1440×1000), `mobile.png`, `dark-mobile.png`, `member.png` (390×844), `quiz.png` (1440×1000). full-page 캡처.
- 메인 직접 Playwright: 앵커 이동·포커스, 한국어 PC/모바일, 다크·모션 감소, 영어 320×720 가로 넘침 없음. 영어 캡처 `english-320.png`.
- 독립 UI 리뷰어는 캡처 5개를 직접 열어 검토. 독립 UX 리뷰는 아래에 기록. 각 리뷰어 새 컨텍스트, 코드 수정 없음.

## 회차와 종료

- R0: UX/UI 필수 결함 없음. 선택적 UI-01 유지. 수정 C1~C3 없이 종료(수정 0회).
- UX 직접 확인: 390×844, ko-KR, 모션 감소 환경에서 앵커 → HTTP 참/거짓 답 선택 → 제출 → 정답·해설 → 다음 문제 완료. URL 해시 및 guest-quiz 포커스 확인.
- UX 목적/첫 화면: 개발자 인사·개발 학습 헤드라인·CTA로 대상과 행동 식별. 데스크톱에는 퀴즈 제목도 보이고 모바일 CTA는 y370 부근.
- UX 밀도/상태: 경쟁하는 주요 행동 없음. 제출 후 내 답·정답·해설·다음 문제를 확인하고 다음 문제는 제출 상태로 복귀.
- UX 접근성/상태: 장식 aria-hidden, motion-safe, 포커스 대상 tabIndex 확인. 회원 화면에는 랜딩 없음. 타인 소유 행동 변경 없음.
- UX 최초 직접 실행은 브라우저 언어와 한국어 locator 불일치로 실패, ko-KR로 바로잡아 성공. 제품 실패가 아닌 리뷰 환경 설정 오류.
- UX 한계: 실사용자 이해도, 전체 키보드 순회, 스크린리더, 빈 상태·오류 상태 직접 리뷰 미실행. 관련 기존 실패/빈 상태 동작은 풀이 E2E로 확인. 동적 모션 체감 평가는 미실행.
- 종료: 주요 사용자 흐름과 방문자/회원 상태 확인, 필수 미해결 문제 없음. 메인이 두 리뷰와 코드 검토 결과 확인.
- UI 정적 캡처에서는 실제 모션·키보드·클릭·영어를 직접 확인하지 않음. 해당 동작은 메인 Playwright와 E2E 증거로 구분한다.

## 사용자 후속 요청 — 외곽 컨테이너 제거

- 사용자 요청으로 큰 외곽 카드와 glow/좌우 패딩 제거. 리뷰어 발견 문제로 기록하지 않음.
- 증거: `/tmp/bugri-open-landing/{desktop,mobile,small}.png`, 각각 1440×1000 / 390×844 / 320×720. 동일 3189 서버. 두 독립 리뷰어가 최신 화면을 직접 열어 검토.
- UI: 제목→CTA→장면의 위계 유지. 제목과 퀴즈 왼쪽 기준선 정렬, 구분선·여백으로 영역 구분. 페이지 배경과 연결되고 CTA/캐릭터 강조 유지. 320px까지 겹침/잘림 없음.
- UX: 모바일 첫 화면 CTA 유지. 외곽선 제거 후에도 퀴즈 진입 목적 명확, 장식이 답안 영역 침범하지 않음. 필수 문제 없음.
- 메인 직접 조작: 세 viewport에서 가로 넘침 없음, 앵커 guest-quiz 포커스 확인. 최초 데스크톱 캡처는 로딩 상태였으며 이후 답 제출 버튼 로드 완료 후 재촬영·직접 확인. 리뷰어는 모바일 완료 화면과 데스크톱 로딩 화면 기준으로 판단.
- UI-01 작은 단계 문구는 기존 선택적 개선 판단 유지. 코드 수정 0회로 종료.
- 한계: 이번 후속 리뷰는 캡처 중심, 제출/다크/동적 모션 재검증 없음. 동작 변경 없는 스타일 범위의 확인이며 이전 전체 검증을 재실행했다고 주장하지 않음.

### 문제·처리·회차

- UI-01 설명의 ‘데/스크’ 분리: break-keep 수정, R1~R3 해결 유지.
- UI-02 모바일 완성 퍼즐 여백: 선택적 미적 개선, 사용자 첫 퍼즐 승인으로 유지.
- UI-03 모바일 3D 작음: 사용자 전체폭 요청과 함께 확대, R2 해결 및 정원 R3 해결 유지.
- UX-01 기존 ThreeView의 SR 상세 좌표 정보: 선택적 개선 보류. 공통 3D 접근성 변경은 범위 외, 실제 SR 미검증 명시.
- R0 퍼즐/SVG: 필수 문제 없음. C1/R1 3D+단어줄바꿈, C2/R2 전체폭·확대, C3/R3 정원 적용까지 확인. 디자인 수정 최대 3회 안에서 종료. 사용자 방향 변경을 리뷰어 발견으로 기록하지 않음.
- 최종 정원 캡처 R3: UX/UI 필수 새 문제 없음. 제목·그림·CTA가 분리되고 버그리·가구·창문 잘림 없음. 완성 캡처 기준이며 최신 320/다크·모션감소 장면은 직접 캡처 재검토하지 않음.
- UX R1 직접 3D 순차 장착/역스크롤(당시 해제)/실행중 모션감소 전환 확인. 이후 사용자 후속 요청인 진행 유지 동작은 별도 직접 재검증: 완성→역스크롤 시 가구 유지, 코인 재등장 없음, 맨위 reload 후 초기화 확인. 현재 순차 장착 진행은 최댓값을 기억함.
- 마지막 사용자 속도 요청은 구간과 단계 간격만 증가. 주요 행동·레이아웃 변경 없음, 관련 E2E 재검증. 리뷰어가 관찰한 속도 수치로 주장하지 않음.

## 스크롤로 배경 좌→우 채우기

- 별도 사용자 후속 작업. 자동 6초 제안은 사용자가 정정하여 폐기했고 최종 코드는 스크롤량만 사용한다. 490svh 중 기존 장면 이후 150svh가 배경 전용 구간이며 역스크롤/정지 시 진행을 유지한다.
- 새 독립 UI paint_ui / UX paint_review 컨텍스트. `/tmp/bugri-story/paint-{desktop,mobile}-{half,full}.png` (1440×1000/390×844) 최신 캡처, 서버3189. 기존 퍼즐·퀴즈·데모 행동 변경 없음.
- UI R0: 4장 직접 확인. 절반 상태에서 왼쪽 벽·바닥만 표시되고 완료 시 오른쪽 창문까지 채워짐. 수직 경계는 의도된 전개. 가구·버그리는 경계로 잘리지 않고 위치 유지. 제목/본문/방/링크 위계와 외부 기준선 유지, 390px 겹침/잘림 없음. 필수 문제0, 수정0.
- UI 한계: 실제 속도·정지·역스크롤·키보드 직접 미검증, 390px미만 미검증. 직접 동작은 UX 및 E2E 결과와 구분.

- UX R0: 최신4장+diff에서 목적/우선순위/모바일/상태/밀도에 필수문제0. 3189 직접 브라우저의 답제출 대기는 완료되지 않아 직접 흐름 통과를 주장하지 않음. 메인 production E2E 증거: canvas 왼쪽/오른쪽 alpha[255,0]→1.2초정지 동일→역스크롤 동일→완료[255,255], 실제 테스트 통과. 구현자 증거와 독립 캡처/코드판단 구분.

- UX 보완판정: 위 구현자 production pixel E2E 증거로 스크롤·정지·역방향유지·완성의 핵심 상태 확인, 필수 문제0 유지. 독립 직접 조작 미완료 한계는 유지. 수정0회로 종료.
