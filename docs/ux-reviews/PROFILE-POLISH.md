# PROFILE-POLISH — 공개 프로필 행동 발견성과 정렬

## 대상과 증거

- 검토용 사용자 가설: 본인 소개·링크를 편집하려는 사용자, 개발자의 공개 퀴즈를 찾는 방문자. 사용자 연구 결과로 주장하지 않는다.
- 확정: 이름 제목 없이 공개 ID 표시, 프로필 편집은 콘텐츠 오른쪽 끝, 데스크 편집은 데스크 위, 저장 성공은 토스트. 소개→데스크→퀴즈→학습 활동 순서 유지.
- 최초 사용자 요청은 앞선 UX/UI 여섯 지적 전체 개선이었다. 후속 “데스크는 편집하지마”에 따라 이번 카메라·확대·도움말은 모두 철회했다. 캔버스 관련 파일 diff는 없다. 추가 요청에 따라 비로그인 버튼 문구만 ‘구독하기’로 바꾸고 기존 동작은 유지한다.
- 기준: 13e1db7 이후 현재 워크트리 미커밋 변경. 격리 production 서버 127.0.0.1:3158. `/users/bugri-author?user=author`, `/users/bugri-learner?user=learner` 및 타인·비로그인 상태.
- 별도 UI 설계자 profile_polish_design이 구현 전 편집 아이콘·강조색·44px 클릭 영역·오른쪽 문구 정렬·퀴즈 바로가기를 제안했다. 데스크 관련 제안은 최신 지시에 따라 적용하지 않았다.
- 최초 리뷰는 새 컨텍스트 UX polish_ux_review와 UI polish_ui_review가 독립 수행했다. 기존 테스트 성공을 최초 화면 판단 근거로 넘기지 않았다.

## UX R0 최초 관찰·흐름

공개 ID와 상단 편집 동작으로 누구의 프로필인지와 다음 행동을 이해했다. 첫 화면의 퀴즈 개수 바로가기가 아래 콘텐츠 발견을 돕는다.

직접 수행: 1280×844·390×844 owner 로그인 → 소개·GitHub 링크 입력 → 저장 → 토스트·편집 버튼 포커스 복귀. 퀴즈 바로가기 → 섹션 스크롤·포커스 이동 → 다음 Tab 전체 보기. 퀴즈 제목 클릭 → `/solve?user=author&quiz=seed-quiz-1` 진입.

| 관점             | 판단           | 근거                                              |
| ---------------- | -------------- | ------------------------------------------------- |
| 목적·대상        | 필수 문제 없음 | 공개 ID와 owner 편집 동작을 상단에서 식별         |
| 우선순위·첫 화면 | 필수 문제 없음 | 큰 데스크 이전에 퀴즈 개수·바로가기 노출          |
| 행동 발견·이동   | 필수 문제 없음 | 편집 아이콘+문구, 섹션 이동과 전체 목록 이동 구분 |
| 밀도·중복        | 필수 문제 없음 | 기존 정보 순서 유지, 필요한 탐색 동작만 추가      |
| 상태·피드백      | 필수 문제 없음 | 저장된 소개·링크와 토스트, 포커스 복귀 확인       |
| 모바일·키보드    | 필수 문제 없음 | 390px 잘림 없음, 섹션 이동 후 Tab 순서 확인       |
| 방문자·본인·타인 | 필수 문제 없음 | 본인만 편집 노출, learner 0개와 실제 빈 상태 일치 |

UX 필수 문제 0개. ‘0개 보기’를 생략하는 선택적 제안은 정확한 목적지·개수를 예고하고 현행 빈 상태로 연결되므로 적용하지 않았다. 저장 실패·네트워크 재시도·스크린리더 실기는 이번 독립 리뷰에서 미확인이다. 학습 활동 placeholder와 데스크 조작은 이번 범위 밖이다.

## UI R0

직접 확인: 360×800 owner 기본·편집·저장, 소개 2문단·링크 저장 후 360/1280, 비로그인 방문자 360/1280. 제공된 390/1280 캡처도 확인했다. 최초 인상은 개발자의 공개 프로필이며 ID·우측 관리 동작·퀴즈 바로가기에서 다음 행동을 찾았다.

| 관점        | 관찰 근거·판단                                                              |
| ----------- | --------------------------------------------------------------------------- |
| 위계        | ID·관리 동작 첫 행, 퀴즈 바로가기는 데스크 전에 노출                        |
| 타이포      | 본문·ID·편집·퀴즈 제목이 굵기와 색으로 구별되며 360px에서도 충돌 없음       |
| 여백        | 소개 없음·소개 2문단/링크 입력 상태 모두 콘텐츠 높이에 따라 자연스럽게 확장 |
| 색          | 두 편집 동작의 보라색 연필·문구 일치, 퀴즈 링크에 밑줄도 제공               |
| 정렬        | 프로필 편집·데스크 편집·전체 보기의 오른쪽 끝 일치, 본문 좌측 기준 일치     |
| 비례·일관성 | 편집 아이콘이 문구를 압도하지 않으며 퀴즈 2열/1열 유지                      |
| 모바일      | 360 직접·390 캡처에서 잘림/충돌 없음, 편집 저장·취소 구분                   |
| 상태        | 입력→링크 추가→저장 내용·완료 토스트 직접 확인                              |
| 본인·방문자 | 본인 편집/방문자 구독이 우측 같은 위치에 나타나고 방문자 편집 미노출        |

UI 필수 문제 0개. 증거 `/tmp/polish-ui-{360,filled-360,filled-1280,guest-360,guest-1280}.png`, `/tmp/polish-ui-edit-360.png`. 색 대비 수치 계산·키보드 전체 순회·긴 소개/다수 링크 극단값·learner 본인/로그인 타인은 UI 리뷰에서 미확인(일부는 UX 리뷰와 기존 E2E가 별도 확인). 최종 구독 문구는 아래 후속 확인에서 다룬다.

## 사용자 문구 요청 최종 확인

- UX: 최종 빌드 390×844 guest `?user=friend`에서 ‘구독하기’ 확인. 클릭 후 데모 로그인·‘개발자 구독하기’로 전환되고 자동 구독 없이 완료 안내 토스트 표시. 순서·가로 넘침 회귀 없음.
- UI: 최종 빌드 1280×900·360×800에서 ‘구독하기’ 우측 정렬·줄바꿈·잘림 없음. 증거 `/tmp/polish-final-ui-1280.png`, `/tmp/polish-final-ui-360.png`.
