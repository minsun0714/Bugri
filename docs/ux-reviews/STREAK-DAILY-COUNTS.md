# STREAK-DAILY-COUNTS — 일별 고유 퀴즈 학습량

## 대상과 증거

- 사용자 가설: 최근 7일의 꾸준함과 일별 학습량을 확인하고 오늘 퀴즈를 완료하려는 더미 로그인 사용자.
- 확정: 하루 같은 quizId 재풀이는 추가하지 않음, 다른 날짜는 별도 집계, 정오 무관, 완료 당시 날짜 보존. 스트릭은 기존 하루1개 완료 판정 유지. 최근7일에 막대/N개를 표시하고 Bugri를 유지한다.
- 변경 가능한 선택: 막대 비율/높이·정보 밀도·문구. 상세 기록·시간대 설정 신규 구현은 제외한다.
- 버전: `9f4a5e8` 이후 API/서비스/스트릭 UI diff. 서버 `http://127.0.0.1:3327` 최신 production. 새 컨텍스트 리뷰어에게 실제 브라우저 1280×900/390×844/768×900 검토 요청.
- 구현자 확인: API 신규 테스트와 UI 테스트의 의도한 실패 후 관련35개 통과. E2E2개에서 제출후1개/당일재풀이1개/복원/사용자격리 확인. 전체 검증 진행 중.
- 다양한 완료량 fixture [1,0,3,2,4,1,2]의 실제 캡처와 격리 storageState: `.bugri-hooks/previews/streak-volume/`. fixture는 시각 검증용이며 기본 사용자 데이터에 추가하지 않는다.

## 최초 관찰과 흐름

리뷰어는 본인 학습현황 확인 후 아래 오늘의 퀴즈에서 답을 제출하는 홈으로 이해했다. fixture에서는 소진 상태의 태그 탐색을 후속 행동으로 식별했다. 신규 context 로그인→number 키보드 선택→제출→1일/오늘완료/1개→재풀기 string 오답→1개 유지까지 직접 확인했다.

## 문제 목록과 처리

발견된 필수·일반 사용성 문제 0개. 가짜 문제 항목을 만들지 않는다. 다양한 학습량과 최초 상태/제출/재풀이까지 직접 확인해 수정 없이 종료한다.

## 회차와 종료

R0 1회, 수정 0회로 종료. 사용자 승인에 따른 학습량 도입을 리뷰어 발견으로 기록하지 않는다. 실제 확인은 1280×900/390×844/768×900 최신3327 production이며 `/tmp/ux-{1280,390,768}.png`, `/tmp/ux-complete.png` 근거가 있다.

독립 화면 리뷰에서 오류/로딩 강제재현·스크린리더 발화·다른날 동일퀴즈·시간대변경·삭제 후 보존은 미확인이다. 날짜/재풀이/정오/미제출/시간대변경/삭제/사용자격리는 API 테스트, 복원/제출후갱신/사용자전환은 E2E로 확인했다. 최종 전체검증 결과는 TASKS에 기록한다.
