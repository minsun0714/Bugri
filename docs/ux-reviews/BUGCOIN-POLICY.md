# BUGCOIN-POLICY 독립 UX/UI 리뷰

## 대상과 증거

데모 학습자가 퀴즈 제출 후 지급 합계·잔액·내역을 확인한다. 기존 디자인 유지, 결과 금액/링크와 내역 사유만 변경. 2026-11-08 현재 작업 diff. 구현자 Playwright가 격리 서버3429에서 1280×900/390×900 각각 새 context로 number 정답→+2.00→내역 링크→일일 첫 정답/최초 정답 각+1·잔액102를 확인했다. 전체 페이지 캡처는 /tmp/bugcoin-result-{1280,390}.png, /tmp/bugcoin-history-{1280,390}.png (로컬 임시 증거).

독립 UX와 새 컨텍스트 UI 리뷰어는 캡처4장을 먼저 보고 코드를 확인했다. 직접 브라우저 조작은 구현자만 수행했다. 설계 상담 에이전트의 사전 검토는 독립 R0와 별도로 취급했다.

## 관점별 평가

| 관점 | UX | UI |
| --- | --- | --- |
| 목적/대상 | 정답·완료일·지급 합계와 데모 사용자 식별 가능 | 결과와 내역에서 BugCoin 단위 일관 |
| 우선순위 | 정오→날짜→보상→답안 | 잔액이 가장 크고 금액 굵기·날짜 보조색 구분 |
| 이동 | 한 번의 내역 링크, 사용자 쿼리 유지 | 금액 옆 링크 배치 유지 |
| 밀도 | 설명·새 카드 없이 한 줄 추가 | 기존 정렬과 여백 유지 |
| 상태 | +기호와 사유로 색 외 지급 구분 | 보상 보라색/정답 연두색 역할 구분 |
| 모바일/키보드 | 390px 한 줄, 결과 포커스 코드는 확인 | 사유와 우측 금액 충돌 없음, focus-visible 코드 확인 |
| 방문자/타인 | 캡처는 학습자. 방문자는 보상 props 없음 코드 확인 | 방문자/타인 실제 시각 미확인 |

## 문제와 처리

- 필수 문제0개.
- UI-01(선택): 내역 링크 기본 밑줄이 없어 발견 단서가 약할 수 있음. 기존 공통 supportLink의 행동형 문구·위치를 유지하므로 이번에는 보류. 필요시 해당 링크만 밑줄 추가 가능.
- 모바일 전체 페이지 상단900px 밖 결과는 기존 달력 영향. 제출 후 결과 focus/scrollIntoView 코드 및 구현자 흐름 확인; 독립 실제 viewport 확인 아님.

## 회차와 한계

R0 종료, UI 수정0회. 독립 리뷰는 캡처/코드 기반이다. 다크·0/복습/재도전·출제자 화면, 실제 키보드·스크린리더는 독립 미확인. 정상 지급과 내역의 핵심 흐름 확인을 전체 접근성 검증으로 확대하지 않는다. 보상 규칙은 단위/API 검증으로 별도 확인한다.
