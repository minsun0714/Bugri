# DEVELOPER-CATALOG-HEADER

## 대상과 확정 범위

- 특정 개발자의 공개 퀴즈를 골라 풀거나 태그로 좁히고 명시적으로 구독하려는 방문자/데모 사용자. 사용자 연구 기반 페르소나가 아닌 검토 가정이다.
- 사용자 최신 답변으로 ‘태그 선택은 필터만, 구독은 별도 버튼’을 확정했다. 과거 P06-TAG-CLICK-SUBSCRIBE를 이 작업에서 대체한다. 전체 퀴즈 복귀 위치는 기존 결과 제목 우측을 유지한다.
- 이름/아바타/공개ID 링크/개발자 구독 헤더, 태그 검색 폭·위계, 선택/구독 상태 및 44px 조작 영역을 정리했다. profile=true와 공통 QuizCard는 유지한다. 잘못된 breadcrumb ‘개발자 프로필’을 해당 경로에서 ‘개발자별 공개 퀴즈’로 수정했다.
- 기존 API/제품 구독3종 계약은 유지한다. 방문자 태그 탐색은 user를 추가하지 않고 구독 요청만 데모 선택을 연다. 구독 후 자동 행동하지 않는다.

## 설계·화면 증거

- UX 설계 에이전트와 별도 UI 설계 에이전트가 현 문서/코드 및 before 화면을 검토했다. UX는 필터/구독 분리와 선택필터 복구, UI는 작은 헤더·제한된 검색 폭·모바일 여백을 제안했다. 과거 확정된 자동구독 동작은 사용자에게 먼저 질문하여 답변 후 구현했다.
- 기준 fe9a259 + 현재 미커밋 소스. 격리 복제 `/tmp/bugri-tag-card-review`, `http://127.0.0.1:3220`에서 동일 코드 실행. 기존 사용자 개발 서버는 중단/재사용하지 않았다.
- `/tmp/bugri-developer-header/`: before-{1280,390}, after-{1280,390}, selected/filter-only/subscribed-only/no-tags/empty/guest-{1280,390,320}.png. viewport 각너비×900, fullPage 캡처. before만 이전 버전이며 나머지는 C1 이후로 갱신했다. 모달/아래 목록은 fullPage 내 스크롤 영역과 구분한다.
- 경로 `/developers/bugri-author/quizzes?user=friend`, 빈 목록 bugri-learner, 게스트 user 없는 경로. UI reviewer는 기본/선택/구독/빈/데모 모달 화면, UX reviewer는 직접 이동과 상태를 확인했다.

## 회차와 한계

- R0: 독립 새 컨텍스트 UX/UI 각각 진행. UX 필수문제0, UI 일반문제1.
- C1/R1: 같은 리뷰어가 필터만/구독만/둘다 최신 캡처를 재확인했다. 왼쪽 보라색 필터와 오른쪽 연두 원형구독체크 소속이 구분되고 320/390 겹침·잘림 없음. UI-01 해결, UX 회귀 없음. 수정1회 후 종료.
- UX 리뷰어 직접 관찰의 마지막 임시 스크립트가 실제 `/solve` 대신 `/quizzes/`를 기대해 URL assertion 실패했다. 실제 풀이 화면을 관찰했지만 그 임시 스크립트를 성공으로 기록하지 않는다.
- 강제 로딩/저장실패·전체Tab순서·화면낭독기·본인profile실제조작·긴 개발자/태그명은 독립리뷰 미확인. 공개profile은 조건분기/기존identity/subscription/간격/breadcrumb 정적 검토와 관련 회귀 E2E로 구분한다.
