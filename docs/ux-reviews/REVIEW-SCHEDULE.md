# REVIEW-SCHEDULE UX/UI 리뷰

## 대상과 증거

- 사용자 목표(가설): 업무 중 배운 것을 메모해 두고 여유가 있을 때 홈에서 오늘 복습을 한 문제씩 푸는 개발자. 성공 행동은 풀이 → 결과·다음 복습일 확인 → 다음 문제 또는 마치기.
- 확정 제약: 홈 순서(빠른 메모 → 오늘 복습 → 연속 학습일 요약), 결과 구성(답·정오·정답·해설·다음 복습일·원래 메모 보기·다음 문제), 상태 5종, 새로고침 복원, 설명 문구 금지.
- 증거: 독립 UX 리뷰어가 Playwright MCP로 직접 조작(데스크톱 1280x900·모바일 390x844, 라이트·다크, 한국어·영어). 코드 버전은 R0 `2d33b76`.

| ID | 요약 | 우선순위 | 메인 처리·이유 |
| --- | --- | --- | --- |
| UX-01 | 시작·복원 시 문제/결과 버튼이 첫 화면 밖 | 일반 | 수정: 풀이 섹션을 화면 상단에 맞춰 스크롤(공유 QuizPanel은 바꾸지 않고 review 쪽 ref 사용) |
| UX-02 | 복습 마친 뒤 포커스가 body로 사라짐 | 일반 | 수정: 완료 헤딩 `tabIndex=-1`, 마치기 후 포커스 |
| UX-03 | 마지막 결과에서 제목이 "오늘 복습 0개" | 선택 | 수정: 남은 0개면 "오늘 복습 끝" |
| UX-04 | 없음 상태 날짜 형식 불일치, 영어 문구에 명사 없음 | 일반(EN) | 수정: "다음 복습: N일 뒤 (날짜) · M개", EN "Quizzes to review tomorrow: N" |
| UX-05 | 메모 상세에 다녀오면 결과가 아닌 대기 상태로 돌아옴 | 선택 | 보류: 개수는 정확하고 복귀 정책은 제품 판단 |
| UX-06 | 메모만 있고 퀴즈가 없을 때 홈에서 퀴즈 만들기 경로 없음 | 선택 | 보류: PRD 확정(퀴즈 없음이면 빠른 메모 강조) 범위 밖 제안 |
| UX-07 | 잘못된 `review` 링크의 주 버튼이 실패할 "다시 불러오기" | 선택 | 보류: 드문 상태, 닫기 버튼 제공 |

범위 밖 관찰: 문제 본문 `function identity<T>(...)`의 `<T>`가 화면에서 사라진다(공유 `QuizText` 렌더링, 이번 변경 아님). 별도 작업 필요.

## UI R0 문제 목록과 처리

UI 리뷰어는 차단 문제 없음, 일반 1건·선택 6건으로 보고했다.

| ID | 요약 | 우선순위 | 메인 처리·이유 |
| --- | --- | --- | --- |
| UI-1 | 영어 "Next review … · 1"에 단위 없음 | 일반 | 수정: "· {2} due" |
| UI-2 | 대기(카드 안 제목)와 풀이(카드 밖 제목)의 틀이 다름 | 선택 | 보류: "섹션 제목 + 풀이 카드"는 의도한 패턴, 공유 QuizPanel 카드 유지 |
| UI-3 | 마지막 결과의 "오늘 복습 끝"과 끝 상태의 스타일 불일치 | 선택 | 수정: 같은 `headingDone`·✓ |
| UI-4 | 대기 버튼(입체)과 풀이 카드 안 버튼(평면) 모양 차이 | 선택 | 보류: 풀이 카드의 기존 공통 규칙 |
| UI-5 | 제출(왼쪽)과 다음 문제(오른쪽) 위치 | 선택 | 보류: 풀이 페이지와 일관성 우선 |
| UI-6 | 로드 오류가 본문색 텍스트 | 선택 | 보류: 연속 학습 카드의 기존 오류 표현과 일치 |
| UI-7 | 연속 학습 카드 가로 패딩 4~5px 차이 | 선택 | 보류: 연속 학습 카드는 이번 범위 밖 |

UI 리뷰어가 확인하지 못한 범위: TIMEZONE_REQUIRED 문구, 풀이 중 로드·제출 오류 화면, 다크+데스크톱 대기·풀이, 한국어 모바일 결과, 키보드 포커스 링.
