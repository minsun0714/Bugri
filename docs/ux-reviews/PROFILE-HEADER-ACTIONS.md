# PROFILE-HEADER-ACTIONS

## 대상·설계 논의

사용자가 제공한 빈 learner 프로필의 독립 순서 편집 줄·큰 빈 퀴즈 영역을 줄인다. 모달·사용자별 순서 저장은 유지한다. 별도 UX/UI 설계 에이전트가 독립 툴바의 44px높이+32px간격 누적을 확인하고, 헤더 관리 그룹 통합 및 프로필 전용 간결한 빈 상태를 제안했다. 버튼 순서 의견은 달랐으며 기존 프로필 편집 우측끝 정렬 요구를 우선해 ‘순서 편집 → 프로필 편집’으로 결정했다. 모바일은 ID 다음행에 두 버튼을 묶는다. 데스크 편집 위치는 그대로다.

기준:577d9e1 이후 현재 diff. 실제 production `http://127.0.0.1:3125/users/bugri-learner?user=learner`, 모달에서 퀴즈를 먼저 배치한 상태. 1280/390/320×900 전체 캡처 `/tmp/profile-header-{width}.png`. 정보·퀴즈가 채워진 author는 별도 관련 E2E로 검증한다.

## UI R0

새 컨텍스트 리뷰어가 세 실제 캡처를 먼저 확인했다. ID/편집 그룹이 콘텐츠보다 먼저 드러나고 굵은 퀴즈 제목·보조 빈 상태 문구의 위계가 구별된다. PC는 ID와 두 액션이 같은 행이며 프로필 편집이 가장 오른쪽이다. 모바일320/390은 ID 아래 두 버튼이 같은 행을 유지하고 퀴즈 제목/전체보기도 잘림·겹침 없이 배치된다. 빈 퀴즈는 큰 아이콘·중복 설명 없이 한 줄로 표시되어 무게가 줄었다. 공통 보라색 액션 톤과 저장 토스트의 가독성을 확인했다. 필수 문제0개.

UI 리뷰어의 직접 조작·모달·키보드 외관·방문자·콘텐츠 있는 프로필 검토는 미실행이며 구현자 관련E2E 및 UX리뷰 근거와 구분한다.

## UX R0

새 컨텍스트 리뷰어가 캡처 후 320px learner 본인/게스트와390px author 타인 상태를 Node Playwright로 직접 확인했다. 공개ID/브레드크럼/퀴즈 제목으로 화면을 식별했고 PC 한행·모바일 ID아래 관리그룹 한행으로 독립 공백행 제거를 확인했다. 모달 진입→위로이동→취소, 손잡이ArrowDown→저장, 저장순서/토스트, 취소 원복을 확인했다. 모달 초기손잡이 및 저장/취소 후 순서편집 초점, 프로필편집→취소 후 프로필편집 초점도 확인했다. guest는 저장순서를 유지하고 관리 버튼이 없으며, friend의 author 프로필은 구독/공개퀴즈2개를 표시한다. 프로필 입력 중 관리그룹을 숨겨 중복 편집 흐름이 없다. 빈 상태의 간결성·전체보기 유지 및 가로넘침 없음을 확인했다.

세 컴포넌트와 단위/E2E diff를 독립 검토했다. 필수 문제0개, R0 수정0회로 종료한다. 실패초안/재시도는 코드·기존테스트 근거이며 이번 직접주입 미실행. 데스크톱 조작·실기기터치·스크린리더·프로필내용저장은 독립 리뷰 미확인으로 남긴다.
