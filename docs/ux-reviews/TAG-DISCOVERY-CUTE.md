# TAG-DISCOVERY-CUTE — 홈 컨셉 태그 UI

## 대상과 증거

- 사용자 목표: 헤더/학습 소진에서 관심 태그를 찾아 구독하고, 명시적으로 학습하거나 내 구독을 관리한다.
- 사용자 요청: 카드 표시 태그명에 # 추가, 홈과 같은 보라·라임·둥근 형태를 참고해 깜찍하게 변경. 구독 중 배지·내 구독 필터 유지, 별도 내 구독 컨테이너는 두지 않는다.
- 범위: discovery-screen/search-results/styles, # 표시와 변경된 데모 사용자 계약에 맞춘 관련 테스트. 홈/API/외부 병합 파일은 수정하지 않는다.
- Node v22.23.3. 태그 dev localhost:3002. 1440·375·320px Chromium 직접 관찰. 화면 참조는 기존 홈과 외부 작업에서 병합된 최신 HOME-QUIZ-03 홈을 함께 사용했다.
- 독립 UI 설계가 마스코트+제목, 둥근 검색/필터 패널, 라임 태그 라벨, 보라 CTA를 제안했다. 구현 후 별도의 새 컨텍스트 UX/UI 리뷰어가 실제 화면을 검토했다.
- 외부 작업이 사용자 확인하에 홈/데모 세션을 같은 워크트리에 병합했고 f167fea로 완료했다. 병합 index와 파일 소유권을 유지하며 이 작업에서 병합 커밋을 만들지 않았다. `?user=`가 로그인 표시인 최신 계약으로 직접 검증한다.

## 구현

- 제목 옆에 탐색용 버그리를 배치했다. 처음에는 공통 Bugri를 사용했으나 사용자 후속 요청에 따라 돋보기 속 #을 바라보며 손잡이를 든 전용 SVG로 바꿨다. 기존 라임 몸체·보라 윤곽·코랄 볼을 유지한다. 검색의 접근성 라벨은 유지하면서 중복 시각 라벨을 숨기고 placeholder는 사용자 후속 피드백에 따라 `태그 이름 검색`으로 표시한다. # 입력이 필수로 보이는 혼동을 없애며 카드의 # 표시는 유지한다.
- 검색/필터를 둥근 흰 패널로 묶고 선택 필터는 보라색으로 강조한다. 카드 #태그명은 연한 라임 라벨, 구독 중은 체크와 보라 배지로 표시한다.
- 카드·버튼의 모서리와 그림자를 정리하고 공개 퀴즈 수에 작은 장식 아이콘, 구독/학습에 +/화살표를 추가했다. 장식은 aria-hidden이며 버튼 이름과 동작은 보존했다.
- 새로운 전역 스타일·래스터 이미지·라이브러리 없이 Tailwind 의미 토큰과 공통 Button/TextField를 재사용하며 탐색 마스코트는 코드 기반 SVG다. 스타일은 discovery/styles.ts의 완성된 literal 문자열이다.

## 검증

- 최신 검증 가이드의 동작 없는 UI 변경 기준으로 변경 파일 lint/Prettier, PC/mobile 및 독립 UX/UI 리뷰를 적용한다. #문구와 외부 데모세션 변경으로 관련 테스트의 기대값·접근경로를 맞추며, 전체 타입 검사·태그 단위/탐색 E2E도 실행한다.
- 앞선 TAG-HASH-LABEL 전체 verify는 사용자 후속 UI 요청 전에 시작했으며 범위 확대 시 작업 소유 프로세스만 중단했다. 완료/성공 근거로 사용하지 않는다. 이후 외부 병합으로 검증 지침이 영향 범위별 검증으로 바뀌었다.
- 검증 결과는 완료 후 추가한다. 외부 작업의 전체 병합 검증을 이 UI 작업의 실행 결과로 주장하지 않는다.

### 병합 후 확인

- 외부 병합 f167fea의 홈·방문자 풀이·URL 사용자 선택을 유지했다. 탐색 제목/카드/스타일 변경이 보존된 것을 diff와 직접 화면으로 대조했다.
- 태그 E2E에서 user 없는 방문자 → 데모 사용자 friend 선택 → 명시 구독을 검증한다. `?user=friend`에서는 이미 선택한 상태이므로 옛 Google 로그인 버튼 단계를 제거했다. 숨긴 검색 레이블·장식 aria-hidden·개발자 화면 스타일 분기·완전한 Tailwind 문자열을 독립 코드 리뷰어가 확인했다.
- scoped lint 및 Prettier 통과(변경 discovery·관련 tests), 전체 TypeScript 통과, 관련 Jest9개 통과(`/tmp/tag-cute-unit.log`).
- 현재 작업자가 기동한 dev3002에서 별도 임시 Playwright 설정으로 탐색분리/태그 E2E6개 통과(`/tmp/bugri-tag-cute-e2e.log`, 37.8초). 검색·필터·URL·게스트선택·명시구독·메뉴초점·Unicode·범위밖페이지·반응형 검증. production build 성공을 이 dev E2E 결과로 주장하지 않는다.
- 병합 이후 이미 활성화된 Hook 전체 검증 `.bugri-hooks/verify-1.log`가 시작돼 그대로 완료를 기다린다. 중복 전체검증은 실행하지 않았다. 이 실행의 E2E 시작 전 최종 solving 테스트에서 구식 로그인 단계만 제거했고 해당 파일 lint/Prettier를 별도 재확인했다. 애플리케이션 코드는 Hook 전체 검사 전에 변경을 마쳤다.
