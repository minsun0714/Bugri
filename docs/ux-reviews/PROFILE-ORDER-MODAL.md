# PROFILE-ORDER-MODAL

## 대상과 증거

본인 공개 프로필의 세 섹션을 간결한 모달에서 정렬한다. 본문 크기·저장 순서는 저장 전까지 유지하며 소개는 상단 고정한다. 이름/손잡이/위아래 이동만 모달에 표시하고 저장·취소·닫기/Escape·실패 재시도를 제공한다. API·공통 Modal은 변경하지 않는다.

기준: d294bf5 이후 현재 워크트리 diff. `/users/bugri-author?user=author`, 방문자 user 생략, 타인 friend. 독립 리뷰 서버 `http://127.0.0.1:3125`. 1280×900, 390×900, 320×900의 모달/실패/본문 전체 캡처는 `test-results/profile-order-compact-*/`에 있다.

구현자 검증: 관련 Jest10개, production E2E8개, 변경파일 ESLint/Prettier 및 전체 TypeScript 통과. E2E는 본문 높이 불변·모달 높이500px미만·키보드/드래그·저장/새로고침/방문자·실패 재시도·취소/닫기/Escape·포커스 복귀를 확인한다. 기존 장거리 본문 edge scroll 테스트는 모달 도입으로 대상 동작이 제거되어 모달 내 세 행 이동/취소 검증으로 교체했다. 저장·사용자별 공개 조회 기대는 유지한다.

## 독립 리뷰

역할별 결과를 아래 기록한다. 실기기 터치·스크린리더는 직접 검증하지 않았다.

### R0 UX

별도 UX 리뷰어가 캡처 후 Node Playwright로 320/390px 실제 조작했다. 목적은 세 섹션을 바꾸고 저장하기로 이해했고, 세 이름과 저장/취소가 첫 화면에 모여 있다. 실제 콘텐츠 중복이 없어 밀도가 줄었다. 편집 → 키보드/포인터 이동 → 저장, Escape/닫기/취소와 초점 복귀, 저장 실패 유발 → 초안 유지 → 재시도 성공을 직접 확인했다. 본문은 초안 이동 중 저장 순서를 유지하며, 게스트/friend는 편집 버튼 없이 같은 저장 순서를 표시한다. 초기 손잡이·이동 후 초점, 방향키, 경계 비활성 조작을 확인했다. savedOrder/draft 분리와 저장 중 조작 차단, 관련 테스트 기대를 독립 코드 리뷰했다. 필수 문제0개.

### R0 UI

별도 UI 리뷰어가 1280/390/320px 모달·실패·저장후 본문 캡처9개를 먼저 확인했다. 제목 → 세 행 → 저장/취소 위계, 같은 행 간격과 컨트롤 정렬, 공통 보라색/테두리/그림자 사용이 유지된다. 320px 퀴즈 이름의 두 줄은 잘리지 않으며, 실패 상태도 900px 높이 안에서 조작 가능하다. 저장후 본문은 원래 크기를 유지한다. 필수 문제0개.

### 종료 및 한계

R0 수정0회로 종료한다. 필수 미해결 없음. UX는 실제 Chromium 조작, UI는 캡처/코드 확인이며 UI 리뷰어의 직접 포커스 외관·저장중·드래그 강조 확인은 미실행이다. 실제 터치 기기·스크린리더·다른 브라우저·가로/낮은 높이·확대는 미확인이다. 테스트 통과를 UX/UI 판단 대신 사용하지 않았다.
