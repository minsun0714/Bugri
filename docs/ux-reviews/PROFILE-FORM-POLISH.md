# PROFILE-FORM-POLISH

## 사용자 목표·확정 범위

소개와 외부 활동 링크를 부담 없이 편집·저장한다. 이전 사용자 스크린샷의 UX3개·UI4개 지적 전체 수정을 승인받았다. 해당 문제를 이번 독립 리뷰어가 발견한 것으로 기록하지 않는다.

- 수정: 링크 추가 후 종류 포커스, 다른 필드 오류 보존·삭제 시 오류 연결, 취소 확인 및 이전 입력 포커스 복귀.
- 수정: 프로필 전용 compact 에디터·16px 입력, 링크 행 외곽 카드·반복 시각 라벨 제거, 보조 버튼 강조 축소.
- 후속 사용자 요청: 전체 폭 추가 영역 중앙 +, 자기소개 코드 블록 버튼 제거, 미리보기 테두리/배경/16px 여백, 삭제는 휴지통 아이콘. 접근 가능한 행별 이름과44px 삭제 클릭 영역 유지.
- 유지: 읽기 소개의 헤더 콘텐츠 전체 폭·데스크·구독·API/저장 계약. 다른 에디터의 기본 UI와 코드 삽입 기능 유지.

구현 전 별도 form_design이 기존 토큰·공통 컴포넌트 기반 설계를 제안했다. 새 컨텍스트 form_polish_ux와 form_polish_ui가 실제 화면을 먼저 관찰하고 코드를 검토했다. 기준044f944 이후 diff, 격리 production127.0.0.1:3158, 본인 author 프로필, PC1280×900·모바일390×844. 별도 브라우저 컨텍스트의 데모 로그인 후 직접 조작했다.

## R0 UX

| 관점 | 관찰 근거 |
| --- | --- |
| 목적·대상 | 공개 ID·프로필 편집 제목으로 대상 식별 |
| 우선순위 | 소개→링크→취소/저장, 링크1개와 저장까지 첫 화면에 표시 |
| 행동 | +→기타선택→표시이름/URL→저장 직접 수행 |
| 밀도 | 카드·반복 시각 라벨 없이 필드로 행을 구분 |
| 피드백 | 오류3개 중URL1 교정 후 다른2개 유지, 삭제 후 남은 URL오류·aria-describedby 연결 유지 |
| 취소·키보드 | 확인 시 계속편집 포커스, 선택 후 이전URL로 복귀; 변경취소 시 저장값 유지 |
| 사용자 상태 | 게스트 편집 없음·본인 로그인 편집 있음 |

필수 문제0개. 저장토스트·공개 표시까지 직접 확인. 타인 로그인·서버저장실패·실제 스크린리더·iOS 키보드는 미확인. 초기 로그인상태 복원 실패는 새컨텍스트에서 직접 로그인하여 해소했다. 추가직후 포커스 순간 로그는 rAF이전이어서 후속 확인에서 명시 재검증한다.
