# QUIZ-CARD-UNIFY

## 대상과 증거

- 공개 퀴즈를 선택해 풀이하거나 본인 퀴즈를 선택해 관리하는 사용자. 사용자 확정 기준은 프로필 카드의 노트 아이콘, 둥근 모서리, 하단 그림자, 화살표다. 프로필 2열과 기타 세로 목록, 검색/필터/페이지 이동 및 공개/관리 동작을 유지한다.
- 현재 작업의 미커밋 코드: `src/components/ui/quiz-card/`, 개발자/태그 목록, 내 퀴즈 목록. API·저장 계약 변경 없음. 디자인 설계 전담 에이전트가 기존 카드 기준과 상태/메타정보 분리를 제안했다.
- 격리 복제 `/tmp/bugri-quiz-card-review`, `http://127.0.0.1:3219` (webpack dev), 원본 코드와 동일. 기존 3001 개발 서버는 중단하거나 검증 서버로 재사용하지 않았다.
- `/users/bugri-friend?user=friend`, `/developers/bugri-friend/quizzes?user=friend`, `/tags/web/quizzes?user=friend`, `/quizzes/authoring/manage?user=friend`. 각 1280×900, 390×900.
- `/tmp/bugri-quiz-cards/{profile,developer,tag,manage}-{1280,390}.png`: 목록까지 스크롤한 viewport 캡처. 첫 진입 화면 전체 평가와 구분한다.
- 추가 `manage-states-{1280,390}.png`: 긴 제목/공백 없는 영문/태그 3개/공개+수정본 검토/비공개/PENDING fixture의 full-page 캡처. viewport는 위와 동일하다. 실제 사용자 저장소와 분리한 Playwright 브라우저에서 생성했다.

## R0 최초 관찰과 흐름

- 새 컨텍스트 UX 리뷰어와 UI 리뷰어가 독립적으로 캡처를 먼저 확인하고 코드를 검토했다. 코드 수정 또는 추가 위임은 하지 않았다.
- 공개 목록은 제목을 선택해 풀이하는 화면, 내 퀴즈는 상태와 수정일을 확인해 관리하는 화면으로 식별했다. 제목/아이콘/화살표를 동일 위치에 배치하고 보조 정보는 아래로 구분한다.
- 구현자 직접 확인: 8개 화면 가로 overflow 없음. 첫 카드 포커스→Enter로 공개 3종은 `/solve?user=friend&quiz=...`, 관리는 `?user=friend&quiz=seed-quiz-3` 이동. 추가 상태에서 수정본 관리 진입 확인.
- UX 리뷰어 직접 확인: 모바일 태그 목록 ‘블록 스코프’ 포커스→Enter→풀이 헤딩. 작성자 링크가 별도 프로필 경로로 연결되는 것도 확인했다. 첫 관찰 스크립트의 전환 중 본문 조회 실패는 풀이 헤딩을 기다려 재확인했다.

## 검증

- Node v22.23.3. 공통 UI 추출이므로 최종 전체 검증 대상이며 Hook은 비활성 상태를 확인하고 수동 실행을 선택했다.
- 변경 코드 ESLint/Prettier, 전체 타입 검사, 관련 Jest 3 suites/8 tests 통과.
- 화면 도구 초기 서버 접속 실패: 같은 경로의 기존 next dev가 감지되어 별도 복제 디렉터리에서 해결. 추가 화면 fixture의 PENDING publishedAt을 null로 지정한 오류는 계약에 맞춰 생략해 해결. 애플리케이션 코드 실패가 아니다.
- 최종 `npm run verify` exit 0: 전체 lint·타입 검사·Jest 54 suites/271개·도구 테스트 3개·production build·E2E 167개 통과(2.2분). 로그 `/tmp/bugri-quiz-cards/verify.log`. 검증 후 변경은 TASKS와 이 리뷰 기록뿐이며 앱 코드/테스트/의존성/런타임 설정은 동일하다. 추가 빈 상태/방문자 동작은 전체 E2E로 확인했으며 독립 화면 리뷰 범위와 구분한다.
- 화면 캡처는 임시 검증 산출물이고 저장소에는 포함하지 않는다. 구현자 외 UX/UI 및 공통 컴포넌트 정적 리뷰 완료. 기존 3001 서버를 유지하고 검증용 3219 서버만 종료했다.
