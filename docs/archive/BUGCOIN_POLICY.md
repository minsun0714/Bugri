# BugCoin 보상 정책

> 보관 문서. 2026-11-08 제품 방향 재정의([PRODUCT-REFOCUS](../tasks/PRODUCT-REFOCUS.md))로 대체되었다. 현재 기준은 [PRD](../PRD.md)와 [페이지 구조](../PAGE_STRUCTURE.md)다. 이 문서의 기능은 "사용자 확보 후 재검토" 대상이며 구현 기준으로 쓰지 않는다.

REQ-09/AC-09a의 지급량을 2026-11-08 사용자 요청으로 확정한다. 기존 ‘지급량 미결정·자동 지급 0’ 설명보다 이 정책이 우선한다. Streak 보상·XP는 범위 밖이며 일일 문제 수·총 지급액 상한은 없다.

| 사유 | BugCent | 자격과 중복 기준 |
| --- | ---: | --- |
| FIRST_CORRECT | 100 | 타인 문제의 전체 제출 이력상 첫 제출 정답, 사용자·Quiz ID 최초 한 번 |
| RETRY_CORRECT | 50 | 이전 오답 후 최초 정답. FIRST_CORRECT와 상호 배타적 |
| DAILY_CORRECT | 100 | 보너스 대상 정답, 사용자·학습일 한 번 |
| REVIEW | 20 | 마지막 문제별 지급 후 정확히 168시간 이상 |
| CREATOR | 40 | 타인의 최초 제출 완료, 풀이자·Quiz ID 한 번. 정오 무관 |

모든 계산은 정수 BugCent(100 = 1 BugCoin)다. 문제별 보상과 일일 보너스는 합산한다. 첫 시도 판정은 날짜·Revision과 무관한 사용자·Quiz ID 전체 제출 이력을 사용한다. Revision 변경은 지급 이력을 초기화하지 않는다.

타인 문제는 최초 정답 보상을 받은 뒤 복습 대상이다. 본인 문제는 PRIVATE/PUBLIC 구분 없이 최초 생성 후 168시간부터 복습 보상과 일일 보너스 대상이다. 이후 복습은 마지막 문제별 지급부터 168시간 간격이다. 일일 보너스는 복습 대기시간을 갱신하지 않는다. 대기 중 풀이를 제한하지 않는다.

학습일은 입력 UTC 시각과 사용자 IANA 시간대로 계산한다. 시간대 변경은 즉시 적용하지만 기존 학습일·지급은 고정한다. 변경 전후 동일 날짜의 보너스는 중복 지급하지 않는다. 날짜 비교로 막지 못하는 시간대 변경 악용은 현재 정책의 허용된 한계다.

## 기존 데이터와 통합 경계

기존 완료·지급 기록은 소급 정산하지 않는다. 과거 정답은 있지만 최초 정답 지급이 없는 타인 문제에는 신규 정답·복습 보상을 소급 생성하지 않으며 이후 일일 보너스만 가능하다. 최초 생성 시각이 없는 이전 저장 데이터에는 정확한 168시간 자격을 추정하지 않는다. 새 퀴즈에는 불변 생성 시각을 저장하며 초기 fixture에는 명시적 생성 시각을 제공한다. 이전 퀴즈의 생성 시각 복구는 원본 데이터가 있는 백엔드/마이그레이션 작업이 필요하다.

## 익명 청구 후속 계약

현재 guestQuiz/guestAnswer는 무저장 체험이며 익명 세션이 없다. 기존 체험을 유지하고 이번 변경으로 익명 시스템을 만들지 않는다. 후속 작업은 세션 ID, expiresAt, 정상 제출 시 now+24시간 갱신, 전체 정오 이력, 사용자 연결/청구 멱등 키, 삭제 퀴즈 미청구 취소를 제공해야 한다. 청구는 만료 전만 허용하며 익명 상태에서는 지급하지 않는다. 이미 확정된 보상을 과거 이력으로 재계산하지 않는다. 실제 인증은 2단계다.
